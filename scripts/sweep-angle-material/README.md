# sweep-angle-material —— 渐变扫过材质 · UV 方向角

平面上的**黑白渐变宽带横扫**：一条（或多条）亮带沿指定方向扫过去、无缝循环。
**扫过方向是一个 0–360° 的 UV 平面角度**（0° 沿 +U、90° 沿 +V、180° 就是反向），
所有参数长在一个**空对象**上（材质可整体搬到别的网格体），
波形结构归脚本、**颜色归 `ColorRamp` 由你手调**。

另有一层**固定不动的水平渐变**与它**相乘**合成 —— 水平层给全白就等于没接（逐像素实测等价）。

📄 原理与坑的完整版：[`../../docs/渐变扫过材质-UV方向角.md`](../../docs/渐变扫过材质-UV方向角.md)
🤖 AI 作业规范：[`../../skills/blender-sweep-angle-material/`](../../skills/blender-sweep-angle-material/)

## 场景

- 想给一个平面做"**光带扫过**"的动态，循环无缝；
- 渐变希望用**颜色渐变节点**（方便随时改色），**黑白色**就够；
- 扫过**速度要能被驱动**（以后要打关键帧变速）；
- **还要叠一层不动的水平渐变**，两层能合成 —— 水平层不用时给白色，不影响竖层；
- 控制参数最好挂在**一个空对象**上，这样同一份材质能直接复用到别的网格体；
- 扫过方向不要只有"正 / 反"，要能**按 UV 角度自由转**（0–360°）；
- **不要常驻 N 侧栏面板**。

## 效果（跑完什么样）

- 目标材质重建节点树：**21 节点 / 23 连线 / 6 驱动器**
- 场景出现空对象 **`渐变控制`**（CUBE 显示、不参与渲染），
  带 5 个中文滑块：`扫过速度` / `扫过角度` / `扫过条数` / `水平条数` / `发光强度`
- 扫过方向 = UV 角度，`0°` **严格等价于原来的一维"方向 = 1"**（`t ≡ u`，逐点相同，不是近似）

```
纹理坐标(Generated) → 分离XYZ
  二维方向投影 t = (u·cosθ + v·sinθ) / (|cosθ| + |sinθ|)      ★ 分母让「条数」不随角度变
    → ×条数 → −相位 → FLOORED_MODULO 1 → 颜色渐变_扫过 ─┐
分离XYZ.Y → ×水平条数 → FLOORED_MODULO 1 → 颜色渐变_水平 ─┤
                       混合(RGBA, MULTIPLY, Factor=1.0) ─┴→ 原理化BSDF
                                                 ├─ Base Color
                                                 ├─ Emission Color
                                                 └─ Emission Strength ← 发光强度
相位 = 扫过速度 × (frame − 1) / fps
```

## 用法

四个脚本都**送 9877 桥**执行（`python bl.py <脚本.py>`，或 Blender Scripting 工作区 Run Script）：

| 顺序 | 脚本 | 说明 |
|---|---|---|
| ① | `probe_sweep.py` | **只读**侦察：目标对象 / 材质 / 节点 / 连线 / 驱动 / 旋钮 / 平面世界包围盒与法线轴。先跑它确认"目标在哪、是不是已经有半成品" |
| ② | `build_sweep_angle.py` | **幂等**构建（空对象 + 5 旋钮 + 21 节点 + 23 连线 + 6 驱动）。结构已正确会**跳过重建** |
| ③ | `verify_sweep_angle.py` | **独立核验**：结构 → 驱动行为 → 四角度渲染读数，并生成自包含预览 HTML |
| ④ | `maintain_ctrl.py` | **非破坏**维护：只对齐驱动器与旋钮，**绝不碰节点/连线/色标**。跑完"0 处改动" = 健康 |

改脚本顶部即可换目标：

```python
PLANE      = "平面"              # 目标网格体
MAT_NAME   = "渐变扫过材质"
CTRL_NAME  = "渐变控制"           # 空对象（参数载体）
FORCE_REBUILD = False            # 只给 build 用：True = 明知会抹掉手调色标也要重建
OUT_DIR    = "D:/workbuddy/blender_tips_out"   # 只给 verify 用：报告 / 截图 / 预览落盘
```

> ⚠️ 送桥的脚本**不能带 BOM**，且桥 `exec` 环境里 **`__file__` 不存在** ⇒ 脚本内**路径一律写绝对常量**。
> 桥有 **120 s 硬超时**；`verify_sweep_angle.py` 要渲 4 张图，用 `RES` / `SAMPLES` 控制耗时。

### 安全闸（`build_sweep_angle.py`）

它默认会**清空并重建整棵节点树**，而两个 `ColorRamp` 的色标是**你的手调成果**。所以进门前先比对
色标指纹，不是出厂的"3 档黑/白/黑"就**拒绝执行**并列出被改的色标：

```
RuntimeError: 安全闸中止,未修改任何数据。以下色标已被手工改过,重建会抹掉它们: {...}。
  只想修驱动器/旋钮 ⇒ 跑 maintain_ctrl.py(它不碰色标)
  确实要重建     ⇒ 把 build_sweep_angle.py 顶部的 FORCE_REBUILD 改成 True
```

★ **闸的门槛是「本次是否真的会重建」，不是「色标是否被改过」**：结构已经正确 ⇒ 走跳过分支 ⇒
根本没有重建 ⇒ 不该拦（否则幂等复跑会被误伤）。此时打一行提示后正常 `BUILD_OK`：

```
色标已被手工改过(节点 ['颜色渐变_扫过', '颜色渐变_水平'])—— 但结构已正确、本次不重建,色标原样保留
结构已是目标状态(节点 21 / 连线 23),跳过重建
```

## 参数表（5 个滑块，键在 `渐变控制` 上）

| 键 | 类型 | 默认 | 滑杆范围 | 说明 |
|---|---|---|---|---|
| `扫过速度` | float | 0.2 | 0–5 | **周期/秒**；0 = 静止；负值 = 反向 |
| `扫过角度` | float | 0.0 | 0–360 | **UV 平面角度（度）**。0°=沿 +U（=原来的 1）、90°=沿 +V、180°=反向 |
| `扫过条数` | float | 1.0 | 1–20 | 扫过方向上同时存在的渐变条数 |
| `水平条数` | float | 1.0 | 1–20 | 静态水平层（沿 V）的条数；水平层全白时无影响 |
| `发光强度` | float | 2.0 | 0–20 | 合成后的整体发光强度 |

> 键名是**中文键名**（`id_properties_ui` 的 `description` 即显示名，中文直接显示中文）。
> `min/max` 是**硬边界**、`soft_min/soft_max` 是**滑杆范围**：本例故意只给 `soft_max=360` 不给硬 `max`
> ⇒ 滑杆看着是 0–360，想输 400（多转一点）也不会被夹住。

## 注意（实战踩的坑，全部实测）

- ★★ **改完自定义属性，只调 `view_layer.update()` 读不到新值。** 必须
  `ctrl.update_tag()` + `nt.update_tag()` + `evaluated_depsgraph_get().update()`，
  否则节点树上的驱动器不重算 —— 会读到**陈旧值**并得出完全错误的结论。
  推论：`driver.is_valid` 也只有在这次刷新之后才可信（刷新前新建的驱动器显示 `is_valid=False`，
  那是"还没算"，不是"坏了"）。GUI 里拖滑杆会自动打 tag，所以这个坑只在**脚本里**出现。
- ★★ **拿"临时材质"探驱动器 = 无效实验。** `D.materials.new()` 造的一次性材质没被任何物体使用 ⇒
  不在依赖图里 ⇒ **驱动器根本不求值**：实测 13 个候选表达式全部 `is_valid=True`、**求值全是 `0.0`**
  （连 `pi` 都返回 0）。要探就在**正在被使用**的材质上探，或直接用**行为法**（改值 → 强刷新 → 看变没变）。
- **`driver.expression` 对非 `SCRIPTED` 类型是 Blender 自动生成的显示串。**
  `AVERAGE` 型的 `expression` 会显示成字面量（`'0.5'`），跟求值无关 ⇒ **别用它判断对错**，
  要比"求值后的插座值 == 旋钮值"。
- ★ **`SINGLE_PROP` 变量的赋值顺序**：先 `t.id_type='OBJECT'` **再** `t.id = ctrl`，反了会被拒。
  另外写"补充参数"的循环里 `for prop, var_name in SPEC` 的**顺序别反** —— 反了会造出指向不存在属性的
  **悬空变量**，不报错，但 `AVERAGE` 会把每个当 `0` 平均进去 ⇒ **数值正好减半**（实测 1.0→0.5）。
- ★ **改驱动器的「变量」必须原子重建**：整条 `remove` 再 `driver_add` 重配。只删一个变量再加一个新的，
  整条驱动会卡在 `is_valid=False`、数值**冻结在旧值**。删之前先把要用的字段冻结成局部变量
  （删完再读会 `ReferenceError: StructRNA ... has been removed`）。
- ★ **`FLOORED_MODULO`，不是 `MODULO`。** 扫过相位会走负值（180° 时 `t = −u`），
  普通 `MODULO` 对负值**裁剪** ⇒ 条纹在边界断掉。
- ★ **`ColorRamp` 的输入插座叫 `Factor`，不是 `Fac`**（`Fac` 是老的 `ShaderNodeMixRGB`）；
  **元素数 ≥ 2**（RNA 硬下限，"删到只剩一个"做不到）。
- ★ **`ShaderNodeMix` 的 `Factor = 0` 不是"纯相乘"**，MULTIPLY 模式下它会退化成**只取 A**
  （= 直接把扫过接出去）。要相乘必须 **`Factor = 1.0`**。
- **接线别硬写 `数学_倍频.inputs[0]`**：MULTIPLY 有**两个同名 `Value` 输入**，而且 `NodeSocket`
  在 5.2 **没有 `.index`**。正确做法是**从旧连线上取 `to_socket`**，删线后把新节点接回同一个插座。
- **零碎 API 事实**：`ShaderNodeTree` **没有** `.update()`；`bpy_prop_collection.__contains__` 只收字符串
  （`a_node in nt.nodes` 会 `TypeError`）；RNA 包装对象**不能比 `is`**（比 `.name`）；
  `Text.use_register` **不存在**（所以"重开自动跑"的面板路线在 5.2 走不通，本轮用户也不要面板）。
- **参数挂在空对象上 ⇒ 必须把该对象设为 `view_layer.objects.active`**，只 `select_set(True)` 不够 ——
  Blender 的**物体属性面板只显示活动对象**。踩过：用户"找不到驱动控制参数"。
- **生成预览 HTML 别用 `%` 格式化**：CSS 里的 `width:100%` 会撞成
  `ValueError: unsupported format character ';'`。用 `__PLACEHOLDER__` + `str.replace`。
- ★★ **核验剖面有两个"自证式"陷阱**（本轮实测踩过，详见文档 §3.11）：
  ① 沿 t 的剖面**必须先按 1.0 取模再分箱**，否则 180° 的负 t 被丢掉 ⇒ 条数塌成 1、相关系数变 0；
  ② **别用"沿 t 的剖面"验证镜像** —— 它的采样方向跟着 t 一起翻，0°/180° 天生重合，再 `[::-1]` 就翻了两次。
  **直接比像素**最干净：镜像差 `0.001884` vs 同向差 `0.273658`（小 **145 倍**），
  并顺手量「图案自身左右不对称度」`0.273729` 来证明判据不是恒真。
- **桥只改内存，不会存盘** ⇒ 跑完记得在 Blender 里 **Ctrl+S**。
