# make-independent —— 集合内对象数据独立化

把集合内对象的**共享数据块**转成每个对象独立副本,解决「复制出去后改一个、其它全跟着变」的链接复制问题。

## 场景

- 从 3ds Max / FBX / OBJ 等外部导入的对象,常以 **linked duplicate(链接复制)** 方式存在:
  多个对象共用同一个网格数据块。
- 把这样的对象**复制/导出到其它工程**后,它们仍然共享数据块 → 改其中一个,所有副本一起变;
  单独导出某个对象时,数据块也被多个对象引用,行为异常。
- 本脚本遍历指定集合,把每个对象引用的共享网格数据 `copy()` 出一份**独占数据块**,彻底脱钩。

## 用法

```bash
# 在桥环境远程执行(默认端口 9877)
python send.py make_independent.py

# 或直接在 Blender Scripting 工作区 Run Script
```

改脚本顶部常量:

```python
COLLECTION = '补充'            # 目标集合名
MAKE_MATERIAL_UNIQUE = False   # 是否也把材质复制成独立副本
```

## 效果

以实战场景为例(`补充` 集合):

```
ALL_DONE 集合=补充 网格对象=43
  网格数据块: 21 -> 43  (独立化 26 个)
  材质数据块: 10 -> 10  (独立化 0 个)
DONE_OK
```

43 个网格对象原本只共享 21 个数据块 → 独立化后 43 个对象各持 1 个数据块(43/43)。

## 幂等与安全

- **幂等**:已独立的数据块 `users == 1` 会自动跳过,重复运行无副作用。
- **非破坏**:只复制数据块、不改对象名/变换/层级;材质默认保持共享(通常无害),
  如需材质也独立,开 `MAKE_MATERIAL_UNIQUE = True`。
- **范围可控**:只处理指定集合内对象,集合外对象不受影响。

## 注意

- 桥接环境 `exec` 时 `__name__` 为 `builtins`,因此脚本**不用 `__main__` 守卫**,直接调用 `main()`。
- 运行后记得 **Ctrl+S** 保存工程,独立化结果才会落盘。
