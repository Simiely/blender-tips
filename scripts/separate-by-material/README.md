# 按材质拆分为多个网格体(可复用包)

一个对象挂着好几个材质槽、几何又是分开的几块时,常需要**按材质拆成独立对象**
(单独隐藏/替换材质/导出/上 LOD)。本包给出确定做法 + 拆分前基线 + 独立验证 + 下游引用扫描。

## 一句话原理

```
bpy.ops.mesh.separate(type='MATERIAL')
```

* **唯一真实可用的算子**。By Material = 按**材质槽**、对**整个网格**生效、**与当前选择无关**
* 原对象保留**「面序中首次出现最晚」的那一组**材质的几何（**不是**「最后一个材质槽」，见下方判据表）;其余各组各生成一个新对象
* 新对象名字按槽顺序为 `原名.001` / `.002` / `.003` …,每个新网格**只留自己那一个材质槽**

> ⚠️ **没有** `bpy.ops.mesh.separate_by_material` 这个算子 ——
> `hasattr(bpy.ops.mesh, "separate_by_material")` 会**假阳性返回 True**,
> 但 `get_rna_type()` 直接 `KeyError`。判 `bpy.ops` 算子存在性**必须用 `get_rna_type()`**。

## 配置项(`separate_by_material.py` 顶部)

```python
MODE    = "separate"        # "separate" 拆分(自动先录基线) | "baseline_only" 只录基线不动数据
TARGET  = "对象13735"        # 要拆分的对象名
BASE_JSON   = ".../baseline.json"   # 基线落盘位置
STATUS_JSON = ".../status.json"     # 执行状态实时落盘
RENAME_BY_MATERIAL = False  # True = 拆完把"新部件"按材质名重命名(原对象名不动)
KEEP_EMPTY_SLOT_MATERIALS = False  # True = 给"空材质槽"里的材质打 use_fake_user,防存盘时被当孤儿丢弃
RECORD_SHARP_BY_MAT = True  # 统计"每个材质组内的锐边数"(判定属性层消失有无信息损失)
```

## 使用步骤

### 1. 执行拆分

```python

```

### 2. 前置自检会拦住的情况

| 情况 | 脚本行为 |
|---|---|
| 找不到对象 / 不是 MESH | 中止(abort) |
| 网格数据被多个对象共享(`data.users != 1`) | 中止 → 先做单用户化(`make-independent` 包) |
| 材质槽 < 2 | 中止(无需拆分) |
| 所有面都指向同一个材质槽 | 中止(拆了也只有一个部件) |

### 3. 独立验证(**必须另开一次请求**)

```python
# verify_separation.py —— 配置与执行脚本一致
TARGET = "对象13735"; BASE_JSON = ".../baseline.json"
```

运行 `python send.py verify_separation.py`。输出 11 组判定:

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 部件数 | == 基线材质槽数 |
| 2 | 面数 / 顶点数守恒 | 面数**精确相等**;顶点数相等 ⇒ 材质组拓扑独立 |
| 3 | 每部件材质槽与面数映射 | 每部件 1 个槽,面数 == 基线该槽面数 |
| 4 | 父级 / `matrix_parent_inverse` / 世界矩阵 | `max|Δ|` < 1e-6 |
| 5 | UV / 自定义法线 / 其它载荷层 | 保留;仅编辑器选择掩码与 `material_index` 正常消失 |
| 6 | **锐边逐组核对** | 见下节(判定属性层消失有无信息损失) |
| 7 | 世界包围盒并集 | 与基线重合,`max|Δ|` < 1e-4 |
| 8 | 集合归属 | 与基线相同 |
| 9 | 材质数据块 users | 全部 ≥ 1,无孤儿 |
| 10 | 动画 / 修改器 / 形态键 | 与基线一致 |
| 11 | 场景统计 / 孤儿 mesh | 原有对象全在;无 `users=0` 的 mesh |

### 4. 收尾:下游引用扫描

```python
# refs_scan.py
TARGET = "对象13735"; CHECK_COLLECTIONS = ["水晶走廊"]
```

拆分后**原对象只保留「首现位置最晚」那一组的几何**（不一定是最后一个槽）。若别的系统引用过它,语义就变了 ——
这一步扫修改器 / 约束 / 粒子 / 驱动 / 材质节点 / 几何节点,明确报出有没有下游影响。

## 关键坑:属性层"消失"不等于数据丢失

拆分后常看到某个部件的 `sharp_edge` 属性层**不见了**,其它部件还在。这**不是 bug**:

* Blender 会丢弃结果网格上**全为默认值**的属性层
* 某组原本锐边数 = 0 → 属性层消失 ⇒ **无信息损失**
* 某组原本锐边数 > 0 → 属性层消失 ⇒ **真数据丢失**

所以基线里必须记录 **`sharp_by_mat`(每个材质组内的锐边数)**,否则无从判定。
真实案例实测:材质 3 组锐边数 = **0**(所以原对象属性层消失),另外三组 = 68142 / 2461210 / 80886,
与拆分后对应部件**逐组精确吻合**。

## 空材质槽(有材质但零面)

源码只遍历**面的** `mat_nr`,从不遍历材质槽 ⇒ **空槽不产生对象、也不被保留**;
`mesh_separate_material_assign_mat_nr` 把数据块 resize 到 1 个槽 ⇒ 空槽**被自动清除**。

* ⇒ **部件数 = 「有面的」材质槽数**,不是槽总数。若拿槽总数当判据,凡有空槽的对象都会被误报。
* ⇒ 只有 1 个槽有面时**完全不拆分**(仍是 1 个对象)。
* ⚠️ **风险:空槽里的材质会被存盘丢弃**。实测三级分辨:

| 阶段 | 空槽材质状态 |
|---|---|
| 拆分前 | `users=1` |
| 拆分后(**未存盘**) | 数据块**仍在**,`users=0` |
| 存盘后(同进程) | 仍 `users=0`(Blender 不立即释放) |
| **重新打开文件** | **不存在** —— 落盘时已被当孤儿丢弃 |

  所以"拆分 + Ctrl+S"对只被本对象引用的空槽材质等于**永久丢失**。
  要保住 → `KEEP_EMPTY_SLOT_MATERIALS = True`(实测:材质存活,`fake=True`,验证 24 项全绿)。
  真实场景 `对象9287` 的两个空槽材质另有使用者(`users` 3→2),**不受影响** —— 判定要看 `users` 是否归零。

## 注意事项(踩过的坑)

1. **`hasattr(bpy.ops.mesh, "separate_by_material")` 是假阳性**:实测返回 `True`,但
   `get_rna_type()` 报 `KeyError` —— 这个算子根本不存在。判 `bpy.ops` 算子存在性必须用
   `get_rna_type()` 包 `try`。
2. **`sharp_edge` 属性层会被丢弃**(全默认值时)—— 必须靠基线里的**分组**锐边数才能判定无损失(见上节)。
3. **桥 120s 超时 + 主线程阻塞** → 长耗时算子必须**逐阶段写盘**,超时后从磁盘回捞。
4. **拆分脚本里禁止写 `if __name__ == "__main__"`**:桥的 `_env()` 命名空间里**没有 `__name__`**,
   写了直接 `NameError`(Blender 执行 `scripts/startup/*.py` 时 `__name__` 也不是 `"__main__"`)。
   结尾**无条件**调用 `main()`。
5. **同一次 exec 内"改完立即验证"会读到未刷新缓存** → 验证一律**另开一次请求**,并尽量读**磁盘基线**。
6. **`Material.use_nodes` 已弃用**:Blender 5.2 起会抛 `DeprecationWarning`(预计 6.0 移除)。
   判"材质有无节点"请用 `mat.node_tree is not None`。
7. **`evaluated_get(dg).matrix_world` 是活引用**:存进列表必须 `.copy()`,否则循环结束后
   所有样本都变成最后一帧的值。
8. **Empty 不支持修改器**:自测台里想把引用挂在空对象上是不可行的,必须用网格对象。
9. **`VERTEX` / `VERTEX_3` 顶点父级**在拆分后会失去意义(顶点索引变了),`refs_scan.py` 会单独报出来。
10. **原点保持不动**:拆分沿用原对象的局部变换与 `matrix_parent_inverse`,所以每个部件都与原对象**逐位重合**,
    没有位移漂移 —— 验证第 4/7 项就是盯这个。
11. **材质数据块本身不会被改动 —— 但"空材质槽"里的材质会被存盘丢掉**(重要):
    有面的槽,材质 `users` 不变;而**空槽**(有材质但零面)在拆分时被清除,其材质变成 `users=0` 的孤儿。
    **拆分算子不删它**(内存里仍在),但 **Blender 存盘时会丢弃未被引用的数据块** ——
    实测「separate → save → 重新打开文件」后该材质**已不存在**。
    ⇒ 若该材质只被本对象引用,**拆分 + Ctrl+S = 永久丢失**。
    → 拆分前把 `KEEP_EMPTY_SLOT_MATERIALS = True`(给它们打 `use_fake_user`),或先手工清空/移走这些槽。
    验证器第 9 节会分级报出:[有面槽] 材质丢失 = ❌;[空槽] 材质消失/归零 = ⚠️(预期但确实变了数据)。
12. **不要用「世界包围盒」判几何守恒**:基线侧是"局部 AABB × `matrix_world`"(松上界),
    拆分后侧是"各部件局部 AABB 的并集"(更紧),两侧口径不等价 ⇒ **必然误报漂移**。
    正确判据是**两侧都取逐顶点局部坐标的 min/max**(算法一致、与帧无关,应精确相等)。
    实测反例:`对象9287` 真实世界范围 Y `0.14~7.31`,旧口径给出 `-11.28~16.31`(差一个数量级)。

## 调试建议

* 面数不等 → 有面在拆分中被吃掉/复制,先查是否有**非三角/非四边**的 N-gon 或退化拓扑
* 顶点数增加 → **正常**(材质边界处共享顶点被各自复制);想看是否真的拓扑独立,对比基线 `counts.verts`
* 某部件属性层消失 → 先看基线 `sharp_by_mat` 该组是否为 0;是 0 即无信息损失
* 部件数对不上 → 判据是**「有面的」材质槽数**,不是槽总数。空槽(有材质零面)不产生对象、且在拆分时被自动清除(v1.15.2 起验证器已内建此判据,不再误报)
* 拆分后名字与材质对不上 → 用 `RENAME_BY_MATERIAL = True` 重跑(注意:原对象名不会改)
