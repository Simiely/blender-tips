# swing-driver · 参数化摆动驱动(单物体 · 参数挂在对象自身)

给一批对象各挂一套「来回摆动」驱动:**最小角度 / 最大角度 / 持续时间 / 相位偏移**
四个滑块长在**对象自己身上**,每个对象各一套、互不干扰,改滑块实时生效,无关键帧、无烘焙。
可选再加一个**「摆幅倍率」总控**,一处改、全部目标的摆幅按倍数缩放。

完整原理、**与主题 46 的适用情况对照**、实测数据见
[`docs/参数化摆动驱动系统.md`](../../docs/参数化摆动驱动系统.md)。

> 选型速记:**群体「时而错开时而整齐」→ [主题 46](../spot-bloom-swing/);
> 个体「各摆各的、参数随对象走」→ 本包;
> 「烘进时间轴、不依赖 Python 权限」→ Skill `blender-loop-keyframe-anim`。**

## 前提

- 目标对象已存在(本项目是空物体父级,下挂一批网格;直接转它网格就跟着走)
- 走 9877 桥执行:脚本**没有** `if __name__ == '__main__'` 守卫
  (桥端 `__name__` 是 `builtins`,加了守卫会**静默不执行**)

## 两步走(顺序不能反)

```bash
python send.py build_swing_driver.py     # 1. 挂参数 + 挂驱动(可选倍率总控)
python send.py verify_swing_driver.py    # 2. 独立核验(必须另一次请求)
```

★ **第 2 步必须另起一次请求**。驱动**只写 evaluated 数据**,同一次 exec 内改完立即读会读到
未刷新缓存值;核验必须走 `obj.evaluated_get(depsgraph)`。

## 配置(两个脚本顶部要勾稽一致)

| 配置 | 含义 |
|---|---|
| `OBJS` | 要挂驱动的对象名列表 |
| `AXIS` | 旋转轴:`0`=X / `1`=Y / `2`=Z |
| `PHASE_STEP` | >0 时按顺序给每个对象递增 `相位偏移`,自动错开(`i × step`) |
| `DEFAULTS` | 参数键名(=显示名)、默认值、min/max、说明 |
| `MUL_SOURCE` | 摆幅倍率总控:`None` / `('SCENE', '键名')` / `('OBJECT', '对象名', '键名')` |
| `MUL_COL` | 只有 OBJECT 模式用:控制空物体放进哪个集合(`None` = 场景根) |
| `TEST_MUL` | verify 的倍率测试值(仅在倍率**没被 K 帧**时执行,测完还原原值) |

## 参数(改完实时生效,不用重跑)

构建后选中对象 → 属性面板 → 自定义属性:

| 属性 | 默认 | 含义 |
|---|---|---|
| `最小角度` | -5.0 | 摆到下死点的角度(度) |
| `最大角度` | 5.0 | 摆到上死点的角度(度) |
| `持续时间` | 100.0 | 一个完整来回 = 一个周期(帧) |
| `相位偏移` | 0.0 | 整体前后挪帧;0 = 帧 1 到达最小角 |

## 摆幅总控(可选)

`MUL_SOURCE` 打开后,所有目标的驱动表达式整体乘上这个倍率:

```
radians(mul*( (amin + amax)/2.0 - (amax - amin)/2.0*cos(...) ))
```

倍率设 `5` ⇒ 每个对象各自的最大/最小角度都变成 **5 倍**(01 的 ±3 → ±15,其余 ±5 → ±25);
设 `0` ⇒ 全部停摆。

| `MUL_SOURCE` | 挂在哪 | 取舍 |
|---|---|---|
| `None` | —— | 不启用,表达式更短 |
| `('SCENE','摆幅倍率')` | Scene 自定义属性 | **★ 免疫「空物体收敛清理」**;代价:要选中 Scene 才看得到滑块 |
| `('OBJECT','钟表控制','摆幅倍率')` | 一个控制空物体 | 好找(在 Outliner 里能选中);**★ 但它没有子级,会被空物体收敛清理当"无用 EMPTY"删掉** |

> 该用哪个:场景里以后还要跑清理 ⇒ 用 SCENE;只在当前工程临时调 ⇒ OBJECT 也行,
> 但记得把控制空物体加进清理的排除名单,或清理后重跑一次 build。

## 改摆幅的三种方式

| 想要 | 怎么做 |
|---|---|
| 整体换一个值 | 直接拖 `最小角度`/`最大角度` 滑块 |
| 一段时间内**渐变** | 给这两个属性 **K 帧**(悬停数值框按 `I`) |
| 全部一起缩放 | 拖**倍率**滑块(或给倍率 K 帧做整体涨落) |

**★ 红线:绝对不要 K `rotation_euler`。** 那条通道已经被驱动占用,**驱动的优先级高于动画通道**,
你 K 上去的关键帧会被驱动直接覆盖、**完全不生效**(看着像"K 帧没反应")。要改幅度就 K **自定义属性**。

**★ K 幅度要 K 一对。** `最小角度`/`最大角度` 是**绝对角度**:只想把摆幅从 ±2 变成 ±8 时,
两条都要 K(`-2→-8` 与 `2→8`)。**只 K 一条会让摆动中心漂走**(实测:只 K `最大角度`
从 5→12,中心从 0 漂到 +3.5)。

## 脚本清单

| 脚本 | 作用 |
|---|---|
| `build_swing_driver.py` | 主构建:建/刷新 4 个滑块属性 → 清同通道旧驱动 → 挂 `SCRIPTED` 驱动(可选挂倍率总控)。**幂等**;若目标身上已有关键帧动画,只摘**同通道**的 action(改名 + `use_fake_user` 留孤儿,可回退,**不删数据块**) |
| `verify_swing_driver.py` | 独立核验:逐帧与**手算期望值**对账(**倍率逐帧读**,支持倍率被 K 帧的情形)、周期一致性、子对象跟随、倍率测试,末尾 `VERDICT PASS/FAIL` |

## 原理一句话

```
α = mul × [ (amin + amax)/2 − (amax − amin)/2 · cos(2π(frame − 1 − phs)/dur) ]
```

方括号里与主题 46 的 `amin + (amax − amin)·(0.5 − 0.5·cos θ)` **代数恒等**(展开即知)。

## 实测(钟表01~05,Blender 5.2.2 LTS)

- 5 个钟表相位 0/20/40/60/80 错开;帧 1 时分别处于 `-3.00 / -1.55 / +4.05 / +4.05 / -1.55`
- 逐帧与手算期望值全部吻合;倍率从 1 涨到 5 的过程中(帧 1/26/51/76/101 → 倍率 1.000/1.770/3.369/4.734/5.000)逐帧仍全部吻合
- 子对象(8~10 个网格)世界坐标随父级变化

## 注意(都是实测踩的)

1. **★ 倍率的括号是承重的** —— 必须写 `mul*(BODY)`。
   写成 `mul*BODY` 会被运算符优先级解析成 `(mul*(amin+amax)/2.0) - (amax-amin)/2.0*cos(...)`,
   即 `mul` 只乘了「中心项」,**对称角度(`amin+amax=0`)时中心项恒为 0 ⇒ 倍率完全失效且不报错**。本地自测抓到的。
2. **★ 被 K 帧的自定义属性,读值必须走 `evaluated_get`** —— 动画值只写在 evaluated 副本上,
   读原始 datablock 拿到的是静态旧值(实测:倍率明明涨到 5,直读仍回 1.0)。
3. **★ 倍率被 K 帧后**,核验里的「周期一致性」判据**不再成立**(f 与 f+dur 本就不同)。
   `verify_swing_driver.py` 会自动跳过,并跳过倍率测试(手改不生效)。
4. **桥只改内存**,满意了 Ctrl+S。
5. **驱动表达式只用内置 `frame` + SINGLE_PROP**,不引自定义 Python 函数
   ⇒ **重开文件驱动不会变红**(无需 Register 文本块)。
6. **挂驱动前脚本会把基准角复位为 0**,避免从被污染的基准累加。
