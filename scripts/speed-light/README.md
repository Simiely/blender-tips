# scripts/speed-light/ · 速度驱动灯光亮度(通用方案)

> 把「灯的亮度随物体 **Z 轴运动速度**变化」的一套方案抽象为可复用的通用脚本包。
> 上移增强、下移衰减,按目标高度分档设定系数与亮度上限,clamp 到安全范围。

**核心逻辑**:灯的 `energy` 由「跟踪目标的 Z 轴速度」驱动;速度用**前向差分**
`pos(frame+1) − pos(frame)` 求(单位为 长度/帧),而非读目标当前 `location`——避免
驱动求值顺序导致读到未刷新的旧值。

## 方案要点

- **灯位置恒定**:灯固定在目标(柱子)轴心,朝上的灯额外上移 0.01 cm。位置**不随目标运动**,
  否则亮度变化会被"灯跟着物体走"淹没、看不出来。
- **亮度 = 速度的线性函数**:
  - 上移(向 +Z):`e = BASE + K_UP · v`
  - 下移(向 −Z):`e = BASE − K_DOWN_RATIO · K_UP · |v|`
  - 最后 clamp 到 `[E_MIN, E_MAX]`
- **分档(TIERS)**:速度数值通常很小(零点零几 米/帧),要可见变化需**几千倍的放大系数**,
  而不同高度/尺寸的目标对系数与上限的需求不同 → 按目标 Z 高度分档,每档独立 `K_UP` 与 `E_MAX`。
- **位置来源是命名空间函数**(默认 `bob`):驱动只负责求差,不依赖目标当时的缓存状态。

## 文件

| 文件 | 作用 |
|---|---|
| `speed_light_driver.py` | 核心:注册 `speed_energy(target, frame)` 到命名空间;顶部可配 BASE / 系数 / 分档表 |
| `build_speed_light_drivers.py` | 给灯的 `energy` 挂 SCRIPTED 驱动(幂等可重跑),写 `energy_panel` 记录跟踪目标 |

## 用法

1. **注册函数**(二选一,推荐前者持久化):
   - 新建文本块 `speed_energy_driver.py`,粘贴 `speed_light_driver.py` 内容,勾 **Register**
     (+ 偏好设置开 **Auto Run Python Scripts**)→ 重开文件自动注册;
   - 或运行一次 `speed_light_driver.py`。
2. **挂驱动**:配置 `build_speed_light_drivers.py` 顶部 `AXES` / `PANEL_BY_AXIS`,运行一次。
3. `Ctrl+S` 保存。

```bash
python send.py build_speed_light_drivers.py     # 远程桥方式
```

## 参数表

| 常量 | 默认 | 含义 |
|---|---|---|
| `BASE` | 6.0 | 基础亮度(速度≈0 时的 energy,即灯的静态亮度) |
| `K_DOWN_RATIO` | 2.0 | 下移衰减倍率(= K_UP × 此值) |
| `E_MIN` | 0.0 | 亮度下限 |
| `POS_FN` | `'bob'` | 目标 Z 位置函数名(须已在命名空间) |

**分档表 `TIERS`**:每档 `(特征函数, K_UP, E_MAX)`,依次匹配命中即生效,未条为兜底。

| 档 | 命中条件 | K_UP | E_MAX |
|---|---|---|---|
| 短柱 | 目标 `dimensions.z < 2.0` | 1700 | 20 |
| 长柱(兜底) | 恒真 | 3400 | 100 |

> 实战里短柱速度小(±0.02~0.03 米/帧)且体量小,不用太亮 → 上限 20、系数 1700;
> 长柱要更明显的 0~100 变化 → 上限 100、系数 3400。调参顺序:先定想要的亮度范围(E_MIN/E_MAX),
> 再按实测速度反推放大系数 `K_UP ≈ (目标亮度变化幅度) / (实测速度极值)`。

## 注意(实战踩的坑)

- **速度必须前向差分**求(`frame+1` 减 `frame`),直接用 `frame-1` 会相位错一帧;末帧无后继,
  用当前帧即可(动画段内影响可忽略)。
- **位置来源用命名空间 `bob` 函数**,别读目标 `.location`——SCRIPTED 驱动按依赖图求值,读
  目标 location 可能拿到未刷新的旧帧值,导致亮度滞后/抖动。
- **放大系数要几百上千倍**:速度是"米/帧"级的小数(约 ±0.03),系数取 1700~3400 才能把亮度
  推到可见的几十~上百;系数太小亮度几乎不动(早期踩坑:系数 150 时 0~10 都看不到变化)。
- **clamp 到安全范围**:亮度计算可能溢出(下移倍率 × 系数 × 速度),必须 `E_MIN/E_MAX` clamp,
  否则 energy 出现负数或爆炸大值。
- **位置要恒定**:一旦灯跟随目标运动,亮度变化会被位移掩盖,看不出效果;先把灯位置定到轴心,
  再挂速度驱动。
- **文本块勾 Register + Auto Run**:命名空间函数的运行期映射不落盘,靠文本块 Register 重注册;
  重启后若断开,优先查「.blend 内嵌文本块是不是旧版」而非 Auto Run(见仓库 AGENTS.md)。
- 运行后 **Ctrl+S** 保存。
