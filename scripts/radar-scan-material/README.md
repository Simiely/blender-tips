# radar-scan-material —— 平面「雷达扫描」空间材质（Y 轴投射 · 极坐标角度扫掠）

把一份 **Canvas 雷达扫描动画**（扫描头绕圈转 + 拖尾扇面 + 同心圆网格 + 中心亮点）
做成 Blender 的**空间材质**（**不用 UV**），贴到一个叫「平面」的网格体上，
且**沿世界 Y 轴投射**（只读世界 X/Z，丢弃 Y ⇒ 图案沿 Y 无变化，平移平面画面逐像素不变）。

配套文档：[`../../docs/空间雷达扫描材质.md`](../../docs/空间雷达扫描材质.md)（推导与全部坑）；
给 AI 的作业规范：[`../../skills/blender-radar-scan-material/`](../../skills/blender-radar-scan-material/)

## 场景

一块**法线朝 −Y** 的平面（实测世界中心 `(0.03, 0.14, -1.66)`、面内半宽 X=Z≈1.77），
要出现和参考动画一样的效果：

- **扫描头**绕中心匀速转（`110°/s`），可**正/反向**
- **5 条**同时存在、每条带 **129° 拖尾**（越靠尾部越暗），扇面互相重叠成漩涡
- 同心圆**网格**（4 环）+ **中心亮点**，发光限制在内切圆内（四角纯黑）
- 沿**世界 Y 轴投射**：图案与 Y 无关（正交侧视下，平面沿 Y 平移 2m，画面 md5 完全一致）

## 用法

```bash
# 0) 先只读量一遍目标几何（中心 / 面内半宽 / 朝向 / 材质槽）
python send.py probe_plane.py

# 1) 构建（幂等，可反复跑；每次都重新实测并重算半径类参数）
python send.py build_radar_material.py

# 2) 另起一次请求独立核验（结构 + 驱动真值 + 像素级测转角/数条数/验 Y 投射）
python send.py verify_radar_material.py
```

三个脚本都**经桥执行**：桥运行中（Blender Scripting 工作区跑 `blender_bridge.py`），
用 `python send.py <脚本>` 发送，见 [`../blender-remote-control/`](../blender-remote-control/)。

> ⚠️ 桥 `exec` 环境里 **`__file__` 不存在**，脚本内**所有路径都写绝对常量**（`verify` 顶部 `OUT_DIR`），
> 不要 `os.path.dirname(__file__)`。
> ⚠️ 送桥的脚本**绝不能带 BOM**（Windows PowerShell 5.1 的 `Out-File -Encoding UTF8` 会写 BOM
> ⇒ 桥端 `SyntaxError: invalid non-printable character U+FEFF`）。

## 构建脚本顶部配置区

| 常量 | 说明 |
|---|---|
| `PLANE` | 目标网格体名（默认「平面」） |
| `MAT` / `CTRL` | 新建材质名 / 控制空物体名 |
| `COLL` | 控制空物体所在集合（不存在则放场景根） |
| `DEFAULTS` | 12 个参数滑块的（默认值, 下限, 上限, 说明） |

`DEFAULTS` 的键名即 UI 显示名（中文键 = 中文滑块）。
`亮面半径` / `淡出宽度` / `中心点半径` 的默认值按**实测半宽**算（0.84 / 0.03 / 0.03 倍），
所以换平面尺寸只要改 `PLANE` 重跑即可。

## 公式（一条链）

```
坐标   纹理坐标(Object=控制空物体) → 分离XYZ          ★ Object 坐标 = 世界坐标相对该空物体
角度   u = ( atan2(世界Z, 世界X) + π ) / 2π           ★ 只吃 X/Z ⇒ 沿 Y 投射
相位   D = frac( 条数×时刻 − 方向×条数×u )             ★ 方向【只进角项】，见下
拖尾   拖尾项 = MapRange(0 .. 条数×拖尾/360 → 1..0) ^ 拖尾曲率
头部   头部线 = MapRange( min(D, 1−D), 0..线宽 → 1..0 )
半径   r = length( (X, 0, Z) )                        ★ 用 CombineXYZ 把 Y 填 0
网格   环带 = MapRange( frac(r ÷ (亮面半径/环数)), 0..0.05 → 1..0 ) × 网格亮度
合成   掩码 = min(拖尾 + 头部线 + 中心点 + 环带, 1) × 亮面裁切
输出   掩码 × 发光强度 → Emission Strength；RGB 白 → Emission Color
```

### ★ 方向为什么必须只进「角项」

```
错法：D = frac( 方向 × 条数 × (时刻 − u) )
      ∵ frac(−x) 的头位置集合与 frac(x) 完全相同
      ⇒ 扫描头仍朝同一方向走，只有拖尾换了边（方向旋钮**按了不反向**）

正解：D = frac( 条数×时刻 − 方向×条数×u )
      ⇒ 头位置 u = 方向×时刻 ⇒ 方向 ±1 真正反向
```

⇒ 时间项 = `时刻 × 条数`（**不含方向**），角项 = `u × (方向 × 条数)`。
**连线会盖过 socket 的驱动值** ⇒ 「有向条数 → 时间项」这条线绝不能连（只用驱动写 `inputs[1]`）。

### ★ 为什么必须 `FLOORED_MODULO` 而不是 `MODULO`

普通 `MODULO` 对负值会**裁剪**（负输入返回负值）⇒ 拖尾在扫描头跨过 0° 时断头。
`FLOORED_MODULO` 把结果规范到 `[0,1)`，跨 0° 无缝。

## 参数（12 个滑块，键在「雷达控制」空物体上）

| 参数 | 默认 | 作用 |
|---|---|---|
| 扫描速度 | 110 °/s | 扫描头角速度（驱动表达式 = `frame/fps × 速度/360`） |
| 扫描条数 | 5 | 同时存在的扫描条数（决定扇面间距 `2π/条数`） |
| 拖尾长度 | 129 ° | 每条拖尾张角 |
| 扫描方向 | 1 | `1` = 从法线正面看的**逆时针**；`−1` 顺时针 |
| 亮面半径 | 1.486 m | 亮面裁切半径（圆外纯黑） |
| 淡出宽度 | 0.053 m | 亮面外缘淡出宽度 |
| 中心点半径 | 0.053 m | 中心亮点半径 |
| 头部线宽 | 0.004 圈 | 扫描头亮线角宽（≈1.4°） |
| 拖尾曲率 | 1.8 | 拖尾衰减指数（越大尾部越暗越快） |
| 环数 | 4 | 网格同心圆环数 |
| 网格亮度 | 0.12 | 同心圆网格亮度 |
| 发光强度 | 8 | 自发光强度倍数 |

> ★ **改自定义属性后，脚本里画面不刷新** ⇒ 必须 `ctl.update_tag()` + `bpy.context.view_layer.update()`
> （GUI 拖滑块 Blender 会自动打 tag）。

构建后：**节点 33 / 连线 39 / 驱动 13**，材质 `平面_雷达扫描` 挂到「平面」槽 0
（旧材质 `Material #26` 保留便于回退）。

核验（`verify_radar_material.py`，全部通过）：

| 判据 | 结果 |
|---|---|
| 驱动真值（帧 1 / 31） | `0.01019 / 0.31574`，与期望 **逐位一致** |
| 单条扫描转角 | 实测 **+109°** vs 期望 +110°（误差 **1°**） |
| 反向（方向=−1） | 实测 **−110°** |
| 5 条 | 数到 **5 个亮峰** |
| **Y 投射** | 平面沿世界 Y 平移 2m，渲染 md5 `5a72afe178` **逐像素一致** |
| 收尾 | 引擎/相机/渲染/参数已复原，无残留异常隐藏 |

## 三条环境事实（Blender 5.2 实测）

1. **`ShaderNodeSceneTime` 不存在**（`bpy.types` 全量探查：5.2 无任何 `ShaderNode*Time*`，
   只有 `CompositorNodeSceneTime` / `GeometryNodeInputSceneTime`）⇒ 时间源改用
   **`ShaderNodeValue` 输出 + 驱动** `fr / fps * sp / 360.0`。
2. **`nt.driver_add(path)` 标量属性不能传 index** —— 传 `0` 报
   `driver_add(): index 0 was given while property ... is not an array`。
3. **`MapRange` 有 VALUE / VECTOR 两套同名插槽** —— 取值一律用**索引**
   （VALUE：`0..5` = Value / From Min / From Max / To Min / To Max / Steps），别按名字。
