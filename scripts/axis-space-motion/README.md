# 位移坐标系:让物体沿【自身轴】或【世界轴】运动(可复用包)

物体的轴向和世界轴不一致时(被旋转过的父级下、或者物体自己带旋转),
**K 出来的 `location` 既不沿世界轴、也不沿自身轴** —— 它沿的是"父空间基底"。
本包给出两条路的确定做法,并附诊断/写入/验证三个脚本。

## 一句话原理

```
matrix_basis = T(location) @ R @ S      ← 注意:平移 T 在最左端
```

* `location` 的坐标系 = **父级世界矩阵 @ `matrix_parent_inverse`**(下称**父空间基底**)
* 它 **不是**世界空间,也 **不是**对象自身空间
* 对象自身的 `rotation` / `delta_rotation` **改变不了** `location` 的方向

> ⚠️ 常见误解两条(**都实测证伪**):
> `delta_location` **不是**"对象局部位移",它与 `location` **同一坐标系**;
> `delta_rotation` 也 **不会** 让 `location` 跟着转。

## 统一心法

> **想让位移沿哪个坐标系,就把"承载位移那一层"的父空间做成那个坐标系。**

由此得到两条完全对称的做法:

| 想要 | 做法 | 本质 |
|---|---|---|
| 沿**自身轴** | 让**承载位移的那一层自身旋转 = 0**(朝向放它上面一层) | 父空间 == 自身空间 |
| 沿**世界轴** | 让**承载位移那一层的父空间与世界对齐**(中间插一层"抵消旋转"的空对象) | 父空间 == 世界空间 |

两种情况下都**只需要 K `location`**,不用做任何换算。

| 文件 | 作用 | 运行位置 |

| `axis_report.py` | **诊断**:量出「K location[2] 现在会往哪走」,并判定该用哪条路 | 桥 `send.py` 或 Scripting 工作区 Run Script |

## 配置项(`key_axis_motion.py` 顶部)

```python
TARGET  = "相机基点"                    # 要写位移的对象(建议是"位移层":自身变换全零)
SPACE   = "SELF"                       # "SELF" 对象自身轴 | "WORLD" 世界轴 | "PARENT" 父空间轴
AXIS    = (0.0, 0.0, 1.0)              # 方向;SELF/PARENT 时是该空间内的向量,WORLD 时是世界向量
KEYS    = [(151, 0.0), (480, -30.0)]   # [(帧, 距离)] 距离带符号,中间线性插值
ENGINE  = "auto"                       # auto 自动选 | direct 只在 KEYS 帧写 | bake 逐帧写
PRESERVE = True                        # True = 叠加在原有 location 之上
CLEAR_EXTRA_KEYS = True                # True = 先清掉 location 通道的旧关键帧
```

换算公式(脚本内部做的就是这件事,`R_own` = 本对象 `matrix_basis` 的旋转,含 delta):

| SPACE | 写入父空间的 `location` |
|---|---|
| `SELF` | `loc = d · (R_own @ AXIS)` |
| `WORLD` | `loc = d · (P_basis_rot⁻¹ @ AXIS)` |
| `PARENT` | `loc = d · AXIS` |

## 使用步骤

### 1. 先诊断

```python
# axis_report.py
TARGET = "相机基点"
```
运行 `python send.py axis_report.py`。典型输出(真实项目实测):

```
父空间基底（= K location 所在的坐标系）:
  f= 151  Z→世=(-0.8234,-0.5310,-0.1999)
  f= 480  Z→世=(-0.8474,+0.4929,-0.1973)
--- 判据（K location[2] 实际会往哪走）---
K location[2] 方向 vs 对象自身Z :   0.0000 度   ← 一致，K location[2] 就是「沿自身轴」
K location[2] 方向 vs 世界Z    : 101.5303 度   ← 不一致，K location[2] 不是世界轴
父空间基底朝向随时间变化(采样内最大) : 149.1429 度   （随时间变 → 世界轴方案必须 bake 或约束）
```

结论直接决定路线: **夹角 0 度**那条就是"现状已经对"的方向;
**随时间变化**说明坐标基底在动,换算只能靠逐帧 bake(脚本 `ENGINE="auto"` 会自动切)。

### 2. 写入

* 沿自身轴: `SPACE = "SELF"`, `AXIS = (0,0,1)`(对象自身 Z)
* 沿世界轴: `SPACE = "WORLD"`, `AXIS = (0,0,1)`(世界上下方向)
* 沿世界轴但父级旋转是动画 → 保持 `ENGINE = "auto"`,脚本会自动转成逐帧 bake

运行后**Ctrl+S 存盘**(桥只改内存)。

### 3. 独立验证(必须另开一次请求)

```python
# verify_axis_motion.py 配置与 key_axis_motion.py 保持一致
TARGET = "相机基点"; SPACE = "SELF"; AXIS = (0,0,1); KEYS = [(151, 0.0), (480, -30.0)]
```
运行 `python send.py verify_axis_motion.py`。它会**静音 location 曲线**先采一遍"没有位移时"的基准轨迹,
再取消静音采实际轨迹,逐帧输出:

```
--- 判定 ---
① 位置 vs 理想轨迹 最大偏差        : 8.092195e-06 单位 @f432   ✅
② 沿轴投影 vs 期望距离 最大误差    : 5.457539e-06 单位 @f426   ✅
③ 垂轴分量 最大绝对值              : 6.198883e-06 单位 @f409   （相对位移最大 0.0005%）   ✅
```

判读阈值(场景坐标量级 ~25 单位):

| 指标 | 通过阈值 | 正常实测 |
|---|---|---|
| ① 位置 vs 理想轨迹 | ≤ 1e-4 单位 | ~1e-5 量级(float32 精度) |
| ② 沿轴投影 vs 期望距离 | ≤ 1e-4 单位 | ~1e-5 |
| ③ 垂轴分量 | ≤ 1e-4 单位 | ~1e-5(< 0.001%) |

> **③ 垂轴分量才是"有没有沿轴"的直接判据。**
> 不要用"逐帧步进方向 vs 轴方向"—— 目标轴随时间旋转时,位移向量本身就在转
> (基准轨迹也在动),那个指标必然误报成大角度(实测误报 112° / 163°)。
> `verify_axis_motion.py` 已改用 ①②③ 三项。

## 四条路的对照(实测)

父级刻意绕 X 转 90°(与世界轴不同),目标 = 在基准轨迹上再叠加沿【世界 Z】0→5 的位移:

| 方案 | 位移方向误差 | 父级旋转是动画时 |
|---|---|---|
| 直接 K `location[2]`(对照) | 偏 **90.0000°** ❌ | ❌ |
| 换算 `loc = P_basis_rot⁻¹ @ (世界Z·d)`,K 三通道 | **0.000000 单位** ✅ | ❌ 偏 7.07 单位(必须逐帧 bake) |
| 逐帧 bake 换算 | **0.000000** ✅ | **0.000000** ✅ |
| 世界空间空对象 + `Copy Location`(owner/target=WORLD, `use_offset=True`) | **0.000000** ✅ | **0.000000** ✅(复合旋转也精确) |
| 中间插"抵消旋转"层(静态固定角) | **0.000000** ✅ | ❌(需要动态抵消) |
| 中间插"抵消旋转"层 + `Copy Rotation`(invert, `owner_space='LOCAL'`) | **0.000000** ✅ | 单轴 **0.000000** ✅ / 复合旋转偏 3.83 单位 ❌ |

**最通用的一条**(父级怎么转都精确):**世界空间控制空对象 + `Copy Location` 约束**
—— 不需要任何换算,也不需要 bake。

## 效果/成本取舍

| | direct(K 少数帧) | bake(逐帧) |
|---|---|---|
| 关键帧数量 | = `KEYS` 个数,曲线干净可手动微调 | = 帧数(330 帧实测耗时数秒,曲线不可读) |
| 适用 | 坐标基底**恒定** | 坐标基底**随时间变** |
| 精度 | 精确 | 精确 |

`ENGINE="auto"` 就是这么选的:采样 `KEYS` 范围内的方向变化,`< TOL_DEG(0.01°)` 走 direct,否则 bake。

## 注意事项(踩过的坑)

1. **`location` 不听对象自己的旋转**:想让位移沿自身轴,只能靠"承载位移的那一层自身旋转为 0"
   (或做换算),**不能**指望"把对象转过去,K 出来就跟着转"。
2. **`delta_location` / `delta_rotation` 都不是解**:实测位移方向误差仍是 90.0000°。
3. **父级/上层朝向是动画时,两关键帧之间只做直线插值会走偏**(实测 7.07 单位)——
   必须 `bake`,或用世界空间约束。
4. **`Copy Rotation` 的 `owner_space` 只有 `WORLD` / `CUSTOM` / `LOCAL`**(没有 `LOCAL_WITH_PARENT`):
   用来"抵消父级旋转"必须用 `owner_space='LOCAL'` + `target_space='WORLD'` + `invert_*`;
   实测 `owner_space='WORLD'` 或 `'CUSTOM'` 都不起作用(仍偏 90°)。
5. **`Copy Rotation` 逐分量取反 ≠ 矩阵求逆**:单轴旋转成立(实测精确),
   多轴复合旋转不成立(实测偏 3.83 单位 / 45°)→ 复合旋转请用 bake 或 `Copy Location` 方案。
6. **diagnose/verify 里存 `matrix_world` 必须 `.copy()`**:
   `evaluated_get(dg).matrix_world` 返回的是活引用,不拷贝直接存,循环结束后**所有样本都会变成最后一帧的值**
   (实测:三帧采样全打印成末帧)。`to_3x3()` / `to_translation()` 会返回新对象,天然安全。
7. **验收别用"逐帧步进方向 vs 轴方向"**:目标轴随时间旋转时该指标必然误报(见上)。
8. **同一次 exec 内"改完立即验证"会读到未刷新值** → 验证一律另开一次请求。
9. **本包按"位移层"语义工作**:建议目标对象的自身变换全零(`loc/rot=0`、`scale=1`、MPI=单位阵);
   `PRESERVE=True` 时会在原有 `location` 之上叠加,但仍以"父空间分量"为基准写入。

## 调试建议

* 诊断里"K location[2] 方向 vs 对象自身Z = 0.0000 度" → 现状已满足"沿自身轴",直接 K 即可,不必动结构
* 诊断里"父空间基底朝向随时间变化" → 世界轴方案一律走 bake 或约束,别用 direct
* 验证不通过 → 依次查: ①`verify` 的 `SPACE/AXIS/KEYS` 是否与写入时**完全一致**
  ②是否在**同一次请求**里验证(缓存假象) ③目标对象是否还有别的约束/驱动在改 `location`
* 只想临时试方向、不想落关键帧 → 直接看 `axis_report.py` 的坐标轴表即可
