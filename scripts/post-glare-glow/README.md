# post-glare-glow —— 合成器后期辉光(Glare)

给**已渲染好的画面**加一层后期辉光:节点组 `渲染层 → 眩光 → 合成输出` 挂到
`scene.compositing_node_group`,6 个中文滑块长在一个**空对象**上,实时可调。

> 传输层(9877 桥、`send.py`、120 s 上限、Blender 5.x API 坑、引用判定)见 [`blender-bridge-ops`](../../skills/blender-bridge-ops/)。
> **材质级**发光(程序化滚筒 / 径向 / 平面扫光等)见 `blender-cylinder-spiral-material` / `blender-radial-pulse-material` / `blender-sweep-angle-material`;
> 本包专管**渲染之后的合成器后期**这一层。

## 场景

工程有光/自发光几何,想要**眩光(Glares)**:灯带、LED、霓虹、曝光高光溢出的柔和光晕。
用合成器节点比在材质上做辉光更好 —— 它作用于**整幅画面**、不动几何与材质、不重渲。

⚠️ **但 5.x 改过 API**:仓库里旧配方的接法(终结节点用 `CompositorNodeConvertToDisplay`)
在这套环境下**已经失效**,而且是**静默失效**(不报错、画面完全不变)。
本包是按 5.x 正确接法重建的版本。

## 效果(跑完什么样)

```
渲染层(RLayers) ──Image──> 眩光(Glare) ──Image──> 合成输出(NodeGroupOutput)
                                                        ▲
                              ┌─────────────────────────┘
                              │  interface 必须先声明一个 OUTPUT 插座,否则整条合成被旁路
```

* 节点 **3** 个 / 连线 **2** 条
* 空对象 `辉光控制`上 **6** 个旋钮、节点组上 **5** 条驱动器
* 眩光节点 label = `参数在空对象「辉光控制」上`(指路),被驱动的插座带悬停提示
* `render.use_compositing = True`(总闸)、两个 3D 视图的 `shading.use_compositor = 'ALWAYS'`
* 活动对象 = `辉光控制`(**Blender 物体属性面板只显示活动对象**,不选中它看不到旋钮)

## 用法

把脚本通过桥送进 Blender(`python bl.py <脚本>.py`),**按这个顺序**:

| # | 脚本 | 干什么 | 期望输出 |
|---|---|---|---|
| 0 | `probe_glow.py` | **只读**侦察:合成器结构 / 是不是旧配方 / 旋钮 / 驱动 / 眩光插座清单 | `PROBE_GLOW_OK` |
| 1 | `build_glow.py` | 幂等构建(必要时重建链条 + 5 条驱动 + 旋钮 UI + 指路提示) | `BUILD_GLOW_OK` |
| 2 | `verify_glow_render.py` | 独立核验:8 项可证伪的像素读数 | `VERIFY_GLOW_OK` |
| 3 | `maintain_glow.py` | 非破坏维护:只对齐驱动与旋钮 UI,**绝不碰节点/连线/Type** | `MAINTAIN_GLOW_OK` |

* 复跑 `build_glow.py` 应该是 `跳过重接(幂等)` + `5 条驱动未改动` + `9 条插座提示`。
* 复跑 `maintain_glow.py` 应该是 `CHANGED=0`。
* 全部改动**只在内存** —— 收尾必须回 Blender **Ctrl+S**。

### 幂等 / 非破坏

* `build_glow.py` 先判断"结构是否已是目标状态",是则**跳过重接**;
  驱动的规格比对**按 `data_path` 匹配**(不按下标 —— 见下"坑")。
* `build_glow.py` 只恢复**默认值**;**没写死的旋钮值不会被覆盖**(只需 5.x 默认值存在的键)。
* `maintain_glow.py` **不动任何节点 / 连线 / Type / Quality**,所以手调过 `Type` 之后跑它不会被打回。

## 参数表(6 个滑块,键在 `辉光控制` 上)

| 旋钮 | 控制 | 硬量程 | 软量程 | 目标插座 |
|---|---|---|---|---|
| `辉光开关` | 总开关(与强度**相乘**) | 0–1 | 0–1 | `Strength`(经 `(sw * st)`) |
| `辉光强度` | 眩光强度 | 0–4 | 0–2 | `Strength` |
| `辉光阈值` | 进入辉光的亮度阈值(线性,越高越挑剔) | 0–50 | 0–20 | `Threshold` |
| `辉光尺寸` | 扩散尺寸(0–1 比例) | 0–1 | 0–1 | `Size` |
| `辉光饱和度` | 饱和度(1 = 原色) | 0–4 | 0–2 | `Saturation` |
| `辉光最大亮度` | 单像素最大贡献(压过曝) | 0–500 | 0–100 | `Maximum` |

★ **只写 `soft_min`/`soft_max` 不够**:Blender 里没设硬 `min`/`max` 时控件仍是个普通数值框
(±3.4e38),看起来不像滑块。必须连硬 `min`/`max` 一起写,再把 `step` 从默认的 1.0 调细到 0.01。

★ 眩光节点上**留给用户手调**(与"色标归用户自己调"同一约定,本包不设驱动):
`类型`(6 选 1)、`质量`(Low/Med/High)、`染色`、`阈值过渡柔度`,以及只在对应类型下起作用的
`条纹数` / `条纹角度` / `迭代` / `淡化` / `颜色调制`。

## 注意(实战踩的坑,全部实测)

1. **★★★ 终结节点必须是 `NodeGroupOutput`,而且必须先用 `tree.interface.new_socket(...)` 声明组输出插座。**
   少了这一步**整条合成被静默旁路** —— 不报错、画面完全不变、**连导出的 PNG 文件字节数都一模一样**。
   这是本主题最难查的坑,唯一能抓住它的信号就是"所有变体出图字节数完全相同"。

2. **★★ 比 md5、比文件大小都不足以判"两张图一样"。** PNG 里有时间戳类块 ⇒ md5 不同但字节数
   可以完全相同。**判"一样"必须比像素。**

3. **★★ 不要把 `CompositorNodeConvertToDisplay` 当终结节点。** 它会把色彩管理**再套一遍**
   (实测旁路档 `max=0.4039`、`90944/129600` 个分量被改动)。正解是 `眩光 → 合成输出` 直连,
   此时"强度 = 0"与"不加合成器"**逐位相同**(早期 180×180 隔离实验实测 `0/129600`)。

4. **★ Glare 的 `Type` / `Quality` / `Kernel Data Type` 是 MENU 插座,取值是「标题式字符串」**:
   `'Fog Glow'` / `'Bloom'` / `'Streaks'` / `'Ghosts'` / `'Simple Star'` / `'Kernel'`,
   写成全大写标识符会 `TypeError`。且 `NodeSocketMenu` **没有 `.enum_items`**,枚举只能试写。

5. **★ `Size` / `Strength` / `Saturation` / `Smoothness` 的 subtype 是 `FloatFactor` ⇒ 量程 0–1**
   (旧配方的 `Size = 12` 是 2.x–3.x 的整数 API,在 5.x 已失效)。
   注意 `Threshold` 是 `NodeSocketFloat`(**不是** Factor),可以用大数值。

6. **★★ 大尺寸眩光 + 低采样 = 噪点放大器。** 同一组 `尺寸=1.0`:12 samples 不降噪 ⇒ 整幅炸成雪花点;
   24 samples + 降噪 ⇒ 干净的柔光雾。Fog Glow 会把任何超过阈值的像素摊开成一大团
   ⇒ **先把渲染弄干净,再调大尺寸**。

7. **★★ 驱动挂在合成器节点树上时,脚本里读插座值必须手工 `ng.update_tag()` + 依赖图更新**,
   否则读到**陈旧值**(实测:属性 1.0→3.5,插座停在 1.0)。
   **但渲染路径会自己求值** —— 全程不 tag,只改开关 1→0,两次渲染相差 `120817/230400` 个分量。

8. **★★ `AnimData.drivers.new()` 是追加到末尾,`remove()` 会让后续元素前移**
   ⇒「第 i 条驱动」这个索引**永远不稳定**,一律**按 `data_path` 匹配**。
   另:`DriverVariable` **没有** `.data_path` / `.id` —— 它们在 `v.targets[0]` 上;
   读错会永远判"规格不符"、**每跑必重建**(数值仍对,但幂等报告失效)。

9. **★ 自定义属性要被当成正常控件(可拖滑块),必须写 `min` / `max`**;
   `id_properties_ui(p).update(min=, max=, soft_min=, soft_max=, step=, precision=)`,
   `step` 默认 1.0 太粗。判"属性是否被锁"**别看** `ID.is_property_readonly/hidden/set`
   (本项目版本上调用签名对不上,一律 `TypeError`),直接看 `id.animation_data`。

10. **★ 合成器节点上「紫色、拖不动」的输入框 = 该插座被驱动,不是锁死。**
    紫色代表"这一格由驱动控制",Blender 每次求值都会把它重算回驱动结果。
    要改的是**驱动源**(空对象上的旋钮),不是显示值。
    `NodeSocket.description` 有 **63 字节**硬上限(中文 3 字节/字 ≈ 21 字,超了**静默截断**);
    `NodeSocket.label` **只读**,只有 `Node.label` 能改(改 label 不动 name ⇒ 驱动地址安全)。

11. **★ 视口里看不见辉光**:要另设 `space.shading.use_compositor = 'ALWAYS'`
    (枚举 `['DISABLED','CAMERA','ALWAYS']`,默认 `DISABLED`),且 `shading.type` 是 `RENDERED`。

12. **★ 脚本层"报告串位"陷阱**:在分支里复用了上一个循环的残留变量,
    会让打印出来的"旧规格"其实是**隔壁那条驱动**,看着像 6 个旋钮整体串了一位 ——
    而**数据一直是对的**。报告异常时先确认自己在读对象本身,不是在读残留引用。

## 核验:可证伪的读数

`verify_glow_render.py` 三层共 8 项,**先自证工具可靠,再证效果成立**:

| # | 断言 | 说明 |
|---|---|---|
| [0] | 同设置渲两次逐位相同 | 不成立的话后面所有像素比对都不作数 |
| [1] | `开关=0` ≡ 完全不加合成器 | 旁路等价(容差:1 个 8bit 量化步 / 8 个分量) |
| [2] | 增益 >0.02 的像素 > 500 个;最大变暗 > −0.02 | 真的出光晕,且**只加不减** |
| [3] | 暗部增益占比 >10%;暗部最大单点 >0.02;高光也被加强 | **光晕的物理签名**(不是整体提亮) |
| [4] | 尺寸↑ ⇒ 暗部增益↑;**阈值↑ ⇒ 总增益↓**;**强度↓ ⇒ 总增益↓** | 三条单调性 |

★ **[1] / [4] 是真正的判据** —— 它们规定了一个**能让它失败的方向**:
把 `眩光 → 合成输出` 接错、把开关做成不影响强度、把阈值接反,都会立刻掉下来。

### ★★ 判据陷阱:本类工程的 Cycles 不是逐位确定的

`[0]` 默认要求**严格逐位相同**。但在对象数以万计、含大量高光的 CAD 场景里实测:

```
A1 vs A2 (同设置两次): max=0.00392157  差异分量=1/360000
差异诊断:
  最大差异在 分量 k=174860(像素 43715,通道 0,y=109 x=115): A1=0.54509807 A2=0.54901963
  差值的 8bit 台阶数 = 1.000000
  两侧中点 = 0.54705885  (= 139.5000/255)
```

* 差值 **恰好 1 个 8bit 量化步**(`1/255`),差异分量**只有 1 个**;
* 两侧中点**正好是 `x.5/255`** ⇒ **真实浮点值压在量化台阶的中点上**,末位抖动就翻到邻档;
* 再跑一次,**抖动的像素换了另一个**(上一次是 `y=212 x=255` 通道 2,中点 `126.5/255`)
  ⇒ 是**多个像素同时踩在台阶上**,跟"哪个先翻"有关,不是某个固定像素坏了。

⇒ **这不是辉光坏了,是判据比介质更严。** 想拿硬结论:**把渲染格式改成 32 位浮点 EXR 再比**;
或者把 `DET_MAX_DIFF = 1.0/255`、`DET_MAX_CNT` 设成个位数。
**先怀疑度量,再怀疑被测对象。**

## 撤回

* **只关效果、不删结构**:`辉光开关 = 0`(实测与"完全不加合成器"等价);
  或 `render.use_compositing = False`(总闸,极端眩光也 0 差异)。
* **整条摘掉**:`scene.compositing_node_group = None`(节点组本身留着,`use_fake_user` 已置,
  不会因无用户被存盘清掉)。视口里要一并看不见,把 `shading.use_compositor` 设回 `'DISABLED'`。
* **连节点组一起不要**:删 `后期辉光` 节点组 + 空对象 `辉光控制`。
  ★ 先删驱动所在的对象会让驱动变 `is_valid=False`;反过来先删节点组则驱动跟着走。**建议先摘挂载再删。**
