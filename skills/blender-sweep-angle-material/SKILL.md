# 平面「渐变扫过材质 · UV 方向角」

传输层（9877 桥、`send.py`、120 s 上限、Blender 5.x API 坑、引用判定）见 **`blender-bridge-ops`**。
世界空间**噪波**滚动发光见 `blender-procedural-emission-material`；**平面**坐标退化与测试卡见 `blender-plane-procedural-material`；
**圆柱面**螺旋条纹见 `blender-cylinder-spiral-material`。
本 skill 专讲：**平面上的多角度扫光** + **两层渐变相乘合成** + **参数外挂到空对象** + 一整套"自证式陷阱"。

- 原理与坑的完整版：[`../docs/渐变扫过材质-UV方向角.md`](../docs/渐变扫过材质-UV方向角.md)
- 脚本包：[`../scripts/sweep-angle-material/`](../scripts/sweep-angle-material/)（**只维护一份**，本 skill 目录下不放副本）

## 铁律

1. **先只读侦察**（`probe_sweep.py`）：目标网格体是不是水平面、法线轴、世界包围盒、材质槽、节点/连线/驱动现状、
   目标旋钮键值。**先判断是"角度版"还是"旧的一维版"**，别对半成品盲改。
2. **不许写死插座索引接线**：MULTIPLY 有**两个同名 `Value` 输入**，`NodeSocket` 在 5.2 **没有 `.index`**。
   要换上游，**从旧连线上取 `to_socket`**，删线后把新节点接回**同一个插座**。
3. **ColorRamp 上不挂任何驱动**（用户的手调口）；结构（条数/相位/循环）全留在 Math 域。
   ★ 改动前先比对色标指纹，**不是出厂值就停下来问**（`build_sweep_angle.py` 的安全闸已内置）。
4. **改完自定义属性必须强刷新再读值**（见 §2 坑 1）。**只 `view_layer.update()` 会得出完全错误的结论。**
5. **判据必须能证伪**：别写"看起来在动"，要写"四角度沿 t 的条数完全相同 `[4,4,4,4]`"、
   "180° 与 0° 的镜像差 0.001884 ≪ 同向差 0.273658（小 145 倍）"这类**能失败**的读数。
6. **执行完另起一次请求独立核验**，并且核验脚本自己也要**自证不自证**（见 §5 陷阱）。
7. **桥只改内存**：收尾必须提醒用户 **Ctrl+S**。

## §1 公式与节点链

```
纹理坐标(Generated) → 分离XYZ

  二维方向投影（本主题核心）
  t = (u·cosθ + v·sinθ) / (|cosθ| + |sinθ|)        ★★ 分母归一化

    t × 条数 → − 相位 → FLOORED_MODULO 1 → 颜色渐变_扫过 ─┐
  分离XY.Y × 水平条数 → FLOORED_MODULO 1 → 颜色渐变_水平 ─┤
                       混合(RGBA, MULTIPLY, Factor=1.0) ─┴→ 原理化BSDF
                                                 ├─ Base Color
                                                 ├─ Emission Color
                                                 └─ Emission Strength ← 发光强度

相位 = 扫过速度 × (frame − 1) / fps            （Value 节点输出 + SCRIPTED 驱动）
```

节点 **21** / 连线 **23** / 驱动 **6**（相位、角度_余弦、角度_正弦、条数、水平条数、发光强度）。

### §1.1 ★★ θ = 0° 必须与原版逐点相同

用户的原话是「0° 就对应现在的 1」。所以升级不能"重新设计一套角度"，必须满足 **θ=0° ⇒ `t ≡ u`**：

| θ | t | 含义 |
|---|---|---|
| 0° | `u` | **与"直接取 `分离_XY.X`"逐点相同**（不是近似） |
| 45° | `(u+v)/√2` | 斜扫 |
| 90° | `v` | 沿 V 扫 |
| 180° | `−u` | 反向（= 原来的 −1） |
| 360° | `u` | 回到起点 |

落在节点上就是「两个 MULTIPLY + 一个 ADD」的**二维投影**（读图左→右）：

| 节点 | 类型 | 作用 |
|---|---|---|
| `角度_余弦` / `角度_正弦` | Value (+SCRIPTED 驱动) | `cos(radians(ang))/(|cos|+|sin|)` / `sin(radians(ang))/(|cos|+|sin|)` |
| `数学_方向X` / `数学_方向Y` | Math MULTIPLY | `u × 余弦` / `v × 正弦` |
| `数学_投影` | Math ADD | 两者相加 → 接 `数学_倍频` |

### §1.2 ★★ 分母 `(|cosθ| + |sinθ|)` 是必须的

`u, v ∈ [0,1]` ⇒ `u·cosθ + v·sinθ` 的值域宽度是 **`|cosθ| + |sinθ|`**（45° 时 = **√2**）。
不除它，把角度从 0° 拨到 45°，**条纹凭空多出 1.41 倍**，「条数」在不同角度含义不一致（用户会以为材质坏了）。
除完 t 的值域**恒为宽度 1** ⇒ 「条数」在任何角度都表示"整块平面上有几条"。
代价是斜角时条纹在世界空间里略宽 —— **刻意的取舍：参数语义稳定 > 绝对物理宽度**。

> 这条是本主题**唯一"能失败"的结构性判据**的抓手：四角度沿 t 数条数必须完全相同，见 §5。

### §1.3 乘性合成：水平层全白 = 中性

`ShaderNodeMix`（`data_type='RGBA'`、`blend_type='MULTIPLY'`、**`Factor=1.0`**），实测：

| 水平层色标 | 逐像素比对（正交俯视渲染） |
|---|---|
| 全白 + `Factor=1` | 与 `Factor=0`（数学上 = 直接连接）最大差 **0.00392**、平均 **0.000000** ⇒ **等价** |
| 黑白条 + `Factor=1` | 与"纯扫过"最大差 **0.816**、平均 **0.133** ⇒ **叠加确实生效** |

⇒ 用户的"保底方案"成立：**水平层只要给全白就等于没接**，想加静态水平条就调它的色标，**接线一个字都不用改**。

## §2 ★★ 驱动与属性：五个"以为坏了、其实是读法错了"的坑

### 坑 1 ★★ 改完自定义属性，只调 `view_layer.update()` 读不到新值

```python
ctrl["扫过角度"] = 45.0
bpy.context.view_layer.update()
nt.nodes["角度_余弦"].outputs[0].default_value     # ← 读到旧值 1.0！
```

**必须**额外标脏：

```python
ctrl.update_tag()                                   # 参数所在 ID
nt.update_tag()                                     # 驱动器所在 ID（节点树）
bpy.context.evaluated_depsgraph_get().update()
```

实测对照：只 `view_layer.update()` ⇒ 插座值**不动**；`ctrl.update_tag()` / `nt.update_tag()` /
`mat.update_tag()` / `dg.update()` —— 任一种 ⇒ **立刻跟上**。
★ **GUI 里拖滑杆会自动打 tag**，所以这个坑只在**脚本里**出现；
但脚本读到陈旧值会得出**完全错误的结论**（本项目在开发中一度误判
"`cos`/`radians`/`abs` 不在驱动表达式白名单里""驱动器坏了"，白写了一圈探针）。
推论：**`driver.is_valid` 也只有在这次刷新之后才可信**——刷新前读，新建驱动器显示 `is_valid=False`，
那是"初始值还没算"，不代表它坏了。

### 坑 2 ★★ 拿"临时材质"探驱动器 = 无效实验

`D.materials.new()` 造的一次性材质**没被任何物体使用** ⇒ 不在依赖图里 ⇒ **驱动器根本不求值**。
实测 13 个候选表达式**全部**显示 `is_valid=True`、**求值全部 `0.0`**（连 `pi` 都返回 `0.0`；
`frame` 也返回 `0.0`）。**正解**：在**正在被使用**的材质/对象上探，或干脆用**行为法**（改属性 → 强刷新 → 看跟不跟）。

### 坑 3 `driver.expression` 对非 `SCRIPTED` 类型是**自动生成的显示串**

```
条数      AVERAGE   expr='0.5'     ← 而 扫过条数 = 1.0（求值实测 1.0，完全正确）
水平条数   AVERAGE   expr='3.765'   ← 而 水平条数 = 2.0
发光强度   AVERAGE   expr='1.0'     ← 而 发光强度 = 2.0
```

**别用 `expression` 判断对错**，要比"求值后的插座值 == 旋钮值"。

### 坑 4 ★ `SINGLE_PROP` 的两个顺序

```python
t = var.targets[0]
t.id_type = 'OBJECT'        # ★ 先
t.id = ctrl                 # ★ 后（反了会被拒 / 落到 None）
t.data_path = '["扫过角度"]'
```

补充变量的循环 `for prop, var_name in SPEC` 的**顺序别反**：反了会造出**指向不存在属性的悬空变量**，
不报错，但 `AVERAGE` 把每个当 `0` 平均进去 ⇒ **数值正好减半**（实测 `扫过条数` 1.0→0.5、`水平条数` 7.53→3.765）。

### 坑 5 ★ 改驱动器的**变量**必须原子重建

只想把变量 `dir` 换成 `ang` 时，只删一个变量再加一个新的 ⇒ 整条驱动卡在 `is_valid=False`、
数值**冻结在旧值**（连强制求值都不刷）。**正解：整条 `remove` 再 `driver_add` 重配**。
删之前先把要用的字段**冻结成局部变量**（`data_path` / `v.name`），删完再读会
`ReferenceError: StructRNA ... has been removed`。

## §3 材质侧：API 事实与接线

| 事实 | 说明 |
|---|---|
| `ColorRamp` 输入插座名 = **`Factor`** | 不是 `Fac`（那是老 `ShaderNodeMixRGB` 的） |
| `ColorRamp` 元素数 ≥ **2** | RNA 硬下限，"删到只剩一个"做不到 |
| **`ShaderNodeMix` 的 `Factor=0` 不是"纯相乘"** | MULTIPLY 下它退化成**只取 A**（= 直接接出去）；要相乘必须 **`Factor=1.0`** |
| `NodeSocket` **没有** `.index` | 5.2 实测；插座只能**按 `(name, type)` 配**或**从连线上取** |
| `ShaderNodeTree` **没有** `.update()` | 5.2 实测 `AttributeError` |
| `bpy_prop_collection.__contains__` 只收字符串 | `a_node in nt.nodes` 会 `TypeError`，改写 `a_node.name not in nt.nodes` |
| RNA 包装对象**不能比 `is`** | `l.from_node is a_node` 是 `False`；比 `.name` |
| `Text.use_register` **不存在** | 5.2 没有；想"重开自动跑"只能走别的路（本轮用户也明确**不要常驻面板**） |
| 取模一律 **`FLOORED_MODULO`** | 相位会走负值（180° 时 `t = −u`），普通 `MODULO` 对负值**裁剪** ⇒ 条纹边界断掉 |

**接线示范（换掉上游那一根，别写死索引）**：

```python
old = next(l for l in nt.links
           if l.from_node.name == "分离_XY" and l.to_socket.name == "Value"
           and l.to_node.name == "数学_倍频")
dst = old.to_socket                       # ★ 先把目标插座抓在手里
nt.links.remove(old)
nt.links.new(nt.nodes["数学_投影"].outputs[0], dst)
```

**参数外挂到空对象**（材质可整体搬到别的网格体）：

```python
ctrl = D.objects.new(CTRL_NAME, None)     # None ⇒ EMPTY，不动用 operator
sc.collection.objects.link(ctrl)
ctrl.empty_display_type = 'CUBE'; ctrl.empty_display_size = 1.6; ctrl.hide_render = True
ctrl["扫过角度"] = 0.0
ctrl.id_properties_ui("扫过角度").update(description="UV 平面角度(度)",
                                        min=0.0, soft_min=0.0, soft_max=360.0)
```

> ★ `min`/`max` 是**硬边界**，`soft_min`/`soft_max` 是**滑杆范围**：本例故意只给 `soft_max=360` 不给硬 `max`
> ⇒ 滑杆看着 0–360，想输 400 也不会被夹住。
> ★★ **交付时必须把它设成 `view_layer.objects.active`** —— Blender 的**物体属性面板只显示活动对象**，
> 只 `select_set(True)` 不够。踩过：用户"找不到驱动控制参数"。

| 键 | 类型 | 默认 | 滑杆 | 说明 |
|---|---|---|---|---|
| `扫过速度` | float | 0.2 | 0–5 | 周期/秒；0 = 静止；负值 = 反向 |
| `扫过角度` | float | 0.0 | 0–360 | UV 平面角度（度） |
| `扫过条数` | float | 1.0 | 1–20 | 扫过方向上的条数 |
| `水平条数` | float | 1.0 | 1–20 | 静态水平层条数（水平层全白时无影响） |
| `发光强度` | float | 2.0 | 0–20 | 合成后的整体发光强度 |

## §5 ★★ 验收：五条可证伪的读数

### 判据 1 结构（23 条连线逐条比对）

外加三条**否证式**断言，防止"看着对"：
旧的一维连线 `分离_XY.X → 数学_倍频` **已断开**、`数学_倍频` **恰好 2 个输入**、
`数学_循环` / `数学_循环Y` 是 **`FLOORED_MODULO` 且除数 = 1.0**。

### 判据 2 驱动行为（不看 `is_valid`，是**改值看跟不跟**）

角度 **0/30/45/90/135/180/270/360°** ⇒ 余弦/正弦与 `cos(radians θ)/(|cos|+|sin|)` **逐点吻合**，且 `cos²+sin² = 1`；
`扫过条数` 1.0 / 2.5 / 4.0 ⇒ 条数节点同步；`扫过速度` 0.5 / 2.0 + 帧号 **+1** ⇒ 相位步进 = 速度 / fps。

### 判据 3 朝向（`gradX/gradY`，别用"亮度质心"）

正交俯视渲染后算两个方向的平均绝对梯度：

| 角度 | `gradX / gradY` | 含义 |
|---|---|---|
| 0° | **10.51** | ≫1 ⇒ 竖条（沿 U 变化） |
| 45° | **1.000** | ≈1 ⇒ 斜条（各向同性） |
| 90° | **0.096** | ≪1 ⇒ 横条（沿 V 变化） |
| 180° | **10.50** | 竖条，且逐像素是 0° 的左右镜像 |

> 别用"亮度质心"：AgX 的高位平台会把质心拉平（实测 0.5→0.57→0.57→0.55→0.53，完全读不出位移）。

### 判据 4 ★★ 归一化成立（本主题**唯一能失败**的结构判据）

把 `t` 按 1.0 取模后分 128 箱，数"沿 t 方向的条数" —— **四个角度必须完全相同**：

```
四角度沿 t 的条数 = [4, 4, 4, 4]     [PASS]
```

不除 `(|cosθ|+|sinθ|)` 时，45° 会多出 **√2 倍** ⇒ 条数写成 5 或 6，一眼看得出来。

### 判据 5 ★★ 180° 是 0° 的逐像素镜像 —— 但**别拿 t 剖面做**

```
平均逐像素差:同向 0.273658 / 镜像 0.001884 / 0° 图自身左右不对称度 0.273729
[PASS] 可证伪前提:0° 图本身左右强不对称(0.273729 ≫ 0.001884)⇒ 镜像判据不会自动成立
[PASS] 180° = 0° 的左右镜像(镜像差 0.001884 ≪ 同向差 0.273658,小 145 倍)
```

## §6 ★★ 两个"自证式"陷阱（核验脚本自己坑过自己，本轮实测）

### 陷阱 A：沿 t 的剖面**必须先按 1.0 取模再分箱**

θ > 90° 时 `t` 是**负数**（180° 就是 `t = −u`）。天真写法

```python
t = (u * cs + v * sn) * k
bi = int(t * bins)
if 0 <= bi < bins:        # ← 180° 时绝大多数点在这被丢掉
    ...
```

会把 180° 的剖面几乎清空 ⇒ **"条数"塌成 1**、任何相关系数退化成 0。
读数长这样 —— 看起来像"材质在 180° 坏了"，其实是**度量写错了**：

```
180 ° ... 沿 t 条数=1
四角度沿 t 的条数 = [4, 4, 4, 1]        [FAIL]
0° vs 180° 剖面:同向相关=+0.0038  镜像相关=-0.0062
```

**正解**：`t = (((u * cs + v * sn) * k)) % 1.0`。
这与材质自身用的 `FLOORED_MODULO 1.0` **同构**，而且图案本身就是周期 1 的，
接缝处**连续**，不会引入假跳变边。

### 陷阱 B：**不要拿「沿 t 的剖面」验证"180° 是 0° 的镜像"——那是自证**

`profile_t` 的**采样方向本身就跟着 t 翻**（180° 时 bin `b` 采的是 `x ≈ (1−b/bins)·W` 处的像素），
所以 0° 与 180° 的 t 剖面**天生重合**；再手工 `[::-1]` 翻一次等于翻了两次 ⇒ 变成反相关：

```
0° vs 180° 剖面:同向相关=+1.0000  镜像相关=-0.3014     ← 全是度量的锅
```

**正解：直接比像素。** `mean|I180(x,y) − I0(w−1−x,y)|`（镜像）应 ≪ `mean|I180(x,y) − I0(x,y)|`（同向）。

> 教训：**"能失败的判据"才算判据。** 顺手把「图案自身左右不对称度」也量出来（≈0.2737），
> 才能证明这个镜像判据不是恒真的 —— 否则一个左右对称的图案会让"镜像 = 同向"两边都成立，测了等于没测。

### 陷阱 C（工程侧）：桥的执行细节

- 桥 `exec` 环境里 **`__file__` 不存在** ⇒ 脚本内**路径一律写绝对常量**。
- 送桥的脚本**不能带 BOM**（PowerShell 5.1 的 `Out-File -Encoding UTF8` 会写 BOM ⇒ 端上 `SyntaxError: U+FEFF`）。
- **桥异常会吞掉前面所有 `print`** ⇒ 关键读数要"跑一段、看一段"，别憋一大坨。

### 陷阱 D（生成预览 HTML）：**别用 `%` 格式化**

CSS 里的 `width:100%` / `minmax(240px,1fr)` 会撞成
`ValueError: unsupported format character ';' (0x3b) at index 588`。用 `__PLACEHOLDER__` + `str.replace`。

## §7 安全闸（`build_sweep_angle.py` 内置）

它会**清空并重建整棵节点树**，而两个 `ColorRamp` 的色标是**用户的手调成果**。所以进门前先比对色标指纹：

```
RuntimeError: 安全闸中止,未修改任何数据。以下色标已被手工改过,重建会抹掉它们: {...}。
  只想修驱动器/旋钮 ⇒ 跑 maintain_ctrl.py(它不碰色标)
  确实要重建     ⇒ 把 build_sweep_angle.py 顶部的 FORCE_REBUILD 改成 True
```

★ **闸的门槛是「本次是否真的会重建」，不是「色标是否被改过」**：
结构已经正确 ⇒ 走跳过分支 ⇒ 根本没有重建 ⇒ 不该拦（否则**幂等复跑会被误伤**）。此时打一行提示后正常 `BUILD_OK`：

```
色标已被手工改过(节点 ['颜色渐变_扫过', '颜色渐变_水平'])—— 但结构已正确、本次不重建,色标原样保留
结构已是目标状态(节点 21 / 连线 23),跳过重建
```
