# 车辆速度系统与刹车收尾

传输层（9877 桥、客户端封装、120s 上限、5.x Slotted Action 读写）见 **`blender-bridge-ops`**。
本 skill 只讲「车怎么跑、怎么停」这件事的结构与调法。

配套文档：[`docs/车辆速度驱动与刹车收尾.md`](../docs/车辆速度驱动与刹车收尾.md) ·
脚本包：[`scripts/vehicle-speed-brake/`](../scripts/vehicle-speed-brake/)

实测环境：Blender **5.2.2 LTS** / Windows / 9877 桥 / CYCLES 2560×1440。

## 铁律

1. **速度曲线是唯一数据源**。改曲线本身**不会**改变运动，位移是从它积分出来再烘焙成关键帧的。改完必须重烘焙。
2. **位移永远是速度对时间的积分**。`位移 = D × spd × prog` 的写法在 spd 随时间变化时会变成"速度×进度"而不是积分，spd 下降时位移导数转负 —— **车会倒着走**。
3. **轮角由位移派生，不要独立打关键帧**。`-(X0 - x) / R` 让任何速度曲线下都零滑移。
4. **烘焙区间取曲线自身的首末关键帧，不要用场景范围**。用户常把场景拉长做静帧，用场景范围会让车在静帧段继续滑行。
5. **每帧满速位移是常量 `REF = D / 原方案时长`**，与烘焙区间长度无关（见坑 1）。
6. **收尾必须提醒 Ctrl+S**：桥只改内存。改了自定义属性后 `bpy.data.is_dirty` 也不会置位。

## 一条链（背下来）

```
控制_车速["速度倍率"]   ← 关键帧曲线，唯一"源"
        │ 数值积分（0.25 帧步长，梯形法）
        ▼
绑定_车辆根.location[0]  ← 逐帧烘焙关键帧，LINEAR 插值，无驱动
        │ 位移派生（驱动）
        ▼
绑定_轮_*.rotation[1]    ← -(X0 - x) / R      （R = 有效滚动半径）
        │
        ▼
控制_相机补偿.location[0] = (D - REF×∫total) × 进度   ← 保证末帧构图不变
        │
        ▼
控制_车身.rotation[1] = 点头曲线 × 点头强度          ← 纯观感层，不影响位移
```

全车如果是「关键帧 + 驱动」结构，就不会有约束和修改器，改起来最省事。

## §1 常量怎么定

| 常量 | 怎么取 | 本次实测 |
|---|---|---|
| `X0` / `X1` | 原方案车根首末帧的世界 X | 7.297282 / 2.621750 |
| `D` | `abs(X1 - X0)`，原总位移 | 4.675532 m |
| `REF` | `D / 原方案帧数`（倍率 1.0 时每帧位移） | 0.077926 m/帧 |
| `R` 有效滚动半径 | **轮心 z − 地面 z**，不是包围盒半径 | 0.360（包围盒半径 0.364，但轮胎底陷地 4 mm） |
| 相机补偿 | `D - REF × ∫spd`，按**最终位置**补 | 0.543167 |

> 轮胎包围盒半径会**高估**滚动半径：算出 0.364，但轮心 z=0.360、地面 z=0，轮胎实际沉进地面 4 mm。
> 用错会让零滑移校验出现千分之几的系统偏差（`Δx/Δθ` 恒为 0.364 而不是 0.360）。

## §2 刹车「顿一下」是怎么造出来的

**软**和**顿**的区别不在总位移，在**减速度的跳变率（jerk）**。

- 软：速度从刹车起点开始平滑衰减 ⇒ 减速度从 0 慢慢爬到峰值，看起来像滑行停稳。
- 顿：刹车起点那一帧，**减速度从 ~−0.3 直接跳到 −7 m/s²**。

做法是给刹车起点做**斜率拐点**：进柄几乎水平、出柄猛压。

| 关键帧 | 值 | 左手柄 | 右手柄 |
|---|---|---|---|
| f30 | 1.000 | (24, 1.060) | (44, 0.820) |
| **f92** | **0.680** | **(80, 0.740) 几乎水平** | **(95.5, 0.260) 猛压** |
| f105 | 0.000 | (100, 0.000) | (110, 0.000) |

实测：逐帧倍率下降量在 f92→f93 从 **−0.0048 跳到 −0.1127（23 倍）**，
减速度 −0.3 → **−7.4 m/s²**，刹车行程 **32.4 cm**。真车急刹 7–9 m/s²。

**取舍（调档前必看）**：中段减速越狠 ⇒ 到起刹帧的速度越低 ⇒ 刹车行程越短，二者不可兼得。

| 起刹倍率 | 中段 | 刹车行程 | 峰值减速度 |
|---|---|---|---|
| 0.80 | 8.42→6.73 km/h | 39.6 cm | 8.02 m/s² |
| **0.68（推荐）** | **8.42→5.72** | **32.4 cm** | **7.4** |
| 0.55 | 8.42→4.63 | ≈26 cm | ≈6.5 |
| 0.10 | 8.42→0.84 | 2.8 cm | 1.6（软） |

**15 帧 = 0.5 秒，行程上限就是 `REF × 0.5s × 倍率`**。想要 1 m 以上的刹车行程，
必须让车在起刹帧还接近满速 —— 那时候「前快后慢」就基本不存在了。**先问用户要哪个。**

## §3 车身点头 + 强度参数

**关键约束：一个属性不能既有关键帧又被驱动。** 所以想"乘一个系数"必须拆成两个属性：

```
控制_车身["点头曲线"]   ← 关键帧，管形状与时机
控制_车身["点头强度"]   ← 普通属性 + id_properties_ui 滑块，管幅度
        │ 驱动：dive * k
        ▼
绑定_车身.rotation[1]
```

**曲线（本项目最终定稿，含用户手调结果）**

| 帧 | 值 | 说明 |
|---|---|---|
| 88 / 92 | 0 | 刹车前保持水平 |
| **96** | **−0.0100** | 峰值。× 强度 0.65 = **−0.37°** |
| 101 | +0.0045 | 回弹过冲（相对峰值 45%，比下压更"轻"一点） |
| 105 / 112 | 0 | 归零。**末帧必须归零**，否则构图偏 |

> 这首稿给的是 −0.0314（−1.17°），用户上手后改成 −0.0100，说"更含蓄、更真"。
> **下压宁小勿大**：真实车在 5.7 km/h 这种低速刹车时点头量很小，动画里 0.3–0.5° 就够读出重量感。

**轴心必须在轮轴高度**。本项目车身空物体轴心 `(3.1649, 0, 0.363)`，z 正好等于轮心高度，
倾起来才像绕悬挂俯仰；轴心在地面会变成"整车往前栽"。

**非等比 scale 下动 rotation 是安全的**（动 scale 才致命）。论证与证伪方法见坑 5。

## §4 六个坑

### 坑 1：烘焙归一化不能依赖区间长度

```python
dist = D / (F1 - F0) * cum      # ✗ 区间一变长，整段被重新缩放
```

原区间 60 帧时恰好吃对，一旦尾部接 15 帧刹车，30–90 段的位移会被整体压到 **80%** ——
悄悄改掉了用户已经认可的部分，而且看不出来（只是"感觉车慢了一点"）。

```python
REF = D / 60.0                  # ✓ 常量，与原方案时长绑定
dist = REF * cum
```

### 坑 2：自定义属性的 min/max 会真的钳制取值

不只是限制滑块。`id_properties_ui(k).update(min=-0.05, max=0.00)` 之后再往里写 `+0.0045`，
**读出来是 0** —— 而 `fcurve.evaluate(f)` 明明是 +0.0045。症状：回弹动作整个消失，
但曲线看起来完全正常，查半天查不到。

**内部用的曲线属性，范围一律留宽**（如 ±0.10），别拿 min/max 当注释。

### 坑 3：一个属性不能既做关键帧又被驱动

`driver_add()` 会顶掉同一路径的关键帧。想乘系数只能另立一个"强度"属性（见 §3）。

### 坑 4：世界坐标采样点不能跨帧复用

做间隙/穿模测量时，轮胎顶点的世界坐标**必须在当前帧重新取**。
车在移动，拿 f105 采的点去量 f96 的间隙，结果全是 0.0x mm 的假穿模（实测踩过）。
症状很好认：不同幅度的结果全都一样，且都接近 0。

### 坑 5：非等比 scale 下的旋转 —— 用保距校验证，别只用推导

父级带非等比 scale `(2.2559, 4.1474, 1.0)`，子级靠 `matrix_parent_inverse` 里的 `S⁻¹` 抵消：

```
body.matrix_world · Mp⁻¹ = P·T·R·S · S⁻¹·T⁻¹ = P·T·R·T⁻¹
```

结果就是**绕车身轴心的纯旋转**，不含剪切。但这一步必须实测证伪：

> 取车身包围盒的对角两点，转前转后量距离。
> 实测 4.803540 m → 4.803540 m，差 **−8.7e−8 m** ⇒ 没拉伸。

**注意：动 scale 会立刻破坏这个抵消关系，车身被非等比拉开。rotation 可以碰，scale 不行。**

### 坑 6：轮胎与轮眉的间隙要实测，不能按角度猜

点头幅度和"车头下沉几厘米"是两回事，真正会穿模的是**轮拱相对轮胎压下去多少**。
量法：取轮胎表面顶点（世界坐标、**当前帧**），对每个车身网格做 `closest_point_on_mesh`，取全局最小距离。

基准曲线峰值 −0.0100 rad（= −0.573°/强度1.0）时实测：

| 强度 | 角度 | 间隙 | 判定 |
|---|---|---|---|
| 0 | 0° | 3.95 cm | — |
| **0.65（定稿）** | **−0.37°** | **3.95 cm** | 完全没压到，最含蓄 |
| 1.00 | −0.57° | 3.95 cm | — |
| 1.15 | −0.66° | 3.95 cm | 仍满格 |
| 2.00 | −1.15° | 3.39 cm | 开始有压缩感 |
| 3.00 | −1.72° | 1.78 cm | 接近首稿观感，仍安全 |

对照：基准曲线峰值 −0.0314 rad（=−1.80°/强度1.0）时，1.20（−2.16°）只剩 0.53 cm，1.50（−2.70°）直接穿模。
两条曲线外推交于同一个结论：**间隙在 −2.35° 附近归零**，这是该车型的物理上限。

**⚠️ 强度是"相对系数"，不是绝对角度。** 基准曲线一改（本例从 −0.0314 改成 −0.0100），
同一个强度对应的物理角度**全部变了**，滑块的 min/max 也就失效了：
首稿 max=1.15 是按 −0.0314 的基准卡出来的，换成新基准后 1.15 只到 −0.66°，
用户想回到原来的 −1.17° 得调到 2.05 —— 却被滑块挡住。
**改完基准曲线必须重量一遍间隙、重设 max。** 本项目最终 max=3.0 / soft_max=1.5。


## §5 核验清单

改完必须过，一条都不能少：

1. **末帧构图**：`相机 - 车` 的三维相对位置与原始基线逐维比对，偏差应 ≤ 1e−4 m（本项目 ≤ 3.9e−5）
2. **零滑移**：从起点到终点逐帧算 `Δx / Δθ`，偏离 `R` 超 1e−4 的帧数应为 0
   （末几帧位移只剩 1e−5 m 时会出现浮点噪声，看该帧绝对位移就能排除）
3. **单调不增**：全段 `spd(f) >= spd(f+1) - 1e−9`，否则车会往前窜
4. **静帧段真的静**：终点之后车 X、相机 X、`进度`、车身角全部冻结
5. **驱动全 valid**：`driver.is_valid` 全 True，变量 `targets[0].data_path` 指向存在的键
6. **离地检查**：`min(车体所有网格包围盒的 z) > 0`，点头到峰值那一帧最容易穿地
7. **读值与曲线一致**：自定义属性读出来的值必须等于 `fcurve.evaluate(f)`（不等 ⇒ 撞坑 2 或没刷新）

## §6 结构上的一个额外收益

相机补偿按 `(D - REF×∫total) × 进度` 施加，`进度` 是一条 0→1 的 S 曲线、在动画终点饱和为 1。
所以**不管速度曲线改成什么样，最后一帧的相对构图都自动回到原方案** —— 用户换档位试效果时，
不需要重新对构图，这是这套结构最大的好处，值得主动讲给用户。
