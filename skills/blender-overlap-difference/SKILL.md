# 让两个网格体「物理不重叠」（布尔差集的面级替代方案）

传输层（9877 桥、客户端封装、120s 上限、Blender 5.x API 坑）见 **`blender-bridge-ops`** skill。本 skill 只讲"去重叠"这件事。

## 铁律（顺序不可颠倒）

0. **先"看见"结构，再谈数字** —— 渲染/线框确认两者拓扑关系（**谁包谁？谁穿谁？**）—— 只看占比必误判（见 §0.5）
1. **问清语义** —— "去掉重叠部分"有歧义，量出占比 **+ 结构图** 再让用户选（见 §0 / §0.5）
2. **只读侦察** —— 出报告，绝不直接动手
3. **干跑布尔评估刀法** —— 在副本上跑，别直接上原对象
4. **放还原点** —— 隐藏备份对象 + `undo_push`（**撤回全靠它**，见 §7）
5. **执行**（面级剔除）—— 执行前把"删的到底是什么"原样讲给用户（见 §0.5 披露纪律）
6. **独立核验**（另起脚本、全新 BVH）+ 核对刀具体逐位不变
7. **提醒用户 Ctrl+S**；不满意按 **§7 撤回**（别只会说 `File > Revert` —— 那会连别的编辑一起退掉）

---

## §0 先问清语义：三种"去重叠"完全不是一回事

用户说"有重叠、去掉重叠部分"时，**先量占比，再动手**。实测案例：

| 用户以为 | 实测 | 后果 |
|---|---|---|
| 两个灯互相插进去一点，切掉交叉处 | `.001` 有 **87~89%** 埋在 `.002` 内部 | 按字面执行 ⇒ `.001` 只剩 **4.98%** |

三种可能语义，**必须摆数字让用户选**：

| 语义 | 算子 | 结果 |
|---|---|---|
| **差集** | `.001 -= .002` | 保留 A 在 B **外部**的部分 |
| **交集** | `.001 ∩ .002` | 只保留**重叠**部分（"让灯不外露"常是这个） |
| **消除面穿插（视觉瑕疵）** | 不删面：`Shrink/Fatten` 整体内缩 | 造型完整、面数不变 |

**判据**：反向占比极不对称是"嵌套"而非"互相插入"。
实测 `.001→.002` 内 87~89%，反向 `.002→.001` 仅 0.01%（奇偶法）⇒ 是**小件整体埋在壳里**。

## §0.5 动刀前必须先"看见"（本 skill 最重要的一课）

**占比数字会骗人，结构图不会。** 实测事故：报告里只写了"87~89% 落在内部"，用户认可"去重叠"，
双方**都不知道那 87% 到底是什么** —— 渲染出来才发现：

| 对象 | 真身 | 规格 |
|---|---|---|
| `.002` | 多面体水晶**珠串** | 珠径 ~2cm，沿 24.6m 走廊排成一长条珠帘 |
| `.001` | 穿过每颗珠子的**竖直细灯丝** | 丝距 ~7.5cm、直径 ~2mm |

⇒ **"灯丝 87% 在珠子内部"是设计如此**（珠子本来就串在灯丝上），**不是建模失误**。
在这里"去掉重叠" = 把藏在珠子里的灯丝整段删掉 ⇒ 必然毁掉灯丝。

**纪律一（看）**：进入 §3 之前，必须先用 `scripts/render_classify.py` 出一套分类着色图 ——
绿=保留 / 红=表面相交被删 / 蓝=判为体积内部被删，刀具体线框套在外面，外加一张 x-ray 视角。
**图出不来、或看了图仍说不清"删掉的到底是什么"，不许动刀。**

**纪律二（说）**：动刀前必须把这句话**原样**讲给用户 ——

> 判定删面的判据②是"**形心落在刀具体体积内部**"，它删掉的面里**绝大多数根本不与刀具体表面相交**。
> 如果你要的是"只删表面互相穿过的"，请显式要求"**只删相交面**"（见 §3 变体）。

实测后果：用户看到结果后反馈「**001 不相交的部分也被删除了**」—— 诉求本身没错，
是我把"内部面"和"相交面"当成一件事讲了。**必须提前把这两种删法摊开让用户选。**

## §1 侦察（只读）

`scripts/probe_overlap.py` —— 一次跑完，输出：

- 两对象变换 / 世界尺寸 / 面·顶点数 / 材质槽 / 修饰器 / 父级
- **BVH 相交对数 + 波及面数** —— "表面穿插"的客观定义，比"我感觉重叠了"可靠
- **内外占比，两种独立方法并列**（射线奇偶 + 最近点法向符号）
- **反向占比**（判断嵌套 vs 互相插入）
- **相交簇空间聚类**（"一整片"还是"大量小穿插"）

> ⚠️ **铁律：内外判定必须两种方法交叉验证。**
> 实测同一对网格：`A 在 B 内` 奇偶法 86.79% / 符号法 89.47% —— **一致，可信**；
> 但 `B 在 A 内` 奇偶法 **0.01%** / 符号法 **23.31%** —— **严重分歧**。
> 分歧意味着被测量的那张网格**法向不可靠或薄壳二义**，此时**不能单信任何一个数**，
> 必须把两个数一起报给用户，并说明哪个更可信（奇偶法依赖闭合性，符号法依赖法向一致性，看谁的假设更可能成立）。

## §2 干跑布尔（评估刀法，别直接上原对象）

在 `.001` 的**副本**上挂 Boolean 修改器并 `evaluated_get(dg).to_mesh()` 量后果，然后删副本。

**实测（3ds Max 导入的 VRay 场景）**：

| 项 | 值 |
|---|---|
| 输入 | 84,208 面（全三角，`E - 1.5F = 0`，1,662 个闭合壳） |
| 刀具体 | 2,207,860 面（含 ~35,456 个四边面，`E - 1.5F = +17,728` ⇒ 非流形） |
| 设置 | `EXACT` / `hole_tolerant=False` / `use_self=False` / `material_mode=TRANSFER` |
| 输出 | **760,407 面（9.0 倍膨胀）**，`E - 1.5F = 658,848` ⇒ 严重非流形 |
| 耗时 | **71.6s**（面级剔除只要 1.77s） |

⇒ **不可用。**

**官方手册（5.0 / 4.5）口径**：
- *"Only **Manifold** meshes are guaranteed to give proper results. Non-manifold ones (especially meshes with holes) will usually work well, but might give odd glitches and artifacts. However, the **Manifold Solver will not work at all** on non-manifold meshes."*
- 三个 solver：`Float/Fast`（快、不支持重叠几何）、`Exact`（最准、全支持重叠、慢）、`Manifold`（最快、仅流形）
- `Hole Tolerant` 仅 `Exact` 可用，*"should only be enabled when the Exact solver demonstrates errors with non-manifold geometry"*
- `material_mode`：`INDEX` 按槽位映射（源的槽0→目标的槽0…）；`TRANSFER` 沿用源材质并**自动给目标加材质槽**

> **结论**：导入的 3ds Max / VRay / Sketchfab 类场景几乎必然是脏网格 ⇒ **布尔优先视为不可用**，直接走 §3。

## §3 面级剔除（推荐实现）

核心思想：**保守保留** —— 只有"**整体完全**在刀具体外部"的面才留下。

### 三类删除判据

```
删 ⟸ ① 与刀具体表面相交的面     ← BVH.overlap() 直接给出，毫秒级
删 ⟸ ② 其余面中，形心在刀具体内部 ← 三票制：沿 +法向奇偶、沿 −法向奇偶、最近点法向符号，≥2 票算"内"
删 ⟸ ③ 形心离刀具体表面 < 1e-4   ← 数值贴面安全网
留 ⟸ 以上都不满足
```

### 为什么"只测形心"就足够严格？

第 ① 类已经把**所有与 ∂B 相交的面**删干净 ⇒ 剩下的面与 ∂B **不相交**；
面是连通集，不与 ∂B 相交 ⇒ 整面**同侧** ⇒ 形心的内外符号即代表整面。

这就是"**不水密、但绝不重叠**"的数学保证：`∂A_剩余 ∩ ∂B = ∅` ⇒ 体不重叠。

### 结果特征（实测）

| 指标 | 值 |
|---|---|
| 面数 | 84,208 → **4,195**（保留 4.98%） |
| 删除构成 | 相交 45,428 + 内部 34,585 = 80,013 |
| 复核相交对 | **0**（另有 `.002` 面/顶点数逐位不变） |
| 游离顶点 / 零面积面 | 0 / 0 |
| UV / 自定义拆分法向 | 保留 |
| 耗时 | **1.77s** |
| 代价 | **切口锯齿状、不水密**（无新增面、无 n-gon） |

> 比"真布尔"保留得**更少**（布尔会沿交线切分面、保留外部的约 11%）——
> 这是"绝不重叠"的必然代价。想要更接近 11% 就得切分面，那就回到布尔的爆面问题上了。

### 变体：只删"表面相交"的面（不删内部面）

用户明确说"**只删互相穿过的部分、别动不相交的**"时，**只用判据①**，跳过②③。
这是**另一种需求**：不是差集，而是"消除表面穿插"。

| 模式 | 保留面数（实测同例） | 效果 |
|---|---|---|
| 全判据（默认，=差集） | **4,195（4.98%）** | 与刀具体表面**零接触** ⇒ 体积不重叠 |
| **仅判据①（消除穿插）** | **38,780（46%）** | 面不再互相穿透 ⇒ z-fighting / 视口穿帮消失；但**体积仍重叠**（小件仍留在壳内） |

选错模式是**静默发生**的：结果摘要同样写"✅ 已不重叠、相交对数 0"，但几何量差 9 倍。
⇒ 报告里**必须写明删了多少面、删的是哪一类**，并给出保留比例。

## §4 还原点 + 执行 + 独立核验

**还原点（双保险，因为直改数据不吃 undo）**：

```python
bak = a.copy(); bak.data = a.data.copy()
bak.name = "__BAK__%s__" % a.name
bak.hide_viewport = bak.hide_render = True
a.users_collection[0].objects.link(bak)          # 隐藏的备份对象
bpy.ops.ed.undo_push(message="cull vs cutter")   # 尝试压 undo 步（包 try/except）
```

**独立核验（另起一次请求、全新 BVH、全部重新取引用）**：

- `BVHTree.FromObject(A).overlap(BVHTree.FromObject(B))` 必须为 **0**
- 刀具体面/顶点/边数 **逐位不变**
- 目标件：游离顶点 0、零面积面 0、UV 层在、材质槽在、修饰器未被追加
- 报告保留件的世界包围盒，让用户知道残留几何落在哪
- 场景对象数变化（+1 = 备份对象）要报出来，并告知删备份的方法

## §6 坑

- **直改 `mesh` / bmesh `to_mesh()` 不是 operator** ⇒ **undo 栈未必捕获**，别只依赖 Ctrl+C→Z。必须自己放隐藏备份对象。
- **BVH.overlap 对"擦边 / 共面"可能漏报** ⇒ 保留 `dist < 1e-4` 的贴面安全网（③）。
- **内外判定法向不可靠时，奇偶法与符号法会打架**（实测 0.01% vs 23.31%）⇒ 必须并列报出，并说明各自假设。
- **`edges - 1.5 × polys` 是判断"是否闭合全三角网格"的快捷指标**：闭合全三角网格恒为 0；为正说明有四边面/边界/非流形，可用它快速判断输入有多脏（无需 bmesh 全扫）。
- **不要用"绝对判据"下结论**：同类操作在已脏的工程上会误报（呼应 `blender-scene-cleanup` 的差集铁律）。
- **删面前先冻结要用的值**（面中心/法向已缓存到 Python 侧再统一删），删后再遍历旧引用会 `ReferenceError`。
- 若刀具体还要参与后续渲染（本例 `.002` 必须完整），**绝不加修改器到刀具体**，只读它。
- **绝不要把"内部面"和"相交面"当一件事**：判据② 删的是形心在体积内的面，其中**绝大多数不与刀具体表面相交**。用户说"不相交的别删"时必须切到 §3 变体（仅判据①），否则几何量差 **9 倍**（4.98% vs 46%）。
- **剔除的"语义"必须在动手前讲透**（§0.5 披露纪律）—— 只报一个"占比 87% 在内部"就动刀，是把判断责任推给了用户。
- **动刀前先确认还原点真的建起来了**：`__BAK__` 对象存在、`mesh.users == 1`、面数与原件相等。直改数据没有 undo ⇒ 还原点没建等于撤回无门。
- **Blender 重启 / 用户重开工程后，`__BAK__` 可能已不在内存**（未存盘时）⇒ 撤回前先 `bpy.data.objects.get("__BAK__…")` 探一下，探不到就只剩 `File > Revert`。

## §7 撤回（回到动刀之前）

面级剔除**直改 mesh 数据**，undo 栈未必吃到 ⇒ 撤回只能靠 §4 执行时留下的隐藏备份对象。
`scripts/restore_from_backup.py`（改顶部 `TARGET` 即可）：

1. **先比后换** —— 别急着换。先把 `__BAK__<对象>__` 的 mesh 与场景里**所有同统计量的同源副本**
   做四个 sha1 比对（顶点坐标 / loop 顶点索引 / 面 loop 区间 / 面材质索引）。
   实测当时有两份独立副本（备份对象 + 一个 `users=0` 孤儿），**四哈希全等** ⇒ 备份可信。
2. **与操作基线逐项核对** —— 从当时的基线 json 取 `data=` 名与 `polys/verts`，填进脚本 `EXPECT`，**任一不符即中止**。
   > 基线在哪：拆分/清理类脚本会落 `*.baseline.json`。本例 `.001` 的原始网格是 `Mesh.6213 / 84208 面 / 45428 顶点 / 材质 灯光光.004`，与备份副本统计完全吻合。
3. `obj.data = bak.data` → 删备份对象 → 清掉本次产生的 orphan mesh。
   **按「本次编号下界」筛**（`ORPHAN_FLOOR`），**绝不无脑删 `users==0`** —— 老工程常有历史遗留孤儿
   （本例 10 个 `Mesh.53xx/56xx`，删了就是额外破坏）。
4. mesh 数据块名还原成原编号。
5. **独立核验**（另起一次请求）：四哈希 + 计数 + 世界矩阵 + UV + 自定义拆分法线 + 材质槽 +
   兄弟对象逐位不变 + **重叠确实回来了**（用最近点+法向符号判 `.001` 顶点落回刀具体内的比例，实测 **98.0%**）。

撤回后场景应当是：备份对象 0 个、`__BAK__` 残留 0 个、孤儿 mesh 数量**回到操作前**、目标对象面数**回到基线值**。

> ⚠️ 若用户中途存过盘，或在别处改了同一批对象 —— 撤回只还原这一个对象，**先确认磁盘 `.blend` 的 mtime**
> 与操作时间戳的先后（`bpy.data.filepath` + `os.stat`），别把整个文件 `File > Revert` 掉，那样会连带退掉此前的合法编辑。
