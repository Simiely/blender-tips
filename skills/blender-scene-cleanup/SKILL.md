# Blender 工程清理（空对象 / 孤儿数据块 / 缺失贴图）

传输层（9877 桥、客户端封装、120s 上限、Blender 5.x API 坑）见 **`blender-bridge-ops`** skill，本 skill 只讲"清理"这件事的方法论与脚本。

## 铁律（顺序不可颠倒）

1. **只读体检** → 出报告，绝不直接动手
2. **给用户选范围** —— 清理类操作有"删多删少"的判断空间，必须让用户定
3. **建还原点**：`Copy-Item` 复制 `.blend` 到 `_backup\<名>.before-<动作>.blend`，**比对字节数**
4. **执行**（脚本内三重闸 + 反向复核）
5. **独立核验**（另起脚本，全部重新取引用）
6. **提醒用户 Ctrl+S**（桥只改内存）；不满意 `File > Revert` 回滚

## 一、空对象（EMPTY）收敛清理

### 判定算法：引用图 + 不动点

**核心问题**：不能只删"当前无子级"的 EMPTY。删掉一批之后，原本挂着它们的中转空物体会变成新的无子级空物体，需要继续删，直到收敛。所以必须**一次算准最终可删集**，而不是反复扫描（反复全量扫描会超 120s 上限）。

```
一个 EMPTY 需要保留  <=>  它「支撑」某个非 EMPTY 对象
「支撑」= 以下任一（传递闭包）：
  a) 直接挂着一个非 EMPTY 子级（MESH / CAMERA / LIGHT / CURVE …）
  b) 子级里有一个"需要保留"的 EMPTY
  c) 被一个"需要保留"的对象引用（约束 target / 修改器指针 / 驱动变量）
  d) 被外部数据块引用（材质节点 OBJECT socket / 场景相机 / 相机 DOF 焦点 / 粒子 dupli_object …）

不满足以上任一条的 EMPTY  →  全部可删
```

实现：读入全部对象 → 建 `children` 映射 → 建 `incoming` 引用图 → **不动点迭代**
（种子 = 所有非 EMPTY 对象 + 所有被外部数据块引用的对象；每轮把满足 a/b/c 的 EMPTY 加进保留集，直到一轮无新增）。

参考实现：`scripts/purge_empties.py`（可直接改路径使用）。

### 三重安全闸（脚本内必须实现）

| 闸 | 内容 |
|---|---|
| 1 | 只删 `ob.type == 'EMPTY'`，其它类型一律跳过 |
| 2 | 靠不动点规则保证：删完不会有非 EMPTY 对象失去父级 |
| 3 | 靠引用图保证：删完不会有保留对象产生悬空引用 |

### 为什么这个算法是安全的（可以向用户论证）

- 删除后**不可能改变任何物体的世界变换**：删除的永远是叶子链，父级关系是父→子单向，删子不影响父
- 「非 EMPTY 对象数」在删前删后**必须完全相等** —— 这是最强的一条断言，写进核验脚本
- 「直接挂着非 EMPTY 子级的 EMPTY 数量」也必须完全不变

### 交付时给用户的两张表

**清理前后计数表**（每行都要有"结论"列，不一致就显式标红）：

| 项目 | 清理前 | 清理后 | 结论 |
|---|---|---|---|
| 总对象 / EMPTY | … | … | 减少 = 预期删除数 |
| 非 EMPTY 对象 | … | … | **必须相等** |
| MESH / CAMERA / LIGHT | … | … | **必须相等** |
| 材质 / 集合 / 场景 | … | … | **必须相等** |
| EMPTY 无子级 | N | **0** | 收敛标志 |

**被删名单**落盘（`NAME / COLLECTIONS / PARENT / ANCESTOR_CHAIN / CHILDREN / HAS_ANIM`），既可回溯，也能被核验脚本反查。

## 二、独立核验清单

另起一个脚本（不要复用执行脚本的内存状态），逐条过：

1. **名单残留 = 0** —— 被删名字不该还能 `bpy.data.objects[...]` 到
2. **非 EMPTY 对象数、MESH / CAMERA / LIGHT 数、材质 / 集合 / 场景数 全等**
3. **父级丢失 = 0** —— 每个有父级的对象，其 `parent` 仍在 `bpy.data.objects` 里
4. **悬空约束 = 0** —— TRACK_TO / COPY_* / DAMPED_TRACK / IK / FOLLOW_PATH / CHILD_OF 等的 `target` 不该为 None
5. **可见几何包围盒逐位一致** —— 取所有非 EMPTY 对象的 `matrix_world @ bound_box` 的 min/max，前后必须完全相同（这是"没动几何"最硬的证据）
6. **EMPTY 无子级 = 0**（收敛）
7. **真缺失贴图 / 链接库 / 字体 / 声音 = 0**
8. **孤儿数据块 = 0**（若本轮目标是清孤儿）
9. 顺带输出"最终保留的 EMPTY 是什么"——按集合/命名族分布，让用户能核对留下来的都是合理的中转节点

## 三、孤儿数据块（users == 0）

- 清理顺序：**先材质，再图像**。删材质会让它引用的图像变成新孤儿，要连着清
- 删孤儿图像前**必须先判磁盘有没有副本或是否已打包**：
  ```python
  # 安全才删
  img.packed_file is not None or os.path.exists(bpy.path.abspath(img.filepath))
  ```
  只打包在 `.blend` 里、磁盘无副本的数据块一旦变孤儿，**存盘即永久丢失**
- Blender 存盘时 `users == 0` 的数据块本来就不会写进 `.blend`，所以"显式删除"与"存盘丢弃"结果等价 —— 这一点要讲给用户，避免他们以为删了很危险

## 四、缺失贴图审计与还原

- **判定缺失必须带 `not img.packed_file`**，否则会把大量"路径失效但已打包"的贴图误报为缺失（本机某工程有 105 个这种）
- 报警来源：`bpy.data.images` 里 `source == 'FILE'`、`filepath` 非空、未打包、`os.path.exists(abspath)` 为 False
- 还原优先级（从优到劣）：
  1. **`.blend` 里已打包的同批次兄弟贴图**（同前缀 + 同烘焙批次号）—— 取字节写回原路径，内容最接近原物，且 `.blend` 不用改、不用存盘
  2. **磁盘上同族的近似文件**（同前缀族）—— 需改 `filepath`，要存盘
  3. 只出报告，让用户手动指定
- 还原后**三方逐位校验**：磁盘文件 md5 == 源兄弟 md5 == 内存打包 md5
- 顺带查 PNG/JPG 头，确认尺寸/位深合理

## 五、常见可清理项排查顺序

1. 缺失外部文件（贴图/库/字体/声音/影片/体积/缓存）
2. 孤儿对象 / 孤儿网格（`users == 0`）
3. 不支撑几何的 EMPTY（本 skill 第一节）
4. 孤儿材质 → **连带孤儿图像**（顺序必须 **先材质再图像**：删材质会让它引用的图像变成新孤儿；每个都先判磁盘副本/是否已打包）
5. 空集合（`len(collection.objects) == 0` 且 `len(collection.children) == 0`）—— **不是"空对象"**，要单独问用户；
   删法 `bpy.data.collections.remove(col, do_unlink=True)`（会自动从场景根摘除）。实测某工程有一个 `Export` 空集合，删后集合 10 → 9，其余计数全等
6. 位置为 `nan` 的对象（Max 导入常见坏数据）
7. 空 action slot（存盘时会被自动丢弃，不用管）
