# 射灯阵列径向摆动绽放

## 何时用

- 有一圈射灯(实测 8 盏),要它们**一起开合**像花开
- 每盏灯只能在**自己的竖直平面**内点头,不能歪
- 要求"速度不一样、先依次、后同步、再错位"的拍频效果

## 几何三要素(动手前必须和用户确认)

| 量 | 怎么定 |
|---|---|
| **起始线(0°)** | 灯 → 中轴线对象 的连线。**中轴对象被抬高时这条线是倾斜的** —— 实测中轴 1.2606 vs 灯 0.4054 ⇒ 起始线朝内上方倾斜 18.8° |
| **旋转平面** | 灯的位置与**竖直中轴线**确定的平面。8 盏 = 8 个绕轴辐射的平面 |
| **旋转轴** | 该平面内水平且垂直于半径的**切向轴** `t̂ = ẑ × r̂` |

⚠️ **定位空对象通常是 `rotation=(0,0,0)` —— 朝向信息根本不存在。**
Blender 聚光灯默认朝 `−Z`(向下)。**方向必须问用户,不许默认朝下。**

⚠️ 「灯到中轴线的连线」有歧义:指向轴上**垂足**(水平)vs 指向**中轴对象那个点**(倾斜)。
按用户原话取"对象"那个点。中轴与灯等高时两者一致,不等高时差出仰角。

## 架构:必须插一层「铰链」

```
射灯(定位空对象, 位置不动)
  └─ 射灯_铰链   rotation_euler = (α_driver, 0, rz),  rz = atan2(t̂.y, t̂.x)
       └─ 射灯_光   rotation_euler = (π/2 + elev, 0, 0),  elev = 起始线仰角
```

**灯的局部旋转为什么是 `π/2 + elev`**(别凭感觉写):

1. `'XYZ'` 欧拉的实际矩阵 `R = Rz(rz)·Ry(ry)·Rx(α)`,`ry=0` ⇒ `R = Rz(rz)·Rx(α)`
2. 此时第一列(X 轴)恒为水平 `(cos rz, sin rz, 0)` ⇒ `rz = atan2(t̂.y, t̂.x)` 得 `X = t̂`
3. 灯照射方向是局部 `−Z`,要求 `α=0` 时指向起始线 ⇒ 灯在铰链局部的朝向
   `v = Rz(−rz)·起始方向 = (0, cos elev, sin elev)`
4. `Rx(θ)·(0,0,−1) = (0, sin θ, −cos θ) = v` ⇒ `θ = 90° + elev`

🚫 **XYZ 顺序下"X 轴水平"必然"Z 轴竖直"**,不可能同时取 `X=t̂` 且 `Z=r̂`。
按 `基=[t̂, ẑ, r̂]` 造矩阵再赋给 `rotation_euler` 会**静默歪掉**。这就是要插铰链的原因。

## 拍频公式(核心)

```
f_i    = 1 + spread·i/7                                    # 按方位递增
θ_i(t) = 2π · ( t·f_i − sync·(f_i − 1) ) / period
α_i(t) = amin + (amax − amin) · (0.5 − 0.5·cos θ_i(t))     # 正弦缓动
```

`t = sync` 时 `f_i` 被抵消 ⇒ `θ_i = 2π·sync/period` 与 i 无关 ⇒ **精确同步**。

**同步瞬间的展开角由 `sync/period` 的小数部分决定**:
`2.0 → 0°`(整体闭合)/ `2.25 → 62.5°`(半开)/ `2.5 → amax`(整体全开,默认)

**对齐周期 = `7 × period / spread`**(默认 240/0.10 ⇒ 16800 帧)。
3000 帧场景里**只会精确同步一次**。要更频繁就加大 spread。

driver 表达式(实测可用,用 `pi/180` 不用 `radians()`):

```python
"amin*pi/180 + (amax-amin)*pi/180"
"*(0.5 - 0.5*cos(2*pi*(fr*(1+spread*%d/7) - sync*spread*%d/7)/period))"
```

## 作业循环

1. **探查**(`probe_bloom.py`):打印 8 个定位空对象的位置 / 起始线仰角 / 方位角 / 缩放 / 现有层级
2. **向用户确认方向**:起始线定义 + 摆幅(起始角与展开角)。**不许替用户拍板**
3. **最小 demo 验证 API**:在临时对象上挂一次 driver、改帧读值,确认通了再写批量脚本
4. **构建**(`build_bloom_swing.py`)
5. **另一次请求核验**(`verify_bloom.py`,看 `VERDICT`)
6. 提醒:桥只改内存要 Ctrl+S;移动中轴不自动重算,需重跑构建

## 铁律(绝对不能干)

1. 🚫 **不许跳过 API 验证直接写批量脚本** —— 中途抛异常会留下**半改造状态**
   (实测:8 盏循环跑到第 1 盏就炸,结果只有那一盏变成铰链架构、朝向与其余 7 盏不一致,
   用户预览直接看到"有一盏不对",而且 driver 已 new 出来但变量没挂上)
2. 🚫 **不许在 5.2 里直接 `tg.id = scene`** —— 必须先 `tg.id_type = 'SCENE'`
3. 🚫 **不许在同一次请求里改完就验证** —— 会读到未刷新缓存值,必须分两次
4. 🚫 **不许用 `startswith("射灯")` 匹配定位空对象** —— 会把 `射灯_光` / `射灯_铰链` 一起吞掉。
   用 `^射灯(\.\d{3})?$`
5. 🚫 **不许默认灯朝下** —— 空对象没有旋转信息,方向必须问用户
6. 🚫 **不许声称"移动中轴会自动重算"** —— 本方案是静态的,`rz`/`elev` 写死在变换里

## 5.2 实测 API 变更(每次写脚本前对照)

| 4.x 写法 | 5.2 实测 |
|---|---|
| `ActionSlot.name` | **不存在** → `name_display` / `identifier` |
| `UnitSettings.length_system` | **不存在** → `system` / `length_unit` / `scale_length` |
| `Light.power` | **不存在** → `energy`(新建 Spot 默认仅 **10 W**) |
| `Light.show_cone` 默认 True | **默认 `False`**,视口要显示锥必须显式打开 |
| `DriverTarget.id` 接受任意 ID | **必须先 `id_type='SCENE'`**,否则只接受 Object |

**桥是 `exec` 整段代码,任何一行抛异常会让前面所有 print 全部丢失**(stdout 被 redirect,
只有整体成功才回包)⇒ 排查成本极高,先探再写。

## 核验判据(三条全过才算成功)

| 判据 | 期望 |
|---|---|
| 灯的**世界位置误差** | `0` |
| **切向偏离** `dir·t̂` | `≈ 0`(锁死在径向平面) |
| sync 帧 8 盏**展开角之差** | `0.000000` |

实测通过值:位置误差 0、切向偏离 0.000000、frame 600 角差 0.000000(全部 125.0°)。

## 参数(Scene 自定义属性,实时可调)

`bloom_min_deg` 0 / `bloom_max_deg` 125
