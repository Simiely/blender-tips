# 径向「内收多脉冲」发光材质（环数恒定）

> 一句话：图案只依赖到**共享中心的距离 r**，把「环」写成 `FRACT(r/间距 + 相位)` 的周期带、
> 让**相位随时间增大**，环就往中心收；`FRACT` 天然环绕 ⇒ 无缝循环。

**三个前置 skill，先读：**

| 需要什么 | 去哪 |
|---|---|
| 怎么把代码送进正在运行的 Blender（桥、客户端封装、120s 上限、BOM、`__file__` 不存在） | **`blender-bridge-ops`** |
| 世界空间程序化材质的**通用机制**（SINGLE_PROP 驱动、tag 矩阵、读求值依赖图、像素级验收、ColorRamp 做对比度） | **`blender-procedural-emission-material`** |
| 径向距离场的**几何地基** + **时间链**（`TVAL ≡ 帧号`、周期/相位分离、四段循环脉冲） | **`blender-radial-pulse-material`** |

**本 skill 只讲「内收多脉冲」这一路独有的东西**：周期环带怎么定、**环数怎么算准**、亮面怎么裁、配色怎么从别的材质搬。

**脚本包**：[`../../scripts/radial-inward-pulse/`](../../scripts/radial-inward-pulse/)（`probe_target_size.py` / `build_inward_pulse.py` / `verify_inward_pulse.py`），
配套文档 [`../../docs/径向内收多脉冲材质.md`](../../docs/径向内收多脉冲材质.md)。

**实测环境**：Blender **5.2.0 LTS** / Windows。

## 铁律

1. **先只读侦察**：量出中心、半宽、**角点半径**。`"共心"` 必须实测，别信描述
2. **先问清「在哪条半径上数环」**——这条不问清，间距算得再准也是白干（见 §2）
3. **改动前放还原点**；姊妹材质只读，`use_fake_user` 保留
4. **执行完另起一次请求独立核验**（全新取引用、驱动输入走求值依赖图）
5. **判据取"解析式复算 + 分布统计"**，别只看最大值（见 §3）

## §1 节点链（径向场 → 周期带 → 裁切 → 输出）

```
纹理坐标(Object=控制器) → Mapping(恒等) → VectorMath(LENGTH) → r
r ÷ 间距 → q
q + 相位                 相位 = 帧号 ÷ 循环周期 + 相位偏移
  → FRACT → t
t → MapRange([0, e/d] → [0,1])              上升沿 ┐
t → MapRange([w/d−e/d, w/d] → [1,0])        下降沿 ┴→ ×  → band（梯形）
r ÷ 色相半径 → rn → ColorRamp(色相)  → Emission Color
rn → ColorRamp(外缘轻收) ┐
band ────────────────────┴→ × → mask
mask = mask × cut          cut = MapRange(r − 亮面半径, 0..淡出宽度, 1..0)
mask × 发光强度 → Emission Strength
色相 × (mask × 底色亮度) → Base Color
```

- **内收方向**：相位增大 ⇒ 带位 `r = 间距 × (k − 相位)` **减小** ⇒ 往中心收。
  「向外扩」= 循环周期设负值。
- **循环周期（帧/圈）= 1 ÷ 每帧推进的周期数**。用**帧数**表达，别用「速度」——
  用户填「多少帧走完一圈」是直觉的，填「每帧 0.02 圈」还要心算倒数。实现是一句除法。

## §2 ★★ 环数恒定：有效窗口公式（本 skill 最值钱的一节）

```
可见带窗口 = L + 占空比 − 软边占比 − 2 × 最小可见宽度          必须 ≈ N
    L = R_ref / 脉冲间距 ; 占空比 = 宽/间距 ; 软边占比 = 柔/间距
⇒ L = N − 余量 − 占空比 + 软边占比 + 2 × 最小可见宽度
```

**三项缺一不可**（每一项都是被实测打回来的）：

| 少扣了哪一项 | 实测症状 |
|---|---|
| 只写 `L + 占空比 ≤ N` | 最多出现 **N+1** 条（宽占空比下首尾各多露一条） |
| 再补「− 软边」，没扣 `2×最小可见宽度` | 仍有约 **2%** 的相位只显示 **N−1** 条 |
| 全扣干净 | **N 条占比 ≥ 99.8%**，永不出现 N+1 |

> **为什么要减软边**：阈值 0.5 下亮带的实际可见宽度是 `占空比 − 软边`
> （梯形两侧各有半条软边落在 0.5 以下）。
> **为什么要减 2×最小可见宽度**：一条带至少占 1% 周期才算「看得见」，
> 区间两端各要留这么多。

### §2.1 ★★ 基准半径 `R_ref` 必须问清（最容易返工的一处）

| 非圆网格（正方形板） | 半径 |
|---|---|
| **内切圆**（用户说的"看圆"） | 半宽 |
| **角点**（对角线） | 半宽 × √2 |

**两者相差 √2 ≈ 1.414，几何上不可能处处一样多。**
实测踩过：按**角点**定 3 条 ⇒ 角上 3 条、**中间的圆只有 2 条** ⇒ 用户直接说「圆形只有 2 个环」。

⇒ **先问「在哪条半径上数环」**，再算间距。构建脚本把它做成开关
（`REF_FOR_COUNT = 'CIRCLE' | 'CORNER'`），并在**解析扫描里同时报告两处**的环数分布。

### §2.2 扫描判据

**别只看最大值**。判据要同时报：**最小 / 最大 / 恰为 N 的相位占比**。

- 一条带要**径向宽度 ≥ 1% 周期**才算一条（滤掉边界上刀尖似的碎屑）
- 相位要扫密（400~600 个）+ 半径采样要细（4000~6000 点）

## §3 亮面裁切：发光限制在一个圆内

```
cut  = MapRange(r − 亮面半径, 0..淡出宽度, 1..0, clamp)
mask = band × 外缘轻收 × cut        ← 发光和底色都取自裁切后
```

- 默认 `亮面半径` = 内切圆半径 ⇒ 四角落在裁切外 ⇒ **不再多出环**，圆外纯黑
- 想「铺满整个方板」：调到 ≥ 角点半径

### ★★「亮面面积」与「黑边粗细」是两个**正交**旋钮

| 用户说的 | 该动哪个 |
|---|---|
| 黑边太粗 / 太细 | **占空比**（`w/d`）+ 软边占比 |
| 亮面面积要缩小 / 发光范围收紧 | **裁切**（`亮面半径` / `淡出宽度`） |

实测踩过：把「亮面面积缩小」理解成**加宽黑边**（占空比 0.88→0.60）⇒
黑边从 24% 涨到 52% ⇒ 用户下一句就是「黑边还是太粗了」。
**混成一个旋钮 = 必然返工。**

## §4 配色复用：从姊妹材质搬 ColorRamp

**不能读那个材质的 `Emission Color.default_value`** —— 插槽若**已连线**，
`default_value` 只是没用的残留存值（实测读到 `(1,1,1,1)`，而真实配色是一条 ColorRamp 的 6 个色标，全丢了）。

**正解**：顺连线找到真正的颜色来源节点，把**色标逐项复制**：

```python
def grab_ramp(src_mat, names, label_kw):
    for nm in names:
        n = src_mat.node_tree.nodes.get(nm)
        if n is not None and n.type == 'VALTORGB':
            return n
    for n in src_mat.node_tree.nodes:          # 再按中文 label 模糊找
        if n.type == 'VALTORGB' and label_kw and label_kw in (n.label or ""):
            return n

old = grab_ramp(bpy.data.materials[MAT_OLD], ("COL",), "色相")
STOPS = [(e.position, tuple(e.color)) for e in old.color_ramp.elements]
```

- **构建时实时读** ⇒ 以后在旧材质里微调颜色，重跑一次就同步，不会走样
- 核验里加一条**跨材质对拍**断言（新色标必须与旧材质逐项一致）

### ★ 色标必须归一化后再喂

旧材质色标铺在 `r ∈ [0,1]` 上（那时网格半宽正好 1.0）。
新网格半宽不同时**必须先 `rn = r / 色相半径`**（默认 = 网格半宽），
否则超过 1 的部分全被钳到**最后一个色标** ⇒ 整个面糊成一片暗红。

## §5 ★★ 驱动只能挂在 `Value` 节点输出上

**症状**：拖时间轴**画面完全静止**。

**根因**：把驱动写在了 `Math` 节点的**输出插槽**（`mul.outputs[0].default_value`）上。
Math 节点的输出由它自己的运算决定 ⇒ **驱动被覆盖 = 等于没写** ⇒ 该项恒 0。

**正解**：每个受驱标量各占一个 **Value 节点**，Math 只做运算：

```python
v_frame  = V('帧号', 0.0)        # 驱动 = SINGLE_PROP → SCENE.frame_current
v_period = V('循环周期', 50.0)   # 驱动 = SINGLE_PROP → ctrl["循环周期"]
div_ph   = MATH('相位推进', 'DIVIDE')
links.new(v_frame.outputs[0], div_ph.inputs[0])
links.new(v_period.outputs[0], div_ph.inputs[1])
```

### ★ 守卫（构建 + 核验都要有）

```python
_bad = []
for d in nt.animation_data.drivers:
    p = d.data_path
    nm = p.split('"')[1] if '"' in p else None
    n = nt.nodes.get(nm) if nm else None
    if n is None or n.type != 'VALUE':
        _bad.append((p, n.type if n else None))
assert not _bad                      # 挂错就直接点名报出来
```

再加一条**帧号响应自检**：`frame_set` 到几帧、读回帧号节点必须精确等于帧号。

> 这条守卫是被真实的返工逼出来的：上一版核验只断言了「有 1 条驱动读 `SCENE.frame_current`、
> 表达式正确」，**没断言它挂在哪类节点上** —— 而计算输出又读不到真值（§6），所以完全看不见相位是 0。

## §6 核验：读不到中间节点真值，改用「基准 + 驱动输入 + 解析复算」

**已连线的「计算输出」插槽，Python 读 `default_value` 恒为 0** ——
只有被**关键帧或驱动器直接写入**的插槽才有可读值。

| 能读 | 读不到 |
|---|---|
| `Value` 节点输出（被驱动/关键帧写入） | `Math` / `MapRange` / 输入已连线的 socket 的**输出** |

⇒ 核验拆成三层：

1. **结构**：节点/连线数、`r` 上游可追到 `纹理坐标.Object`、无 `SEPARATE_XYZ`/`COMBINE_XYZ`、
   MapRange 名单、色标逐项对拍
2. **驱动**：全部 `is_valid=True`、**全部挂在 Value 节点输出上**、变量与 data_path 正确
3. **行为**：逐参数改值 → 读对应 `Value` 节点回值；**帧号响应**；再**用现读参数解析复算环数**
   （扫描判据同 §2.2）

## §7 坑表（本路实测）

| # | 坑 | 正解 |
|---|---|---|
| 1 | 基准半径选错（圆上少一条） | 先问「在哪条半径上数」（§2.1） |
| 2 | 有效窗口公式漏项，环数在 N±1 跳 | 软边、最小可见宽度都要扣 |
| 3 | 驱动挂在计算节点输出上 ⇒ 画面静止 | 只挂 Value 节点输出 + 加守卫（§5） |
| 4 | 读别人颜色读 `default_value` | 顺连线找真正的来源节点（§4） |
| 5 | 色标没归一化 ⇒ 整面暗红 | `rn = r / 色相半径` |
| 6 | 「亮面面积」与「黑边粗细」混成一个旋钮 | 裁切 vs 占空比，正交（§3） |
| 7 | `__file__` 在桥 exec 里不存在 | 附件路径写绝对常量或内联（`blender-bridge-ops`） |
| 8 | `animation_data.drivers` 的元素是 `FCurve` | 走 `d.driver.variables` / `d.driver.expression` |
| 9 | VectorMath 节点类型是 `'VECT_MATH'` | 不是 `'VECTOR_MATH'` |
| 10 | ColorRamp 输入插槽 `name='Factor'` / `identifier='Fac'` | 断言用 `name`，连线用索引 |
| 11 | 对象总数掩盖构成变化（+1 EMPTY / −1 MESH） | 核验**按 `ob.type` 分类计数** |
| 12 | `driver_add()` 把表达式填成常量 | 必须**覆盖** `d.expression` |
| 13 | `Map Range` 同名不同类型的插槽（VALUE/VECTOR） | 按 `(name, type)` 或索引取 |
