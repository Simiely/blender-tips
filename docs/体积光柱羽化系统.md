# 体积光柱羽化系统(Blender 5.2)

> 舞台光柱在 Cycles 里**真空是看不见的**;用「闭合锥体 + 局部体积」当假体积,
> 再把**同一个渐变同时接到 `Density` 和 `Emission Strength`**,边缘才会真正羽化。
> 本文含一处**反直觉的决定性发现**、一处 **5.2 引用失效坑**,以及 8 盏射灯共用一份材质的做法。

---

## 场景

射灯(SPOT)阵列要出「光束」效果 —— 舞台上那种一道道可见的光柱。

直接渲染是**看不到**的:

| 场景(纯黑世界,400×400) | 非零像素 | 峰值 |
|---|---|---|
| A 只有灯,无任何锥体 | **0** | 0.00000 |
| B 灯 + 体积锥 | **5871** | 1.19355 |
| C 锥体 `hide_render=True` | **0** | 0.00000 |

A 精确为 0 不是"暗",而是**一个光子都没进摄像机**。C 归零反证 B 那 5871 个像素确实来自锥体。

---

## 原理

### 一、为什么真空里看不见光柱

Cycles / EEVEE 都是**光线追踪**:相机只记录"射到它身上的光"。介质为空时,光子在灯到物体之间直线穿过、不产生任何可被捕获的散射事件,相机收不到"光路径中间"的信息。

现实舞台能看到光柱,是因为空气里有雾和烟尘。**纯空气里连激光束都看不见。**

所以"不加体积也能看到光柱"在物理上做不到 —— 但**用几何体造一个"假光柱"**完全可以,而且这是实际制作里最常用的做法。

三条路:

| 方案 | 需要体积? | 形状来源 | 速度 | 适合 |
|---|---|---|---|---|
| **发光几何锥** | 否 | 几何精确匹配 | 极快 | 舞台光柱、阵列、需精确可控 |
| **局部体积**(锥内挂体积材质)⭐ | 是(小范围) | 几何 | 中 | 要雾感但不想全局变雾 —— **本文方案** |
| 全局体积散射 | 是 | 灯光锥角 | 慢、噪 | 雾中真实光交互 |
| Billboard 贴图 | 否 | 贴图 | 最快 | 远景、大量灯 |
| 后期 Glare / Bloom | — | 无 | 极快 | **只能给已有亮像素加光晕,造不出光柱** |

实测淘汰过程(10 个变体,逐个渲图判断):

| 变体 | 结果 |
|---|---|
| 发光锥几何(Emission + Transparent mix) | 像一根**实心白塑料柱**,边缘生硬 |
| 经典「假体积」(加视线-光轴夹角补偿) | 与上者几乎无差别 |
| 全局体积散射 | 200W 灯 / 10m / 10° 下**散射太弱,几乎全黑**(峰值 0.047) |
| 三层同心锥(靠堆层数柔化) | **出现难看的竖直条带**(轮廓线可见)—— 淘汰 |
| **局部体积 + 自发光** | **胜出**:边缘融进背景 |

### 二、为什么假几何锥的边缘天生是硬的

假几何方案的亮度来自「**锥面被照亮**」—— 你实际看到的是**前后两层壳**,边缘就是网格边界,所以永远是硬的,靠调材质救不回来。

体积方案则不同:亮度来自「**视线穿过的介质总量**」。在轮廓处,穿过的介质厚度自然趋于 0,所以边缘**自动柔化**。

但**还不够软**,原因在数学上:

> 均匀密度的体积锥,横向亮度 ∝ **弦长** = `2√(R² − d²)`
> 在 `d → R`(贴近轮廓)处,`√` 的导数**发散** ⇒ 亮度是"猛一下升起来"的 ⇒ **看上去仍然是硬边**。

实测:未加径向衰减时,亮度从峰值的 **78% 掉到 0 只用了 8 个像素**(近距 400×400 下 50%→10% 过渡宽度仅 **6px**)。

### 三、★ 决定性发现:`Principled Volume` 的 **Emission 不受 Density 控制**

这是本文最关键、也最反直觉的一条。**只把渐变接到 `Density` 是白费的。**

实验(独立后台进程,给 `Density` 接一个常量):

| `Density` 链接到 | 渲染峰值 |
|---|---|
| `Value = 0.0`(零浓度) | **19.74** |
| `Value = 0.8` | **17.32** |

**零浓度竟然还是亮的**,而且**比有浓度时更亮**。

- `Density` 只控制**吸收 / 散射**系数,**自发光是独立通道**
- 浓度越低 → 吸收越少 → 自发光累积得越多 → **反而更亮**

⇒ 结论:**边缘硬度来自"发光是均匀的",而不是来自密度**。
⇒ 修法:**把同一个渐变同时接到 `Emission Strength`**,让发光本身在边缘趋零。

修正前后实测:

| | 50%→10% 过渡宽度 |
|---|---|
| 只接 `Density`(修正前) | **6 px** |
| 同时接 `Emission Strength`(修正后) | **18 px**(3 倍) |

### 四、径向衰减公式与节点链

锥体局部坐标(用 `primitive_cone_add` 建,原点在中腰):

```
apex 在 z = +L/2  (半径 0)
底面 在 z = −L/2  (半径 R)
半径随高度线性变化:  radius(z) = R/2 − R·z/L
任意点的径向距离:    r = √(x² + y²)
归一化径向坐标:      ρ = r / radius(z)      ∈ [0, 1]  (锥内)
```

**径向衰减:**

```
径向 = 1 − ρ^p          p = 「羽化指数」
```

`p` 越小,渐变铺得越开、整体越柔:

| p | 效果 |
|---|---|
| 0.1 | 极柔(但很暗) |
| **0.5** | 很柔 —— 常用档 |
| 1.0 | 线性 |
| 2.5 | 亮芯集中 |
| 4.0 | 边缘最清晰 |

**长度(轴向)衰减**:决定**两端的收尾**。这一项**第一版做错过**,详见 §五。

**最终节点链:**

```
u      = MapRange(z, zmin … zmax → 0 … 1)                   0=远端粗端, 1=近灯细端
长度项  = MapRange(u, 0 … 尾部羽化 → 0 … 1, SMOOTHSTEP)      ★ 端点精确到 0
径向项  = 1 − ρ^p                                          p = 羽化指数

fall = 长度项 × 径向项

Density           ← fall × 浓度
Emission Strength ← fall × 亮度      ★ 少了这条,羽化不生效
```

节点实现要点:

- `ρ` 的分母要 `MAXIMUM(radius(z), 0.0001)`,否则锥尖处 `0/0` 出 NaN
- `分离XYZ → 合并XYZ(x,y,0) → 向量数学 LENGTH` 得 `r`
- `POWER` 与 `SUBTRACT` 都要勾选 **Clamp**,把结果压在 `[0,1]`
- 轴向那级 `MapRange` 要设 `interpolation_type = 'SMOOTHSTEP'`(默认是 `LINEAR`)
- 体积域**必须是闭合网格**(`end_fill_type='TRIFAN'` 或 `'NGON'`)

### 五、轴向收尾:远端为什么会有平切硬边

这是实战里最容易做错的一处。**第一版**的轴向衰减是一条线性斜坡:

```
MapRange(z, −L/2 … L/2 → 0.05 … 1.0)
```

看起来没问题,实际上**远端是硬切**:它在**几何末端只降到 0.05,不是 0** ——
端面那片圆盘还留着 5% 亮度,然后被网格边界**一刀切掉**。
正交侧视一看就出来:光柱底部是**一条平切的水平硬边**,而不是渐渐消失。

**正确做法:归一化 + 平滑渐变,且精确到 0**

```
u      = MapRange(z, −L/2 … L/2 → 0 … 1)              归一化(0=远端粗端, 1=近灯细端)
长度项  = MapRange(u, 0 … 尾部羽化 → 0 … 1, SMOOTHSTEP)
```

`SMOOTHSTEP` 让曲线**在远端趋近 0 且极其平缓**,于是光柱自然溶进黑暗,**没有端面残余**。

**★ 为什么用 MapRange 的 SMOOTHSTEP,而不是 ColorRamp 节点**

需求是"**羽化距离可调**",也就是**渐变终点要可调**:

| 方案 | 终点能否被节点驱动 |
|---|---|
| `ColorRamp` 节点 | ✗ —— 色标位置 `color_ramp.elements[1].position` **没有输入插槽**,连不上 `Value` 节点 |
| `MapRange` 节点 | ✓ —— `From Max` **是一个 socket**,可直接连 `Value` 节点 |

两者是同一族的平滑曲线,但只有 MapRange 这一路能把"渐变终点"接到滑块上。

**实测档位**(正交侧视,远端基座在画面 93.5% 处;取样自近灯端 → 远端):

| 尾部羽化 | 70% 处 | 80% 处 | 90% 处 | 观感 |
|---|---|---|---|---|
| **1.0** | 0.774 | 0.533 | 0.168 | **最柔**,远端溶进黑暗 ✅ 推荐默认 |
| 0.70 | 0.865 | 0.645 | 0.198 | 略亮、收尾略清晰 |
| 0.40 | 0.972 | 0.825 | 0.311 | 收尾最明确(接近"硬切"那版观感) |

> 注意 **1.0 是数学上的极限**:此时渐变铺满全长,中点亮度约为峰值的一半。
> 想更长就得同时压低近端亮度,那等于整体变暗,不如直接调「亮度」。


### 2. 建(或重建)羽化材质

```python

```

同时会在场景上创建 3 个**带滑块的**自定义属性(见下「参数驱动器」)。

### 3. 批量建锥,并让多盏灯**共用同一份材质**

```python
python add_cones_all_lights.py
```

- 遍历所有 `SPOT` 灯,**已有锥则跳过**
- 锥体 `parent` 到各自的灯,局部位置 `(0, 0, −L/2)`、旋转 `(0,0,0)`
  ⇒ apex 精确落在灯位、轴向自动跟随灯
- 只对相机可见(见下)
- **全部挂同一个材质** ⇒ 8 盏灯 = **一组驱动器**,改一个数全变

**共用的前提**(很重要):材质里**烘焙了 `R` 和 `L` 两个常量**,
所以只有当所有灯的 `spot_size` 与 `cutoff_distance` **完全一致**时才能共用。
不一致就必须一灯一材质(脚本会自动分组处理)。

### 4. 只对相机可见

## 参数驱动器(让参数可手动调)

材质节点**不会**出现在属性面板上,所以链路是:
**场景自定义属性(面板滑块) → 驱动器 → 节点里的 Value**。

```python
# ① 属性(键名就是显示名,想要中文标签就得用中文键)
sc["光锥羽化"] = 1.5
sc.id_properties_ui("光锥羽化").update(
    description="光锥边缘羽化:越小越柔",
    min=0.1, max=8.0, soft_min=0.5, soft_max=4.0)     # 设了 min/max 才会变滑块

# ② 驱动器:AVERAGE 型 = 单变量、无表达式
fc = value_node.outputs[0].driver_add("default_value")
d  = fc.driver
d.type = 'AVERAGE'                    # ★ 不用 SCRIPTED,避开脚本自动执行权限
var = d.variables.new(); var.name = "v"; var.type = 'SINGLE_PROP'
tgt = var.targets[0]
tgt.id_type = 'SCENE'                 # ★ 必须先设 id_type,再赋 id
tgt.id = sc
tgt.data_path = '["光锥羽化"]'
```

**为什么用 `AVERAGE` 而不是 `SCRIPTED`**:`SCRIPTED` 型在**非受信任打开的 .blend** 里会静默不求值(见主题 45)。`AVERAGE` 只做单变量取值,**不需要 Python 表达式求值权限**,天然免疫。

**改完属性后要打 tag**:依赖图**不会**因为你改自定义属性就自动重算。
脚本里改完要 `sc.update_tag()`;**GUI 里拖滑块 Blender 会自动打**,所以手上是即时的。

## ⚠️ 坑(代码里看不出,全是实战踩的)

### 1. ★★★ 绝不在用户正在用的会话里执行「换文件级」operator

`bpy.ops.wm.read_factory_settings` / `read_homefile` / `wm.open_mainfile` ——
**通过远程桥送进用户正在用的 Blender,会重置/卸载当前文件**。

实测事故:在用户会话里连调两次 `read_factory_settings`,`Blender 卡死 → 桥无响应 → 崩溃`,
**未存盘的改动全部丢失**(本次丢了两次羽化改造)。

> **铁律**:需要在空场景里做实验 → 一律另开**独立后台进程**:
> `blender.exe -b --factory-startup --python 实验.py`
> 桥只允许跑「读写当前 .blend 内存」的脚本。

**识别信号**:桥开始 `ERR / timeout after 120s`,同时 `tasklist` 里 blender.exe
**内存长时间不变** ⇒ 多半是弹了模态框或主线程卡死,不是"在忙"。

### 2. ★★★ `Principled Volume` 的 Emission **不受 Density 影响**

见上文「决定性发现」。**只把渐变接 `Density`,羽化完全不生效**,
而且会得到"密度越低画面越亮"的反直觉结果。必须**同时接 `Emission Strength`**。

### 3. ★★ 5.2 里 `nodes.remove()` 之后,旧节点引用会失效

```python
out = [n for n in nt.nodes if n.type == 'OUTPUT_MATERIAL'][0]
for n in list(nt.nodes):
    if n is not out:
        nt.nodes.remove(n)
nt.links.new(pv.outputs[0], out.inputs["Volume"])   # ← 可能拿到失效引用!
```

- `out.name` 读出**乱码**,直接抛 `UnicodeDecodeError`
- `out.inputs["Volume"]` 抛 `KeyError: key "Volume" not found`
- 更阴的是:**链接可能静默丢失** —— 不报错,但节点根本没接上
  (本次就因此误会过一整轮,以为"密度衰减接上了其实没生效")

> **正确写法**:删完节点后**重新遍历 `nt.nodes` 取输出节点**,绝不跨删除持有引用。

### 4. ★★ 改自定义属性后依赖图不会自动重算

脚本里:`sc["X"] = v` 之后必须 `sc.update_tag()`,否则驱动器读到的是旧值。
**GUI 拖滑块会自动打 tag**,不用管。
另:驱动器求值**有延迟** —— 同一次脚本内"改属性 → 立刻读插槽"读到的是**旧值**,
要**下一个独立事件**(下一次远程调用 / 下一次刷新)才读到新值。

### 5. ★ `NodeSocketFloat` 没有 `.is_driven`

查某个插槽有没有被驱动,不能读属性,要翻动画数据:

```python
dpaths = [fc.data_path for fc in nt.animation_data.drivers]
# → 'nodes["羽化指数"].outputs[0].default_value'
```

### 6. ★ 体积域必须是闭合网格

`primitive_cone_add` 要带 `end_fill_type='TRIFAN'`(或 `'NGON'`)把底封上。
不封口的锥体做体积域会漏。

### 7. ★ 纯散射在这个尺度下几乎不可见

200W 灯 / 10m 长 / 10° 锥:纯散射峰值只有 **0.047**,
必须靠 `Emission` 补亮才看得见。代价是"更像自发光的凝胶"而不是"被照亮的雾",
两者可以混(把 `Emission Strength` 调小、散射调大)。

### 8. **羽化越强越暗**,要用亮度补偿

因为 `Emission Strength` 被 `fall` 乘了一遍,羽化指数越低,整体发光越低。

| 羽化指数 p | 峰值 | 50% 宽度 | 过渡宽度 |
|---|---|---|---|
| 0.1 | 0.390 | 222 px | 297 px |
| 0.5 | 0.613 | 242 px | 277 px |
| 1.0 | — | 259 px | 260 px |
| 1.5 | — | 269 px | 250 px |
| 2.5 | — | 280 px | 239 px |
| 4.0 | — | 289 px | 230 px |

(近距离 520×520 渲染;过渡宽度 = 扫描线上 50% 与 10% 阈值之间的像素跨度,越大越柔)

### 9. **按名字筛对象时,中文下划线的位置会坑你**

实测误报:用 `o.name.endswith("_光锥")` 找锥体,漏掉了 `射灯_光_锥`
—— 它结尾是 `光_锥` 不是 `_光锥`。结果我向用户报告"那个对象已不存在",**是错的**。

> 宁可放宽成 `"锥" in o.name` 或正则可选组,别用 `endswith` 拼中文名。

### 10. 自定义属性的**键名就是显示名**

Blender 没有独立的 label 字段 —— 想要中文标签,键本身就得是中文。

### 11. 桥的 exec 是整段代码,异常会让前面所有 print 全丢

写批量脚本一律**整体 `try/except` + 打 traceback**,否则报错后你连它跑到哪一步都看不到。

### 12. ★★ 线性长度衰减的底值不是 0 ⇒ 远端是一条平切硬边

体积锥的**端面**就是几何边界。如果轴向衰减在几何末端**还留着残余值**
(第一版写到 `0.05`),那片端面圆盘就带着 5% 亮度**被一刀切掉**
⇒ 画面上是一条明显的**水平硬边**,看着像被刀切平的。

**必须让轴向渐变精确到 0**,并且**在远端极其平缓**(用 `SMOOTHSTEP`)。
反过来,想让远端"实"一点,就**调小「尾部羽化」**(把渐变挤进更短的距离)。

**配套的第二个坑**:要调"渐变终点",**别用 `ColorRamp` 节点** ——
它的色标位置 `color_ramp.elements[1].position` **没有输入插槽,连不上 `Value` 节点**,
想做成滑块只能另外挂驱动器(路径绕、易错);
而 **`MapRange` 的 `From Max` 本身就是 socket**,直接连过去就行。

## 参数速查

| 参数 | 建议默认 | 说明 |
|---|---|---|
| 径向羽化指数 `p` | 0.5 ~ 1.5 | **横截面**羽化;越小越柔,同时越暗 |
| **尾部羽化** | **1.0** | **轴向收尾**渐变长度;越大 → 渐变越长 → 远端越柔(0.15 ~ 1.0) |
| 浓度 | 0.8 | 体积浓度。注意它**不影响自发光亮度** |
| 亮度(Emission) | 2.5 | 主要亮度旋钮;**羽化变柔后整体会变暗,用它补** |
| Anisotropy | 0.40 | 轻微前向散射 |
| 锥体顶点数 | 64 | 体积域不需要高模 |
| 渲染成本 | 400×400 / 64 samples ≈ **1.6 s** | 体积域小,并不慢 |

## 验证要点

1. **可见性**:纯黑世界下,只有灯 vs 灯+锥,比**非零像素数**;
   再把锥体 `hide_render` 打开,应归零(反证亮度来自锥体)
2. **边缘软硬**:扫描线上取 **50% 与 10% 阈值之间的跨度**,越大越柔;不要靠肉眼
3. **轴对齐**:`axis_dot` 应 = 1.000000(锥轴与灯光轴平行)
4. **位置**:`apex_offset` 应 ≈ 0(锥尖落在灯位)
5. **材质共享**:`mat.users` 应等于锥体数量
6. **驱动器**:跨事件验证 —— 改属性 + `update_tag()`,**下一次独立执行**再读插槽
7. **可见性标志**:`visible_camera=True`,`visible_shadow/diffuse/glossy/transmission/volume_scatter/volume` 全 `False`
8. **远端收尾**:沿轴向取样(**正交侧视**最方便,整根入画),末端亮度必须**单调趋 0、无台阶**;
   若在几何末端仍有一级跳变 ⇒ 轴向渐变没到 0(见坑 #12)
