# 径向内收多脉冲材质（多环从外往内收 · 环数恒定）

> 适用于：**共心**的多个正交平面 / 球面上，要「若干个同心亮环**持续从外往内收**、无缝循环、
> 黑边很细」的发光效果。
> 与 [径向距离场脉冲](../skills/blender-radial-pulse-material/) 同族：**径向距离场**（只依赖到共享中心的距离 r）
> 是几何地基，本文只讲「**内收**」这一路独有的东西 —— 周期环带、相位推进、
> **环数恒定的约束解算**、亮面裁切、以及配色从姊妹材质复用。

---

## 1. 场景

三块**两两正交且共心**的平面（XY / XZ / YZ），要在一个共享圆心周围看到：

- **3 个同心亮环**同时存在（不多不少）
- 环**不断从外往内收**、到中心挤掉，外面又进来新的，**无缝循环**
- 环之间只有**很细的黑边**（约 10%）
- 发光**限制在一个圆内**，四个角不要多出环
- （可选）**出场**：从**全黑**开始 → 第一圈从圆心诞生往外扩 → 后续圈依次循环跟上 → 之后无缝循环（烟花灯，见 §2.8）

「共心」这件事**必须实测**（见 §2.1）：面积算出来的中心、三个面各自的包围盒中心、
以及控制器当前位置，三者要一致。

---

## 2. 做法

### 2.1 径向距离场：圆心 = 一个空物体

```python
tex = nt.nodes.new('ShaderNodeTexCoord')
tex.object = ctrl                       # ctrl = 位于共享中心、rot=0、scale=1 的空物体
mp  = nt.nodes.new('ShaderNodeMapping') # 恒等，留作「整体平移/缩放整个场」的钩子
ln  = nt.nodes.new('ShaderNodeVectorMath'); ln.operation = 'LENGTH'
links.new(tex.outputs['Object'], mp.inputs[0])
links.new(mp.outputs[0], ln.inputs[0])  # ln 输出 = r = |P − 圆心|
```

- `Object` 坐标 = **世界坐标相对该空物体** ⇒ 空物体在哪，圆心就在哪
- 多物体**全部指向同一个空物体** ⇒ 环天然同心、交线连续
- ⚠️ 空物体必须 **rot=0、scale=1**：带缩放会把 r 一起缩掉（环密度全变）

> **不要用 `ShaderNodeTexGradient(SPHERICAL)` 做径向** —— 它的有效半径恒为 1
> （源码 `fac = max(0.999999 − |v|, 0)`），做不了任意半径。

### 2.2 周期环带 + 相位推进（内收）

```
t = FRACT( r / 间距 + 相位 )        相位 = 帧号 ÷ 循环周期 + 相位偏移
band = 梯形剖面(t)                   = 上升沿 × 下降沿（见 §2.3）
```

**内收方向**：相位增大 ⇒ 亮带位置 `r = 间距 × (k − 相位)` **减小** ⇒ 往中心收。
`FRACT` 天然环绕 ⇒ **无缝循环**，不需要任何显式「重置」。

> 想做「向外扩」就把**循环周期设负值**（等价于相位递减）。

**时间参数用「循环周期（帧/圈）」而不是「速度（圈/帧）」**：
一个完整循环 = 图案整体向内移动一个「间距」，所以

```
循环周期（帧/圈） = 1 ÷ 每帧推进的周期数
```

前者直接填帧数（**帧数越小转得越快**），比让用户心算倒数直观得多。实现就是一句除法：

```python
div_ph = MATH('相位推进', 'DIVIDE')      # 帧号 ÷ 循环周期
links.new(v_frame.outputs[0], div_ph.inputs[0])
links.new(v_period.outputs[0], div_ph.inputs[1])
```

### 2.3 梯形脉冲剖面

`FRACT` 出来的是 0~1 锯齿，要变成「亮带 + 黑间隔」用**两个 Map Range 相乘**：

```
f_up = MapRange(t, [0, e/d] → [0, 1], clamp)          # 上升沿
f_dn = MapRange(t, [w/d − e/d, w/d] → [1, 0], clamp)  # 下降沿
band = f_up × f_dn                                     # 梯形，亮带宽度 = w/d
```

- `d` = 脉冲间距，`w` = 脉冲宽度，`e` = 边缘柔和（都是世界单位）
- **黑间隔 = d − w**；亮度在 `t ∈ (e/2d, w/d − e/2d)` 内为 1（阈值 0.5 判据）

⚠️ **`Map Range` 有两套同名不同类型的插槽（`VALUE` / `VECTOR`）** ⇒ 取插槽要按
`(name, type)` 或索引，按名字取会取错或报错。

### 2.4 ★ 环数恒定：有效窗口公式（本文最值钱的一节）

**目标**：任意相位下，**恰好** N 条亮环（不是"最多 N 条"）。

**推导**：把「亮带的可见区间」和「半径查询区间」求交。

```
可见带窗口 = L + 占空比 − 软边占比 − 2 × 最小可见宽度          必须 ≈ N
    L          = R_ref / 脉冲间距      （基准半径方向跨几个周期）
    占空比     = 脉冲宽度 / 脉冲间距
    软边占比   = 边缘柔和 / 脉冲间距
    最小可见宽度（占周期）—— 一条带至少多宽才算「看得见」
⇒ L = N − 余量 − 占空比 + 软边占比 + 2 × 最小可见宽度
```

三项**缺一不可**，每一项都是被实测打回来的：

| 少扣了哪一项 | 实测症状 |
|---|---|
| 只写 `L + 占空比 ≤ N` | 最多出现 **N+1** 条（宽占空比下首尾各多露一条） |
| 补了「− 软边」，没扣 `2×最小可见宽度` | 仍有约 **2%** 的相位只显示 **N−1** 条 |
| 全扣干净 | **N 条占比 ≥ 99.8%**，且永不出现 N+1 |

> **为什么减 2×最小可见宽度**：扫描/肉眼都要求一条带至少占 1% 周期才算「存在」，
> 区间两端各要留这么多 ⇒ 有效窗口被压缩 2×该值。

#### ★★ 基准半径 `R_ref` 必须问清「在哪条半径上数」

**同一个材质，换个基准就能从「3 条」变成「2 条」** —— 这是最容易返工的一处：

| 非圆网格（如正方形板） | 半径 |
|---|---|
| **内切圆**（用户说的"看圆"） | 半宽 = 2.0146 |
| **角点**（对角线） | 半宽 × √2 = 2.8491 |

**两者比值 √2 ≈ 1.414，几何上不可能处处一样多。** 按角点定 3 条 ⇒ 圆上只剩 1.55 个周期 ⇒ **只看到 2 条**（实测就是这个返工）。
**必须先问用户「在哪条半径上数环」**，再算间距。

### 2.5 亮面裁切：把发光限制在一个圆内

```
cut  = MapRange(r − 亮面半径, 0..淡出宽度, 1..0, clamp)
mask = 脉冲 × 外缘轻收 × cut        ← 发光和底色都取自裁切后的 mask
```

- `亮面半径` 默认 = 内切圆半径 ⇒ 四角落在裁切外 ⇒ **不再多出环**，圆外是纯黑
- 想恢复「铺满整个方板」：把它调到 ≥ 角点半径

> ⚠️ **「亮面面积缩小」≠「黑边变粗」** —— 这是两个**正交**的旋钮。
> 「限制发光范围」用裁切（本节）；「黑边粗细」用占空比（§2.3）。
> 混成一个（靠加宽黑边去"缩小亮面"）会得到「黑边更粗」的反效果。

### 2.6 控制面 = 空物体自定义属性 + 驱动（不写面板）

```python
ctl["循环周期"] = 50.0
ctl.id_properties_ui("循环周期").update(
    min=-2000.0, max=2000.0, soft_min=6.0, soft_max=400.0,
    description="黑→亮→黑 走完一个完整循环所需的帧数")

v = d.variables.new(); v.name = 'pd'; v.type = 'SINGLE_PROP'
t = v.targets[0]; t.id_type = 'OBJECT'; t.id = ctl; t.data_path = '["循环周期"]'
d.expression = 'pd'          # ★ 变量绑好【再】写表达式
```

- **中文键名就是 UI 显示名**（「物体属性 → 自定义属性」那张列表**无法本地化**，只认键名本身）
- 派生读数（如「可见脉冲数 = 角点半径 ÷ 脉冲间距」）用 **IDProperty 驱动**做只读自动跟随，
  description 写明「自动计算（只读）」—— 死数字会被误判成"逻辑没理顺"

### 2.7 配色复用：从姊妹材质读 ColorRamp（不是读 default_value）

要「和另一个材质同一套配色」时，**不能读那个材质的 `Emission Color.default_value`** ——
如果该插槽**是连线的**，`default_value` 只是个没用的残留存值（实测读到 `(1,1,1,1)`，
而真实配色是一条 ColorRamp 的 6 个色标，全丢了）。

**正解**：顺着连线找到真正的颜色来源节点，把它的**色标逐项复制**过来：

```python
def grab_ramp(src_mat, names, label_kw):
    for nm in names:                       # 先按节点名找
        n = src_mat.node_tree.nodes.get(nm)
        if n is not None and n.type == 'VALTORGB':
            return n
    for n in src_mat.node_tree.nodes:      # 再按中文 label 模糊找
        if n.type == 'VALTORGB' and label_kw and label_kw in (n.label or ""):
            return n

old = grab_ramp(bpy.data.materials["旧材质"], ("COL",), "色相")
STOPS = [(e.position, tuple(e.color)) for e in old.color_ramp.elements]   # 逐项搬
```

构建脚本每次跑都**实时读** ⇒ 以后在旧材质里微调颜色，重跑一次就同步，不会走样。
核验里再加一条**跨材质对拍**断言（新色标必须与旧材质逐项一致）。

> ⚠️ 色标是铺在 `r ∈ [0,1]` 上的（旧材质的网格半宽正好 1.0）。**新网格半宽不同时必须先归一化**
> `rn = r / 色相半径`（默认 = 网格半宽），否则超过 1 的部分全被钳到**最后一个色标**，
> 整个面会糊成一片暗红。

### 2.8 出场（黑场起步 + 逐圈跟上）

**用户要的**：「一开始全黑 → 第一圈从圆心诞生往外扩 → 第二/三圈依次循环跟上 → 之后永久循环」（烟花灯）。

**❌ 第一反应（错的）**：把 `亮面半径` 从小长到大 ⇒ **整体缩放**。实测被用户当场否掉（"你这个怎么是整体缩放的哦"）。

**为什么它必然是错的**：`FRACT(r/间距 + 相位)` 是**无限延伸的周期图案**，
任意相位下视野里恒有 2~3 条带 —— 它**根本没有"开始"**。改亮面半径只是给整幅图案套了个渐渐张开的光圈。

**量化归因**（一眼看出是缩放的原因）：

| 量 | 算法 | 实测值 |
|---|---|---|
| 环带外走速度 | 间距 ÷ \|循环周期\| | 0.0080 /帧 |
| 裁切边缘张开速度 | 亮面半径 ÷ 淡入帧数 | 0.0335 /帧 |

边缘比环**快 4.2 倍** ⇒ 视觉是"光圈张开"而不是"环从圆心冒出"。

**✅ 正解 —— 出生门**：给**环序号**设一道闸门，只乘在**掩码**上。

```
k    = 相位叠加 − 周期取模      (SUBTRACT)   ← k = floor(x) = 环序号（第几圈）
gate = (k < 0.5) ? 1 : 0        (LESS_THAN)  ← 只放行"已出生"的环
mask = 掩码裁切 × gate          (MULTIPLY)   ← ★ 门只乘掩码，不碰亮面半径
```

**推导**

```
x = r/间距 + 相位 ;  t = FRACT(x)   ⇒   k = x − t = floor(x) = 环序号
环 k 的亮区：r/间距 ∈ [k − 相位, k − 相位 + 占空比)
外扩 ⇒ 循环周期取负 ⇒ 相位递减 ⇒ 环 k 的左边缘 = (k − 相位) × 间距
左边缘降到 0 ⇒ 这一圈"在圆心诞生"，此刻宽度恰为 0 ⇒ 硬开也不跳变
"已出生" = 左边缘 ≤ 0 的环 ⇒ 判据 k ≤ 0 ⇒ Math 阈值取 0.5（k < 0.5）
每过 |循环周期| 帧相位少 1 ⇒ 从圆心多放出一条（逐圈跟上）
```

> ⚠️ **阈值必须 `0.5`，不能 `0`**：`LESS_THAN` 是**严格小于**。
> 填 0 会把"左边缘恰为 0、宽度恰为 0 的这一条"判成不放行 ⇒ 第一圈**晚一帧**出现。

**「开头全黑」怎么定**：全黑 ⟺ 当前相位 ≥ 占空比（所有带左边缘都 > 0）。
出场相位递减 ⇒ 第一帧最大 ⇒ 取

```
相位偏移 = 占空比 + 1/|循环周期|        （再 % 1）
```

实测：占空比 0.9399、周期 −50 ⇒ 相位偏移 = 0.9399 + 0.02 = **0.9599** ⇒ f=1 纯黑。
（`+1/|周期|` 留一格，让"第一圈从圆心冒出"发生在**第二帧**而不是第 0 帧。）

**三条硬约束**

1. **门只乘掩码，绝不碰 `亮面半径`** —— 碰了就是整体缩放（§2.5 的正交拆分在这条路上是承重的）
2. **阈值填 `0.5`**（等价 `k ≤ 0`），别填 0
3. **`循环周期` 取负**（外扩）+ 相位偏移按上式算 —— 两者一起才是"黑场起步"

**验证交付**：逐帧自检 `第 1 帧 0 条 → 单调不减 → 稳态恒 3 条`，
且**亮面半径逐帧恒定**（这就是"没有缩放"的机器可判据）。
脚本 [`../scripts/radial-inward-pulse/set_firework_birth_gate.py`](../scripts/radial-inward-pulse/set_firework_birth_gate.py)
（幂等加门 + 自动算相位偏移）+ [`verify_firework_birth_gate.py`](../scripts/radial-inward-pulse/verify_firework_birth_gate.py)（另起请求独立核验）。

**实测（参考工程，Blender 5.2.2 LTS）**：节点 39→**42**、连线 49→**53**（+3 节点 / +4 连线）、**驱动仍 11 条**；
逐帧相位 +0.9399（f=1 全黑）→ −0.0001（f=48 第一圈铺满）→ −0.5001（f=73 第二圈从圆心冒出）→ −2.0001（f=148 三圈）→ 稳态；
**亮面半径逐帧恒 0.8378**。

## 3. 坑（全部本机实测）

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | **基准半径选错** | 圆上只有 2 条环 | 先问清「在哪条半径上数环」，用 `R_ref`（§2.4） |
| 2 | **有效窗口公式漏项** | 多一条 / 少一条，且随相位跳变 | 软边、最小可见宽度都要扣（§2.4） |
| 3 | **驱动挂在「计算节点」的输出插槽上** | 拖时间轴画面**完全静止** | 驱动只能挂 **Value 节点输出**（或节点输入 socket）；挂 Math/MapRange 的输出会被节点运算覆盖 = 没写 |
| 4 | **读别人颜色读 `default_value`** | 复制过来的颜色是白色 / 完全不对 | 插槽若已连线，`default_value` 是残留值 ⇒ 顺连线找真正的来源节点（§2.7） |
| 5 | **改自定义属性不 tag 不重算** | 脚本里改完读回是旧值 | `ctl.update_tag()` + `view_layer.update()`（UI 拖动那条另论，见姊妹 skill） |
| 6 | **`driver_add()` 自动把表达式填成常量** | 改属性纹丝不动 | 装完必须**覆盖** `d.expression` |
| 7 | **`__file__` 在桥 exec 里不存在** | 构建脚本找不到同目录附件 → `NameError` | 附件路径写**绝对常量**，或把源码内联 |
| 8 | **「亮面面积」与「黑边粗细」混成一个旋钮** | 想缩小亮面却把黑边加粗了 | 范围用裁切、粗细用占空比，两个正交（§2.5） |
| 9 | **`animation_data.drivers` 的元素是 `FCurve`** | `AttributeError: 'FCurve' object has no attribute 'variables'` | 变量走 `d.driver.variables`、表达式走 `d.driver.expression` |
| 10 | **VectorMath 节点类型是 `'VECT_MATH'`** | 断言恒失败，误判"节点建错" | 不是 `'VECTOR_MATH'` |
| 11 | **ColorRamp 输入插槽 `name='Factor'` / `identifier='Fac'`** | 用 `'Fac'` 匹配 `to_socket.name` → 连线断言漏报 | 断言用 `name`，连线用索引 |
| 12 | **对象总数会掩盖构成变化** | 新增 1 个 EMPTY + 少 1 个 MESH ⇒ 总数不变 | 核验**按 `ob.type` 分类计数** |
| 13 | **已连线的「计算输出」插槽读不到真值** | Python 读中间节点恒为 0，误判"没生效" | 只有被**关键帧/驱动器直接写入**的插槽才有可读值；核验改成「验基准 + 验驱动输入 + 解析式复算」 |
| 14 | **想要「黑场起步、逐圈扩散」却去改亮面半径** | 变成**整体缩放**，边缘比环快 4.2 倍 ⇒ 一眼看穿 | 改用**出生门**：门只乘掩码（§2.8） |
| 15 | **出生门阈值填 0** | 宽度为 0 的首圈被判掉、**晚一帧**才出现 | 填 **0.5**（`LESS_THAN` 严格小于 ⇒ 等价 `k ≤ 0`） |
| 16 | **设了负周期（外扩）却没调相位偏移** | "一开始就在循环"，用户会说"没有开始了" | 相位偏移 = 占空比 + 1/\|循环周期\|（§2.8） |
| 17 | **`Math` 节点三输入同名 `Value` 按名字聚集上游** | 环序号 `k` 会聚到多个来源 / 核验判据误报 | 用 `set(上游) == {...}` 而非排序比较；`k` 只能 `= 相位叠加 − 周期取模` |
