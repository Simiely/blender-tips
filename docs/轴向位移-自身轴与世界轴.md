# 位移坐标系:让物体沿【自身轴】或【世界轴】运动

> 场景:**物体的轴向跟世界轴不一致**(被转过的父级下、或物体自己带旋转),
> 想让位移按"自己的轴"走 / 按"世界轴"走,但 K 出来的 `location` 两个都不是。

配套脚本包: [`scripts/axis-space-motion/`](../scripts/axis-space-motion/)(诊断 + 写入 + 验证)

---

## 1. 为什么会"哪个都不是"

Blender 的对象局部矩阵是:

```
matrix_basis = T(location) @ R(rotation) @ S(scale)      ← 平移 T 在最左端
matrix_world = parent.matrix_world @ matrix_parent_inverse @ matrix_basis
```

`T` 在最左端 ⇒ 一个点先被旋转/缩放,最后才被 `T` 平移 ⇒
**`location` 的坐标系 = `parent.matrix_world @ matrix_parent_inverse`**(本文称**父空间基底**),
和对象自身怎么转**没有关系**。

三条推论(都经隔离实验实测):

1. `location` **不是**世界空间 —— 父级被转过就跟着歪。
2. `location` **不是**自身空间 —— 对象自己怎么转都不影响位移方向。
3. **`delta_location` 与 `location` 同一坐标系**,`delta_rotation` 也不会把 `location` 带转。

实测(父级固定绕 X 转 90°,子级位移 5 单位,量"世界位移方向 vs 自身 Z 的夹角"):

| 做法 | 与自身Z 夹角 | 判定 |
|---|---|---|
| 子级**无**旋转,K `location[2]` | 0.0000° | ✅ 父空间 == 自身空间 |
| 子级**自转 90°**,K `location[2]` | **90.0000°** | ❌ 沿父级轴 |
| 子级自转 90°,K **`delta_location[2]`** | **90.0000°** | ❌ 同一坐标系 |
| 子级 `delta_rotation` = 90°,K `location[2]` | **90.0000°** | ❌ 不受影响 |

> "用 delta 做局部位移"是高频误解 —— 实测它不是。

## 2. 统一心法

> **想让位移沿哪个坐标系,就把"承载位移那一层"的父空间做成那个坐标系。**

于是两条路完全对称,**都只需要 K `location`,不做任何换算**:

| 想要 | 结构做法 | 本质 |
|---|---|---|
| 沿**自身轴** | **朝向放在位移层上面**;承载位移的那一层自身旋转 = 0 | 父空间 == 自身空间 |
| 沿**世界轴** | 承载位移的那一层上面**插一层"抵消旋转"的空对象** | 父空间 == 世界空间 |

不改变结构时的兜底: **按公式换算后 K 三通道**(静态) 或 **逐帧 bake**(动态),
或干脆用 **世界空间约束**(最通用)。

## 3. 想让它按【自己轴】运动

### 做法 A(推荐):朝向层 / 位移层分开

```
父级
└── <对象>_朝向      ← 要旋转就放这一层,location 保持 0,不要 K
    └── <对象>_位移  ← 自身旋转恒 0;K location[2] 就是沿它自己的 Z
        └── 目标
```

**为什么精确**: 位移层的 `matrix_basis = T(loc) @ I @ I`,而它的父空间就是朝向层 ⇒
`location[2]` 落在朝向层自己的 Z 轴上,也就是位移层自己的 Z 轴上。

**上层旋转是动画也成立**: `matrix = 父 @ R_朝向(t) @ T(loc)`,每一帧位移都落在"当时"的旋转帧里。
实测(上层绕 X 从 0° 动画到 90°,下层 K `location[2]` 0→5):

| 帧 | \|B−A\| | 位移方向 vs 当时自身Z |
|---|---|---|
| 5 | 1.05263 | **0.000000°** ✅ |
| 10 | 2.36842 | **0.000000°** ✅ |
| 15 | 3.68421 | **0.000000°** ✅ |
| 20 | 5.00000 | **0.000000°** ✅ |

### 做法 B:不新增对象,按公式换算

只有一个对象、且它自己的朝向**是静态的**时,可以直接把位移换算到父空间:

```python
loc = d * (R_own @ AXIS)      # R_own = obj.matrix_basis.to_3x3()（含 delta）
```

`R_own = I` 时退化成 `loc = (0, 0, d)`。实测误差 **0.0000°**。

代价:数值"斜"、不可读;朝向一改就得重算;朝向是动画时必须逐帧 bake。

### 做法 C:打算用"一个数值 = 一段距离"控制

用 driver 单通道:自定义属性 `d` → 驱动 `location[0..2]`。

> ⚠️ 表达式里**不能直接写自定义属性名**(报 `NameError: name 'd' is not defined` /
> `BPY_driver_exec: restricted access disallows name 'd'`,实测**即使打开
> `preferences.filepaths.use_scripts_auto_execute=True` 也没救**)。
> 必须声明**驱动变量** `type='SINGLE_PROP'`、`data_path='["d"]'`,表达式只引用变量名。
> 另外:测 driver 值要把自定义属性**K 成动画再逐帧取**,直接改属性 + `view_layer.update()`
> 在后台模式不会触发驱动重算(会得到 Δ=0 的假象)。

## 4. 想让它按【世界轴】运动

### 做法 A:按公式换算 + K(E 引擎自动选 direct / bake)

```python
loc = d * (P_basis_rot⁻¹ @ AXIS)     # P_basis_rot = (parent.matrix_world @ MPI).to_3x3()
```

* 父级朝向**恒定** → 换算一次,K 到各关键帧即可(实测 **0.000000 单位**)。
* 父级朝向**是动画** → 两关键帧之间只做直线插值会走偏(实测偏 **7.07 单位**)
  ⇒ 必须**逐帧 bake**(实测 **0.000000**)。

### 做法 B(最通用):世界空间控制空对象 + `Copy Location`

勾选 `use_offset` 保留对象原有的基准位置,位移由**世界空间**的动画决定:

```python
ctrl = 新建空对象（无父级 = 世界空间）;  ctrl 上 K 好沿世界轴的动画
con = obj.constraints.new('COPY_LOCATION')
con.target = ctrl
con.owner_space  = 'WORLD'
con.target_space = 'WORLD'
con.use_offset   = True          # 在"对象自己原本的位置"上叠加
```

**父级怎么转都精确**:实测单轴动画父级 **0.000000**、
绕 X + 绕 Z 复合动画父级 **0.000000**。不需要换算,也不需要 bake。

### 做法 C:中间插一层"抵消旋转"的空对象

```
父级(带旋转)
└── <对象>_世界对齐   ← 自身旋转 = 父级世界旋转的逆 ⇒ 它自己的坐标系就是世界坐标系
    └── <对象>_位移   ← 自身旋转 0;K location[2] 就是沿世界 Z
        └── 目标
```

* 父级朝向**静态**: 手动填抵消角(父级绕 X 转 90° → 这层填 −90°),实测 **0.000000** ✅
* 父级朝向**是动画·单轴**: 给这层挂 `Copy Rotation`
  (`target=父级`, `owner_space='LOCAL'`, `target_space='WORLD'`, `invert_x/y/z=True`),
  实测 **0.000000** ✅
* 父级朝向**是动画·复合旋转**: ❌ **不成立**(实测偏 3.83 单位 / 45°) ——
  因为 `Copy Rotation` 的 invert 是**逐分量取反**,不等于矩阵求逆(只有单轴时两者才等价)
  ⇒ 这种情形改用做法 A(bake)或做法 B(约束)。

> `Copy Rotation` 的 `owner_space` 只有 `WORLD` / `CUSTOM` / `LOCAL` 三种(没有 `LOCAL_WITH_PARENT`)。
> 实测只有 `LOCAL` 那一档能起到"抵消父级旋转"的作用,`WORLD` 与 `CUSTOM` 都不起作用(仍偏 90°)。

## 5. 视口里手动操作(不写脚本)

* **要沿自身轴拖** : 顶部 Transform Orientation 选 **Local**(或按 `Alt+Space` → Local),
  再 `G` `Z` `Z`(连按两次 Z 切到本地轴)。
* **要沿世界轴拖**: Transform Orientation 选 **Global**。

> ⚠️ 但要注意: 视口里怎么拖都只是"算出当时的父空间分量写进 `location`"。
> **两个关键帧之间永远是父空间直线插值** —— 父级或对象自身朝向是动画时,
> 中间帧一定偏离你想走的轴(实测偏 7.07 单位)。
> 想全程严格沿轴 ⇒ 用 `bake`,或用第 4 节做法 B 的约束。

另外注意: **在视口里拖出来的方向和"K 下来的数值"不是一回事**。
数值永远是父空间分量,想读懂它得先做第 6 节的诊断。

## 6. 先诊断:"K location[2] 现在会往哪走"

```
python send.py scripts/axis-space-motion/axis_report.py      # 改 TARGET
```

它打印: 父空间基底各轴在世界中的方向 / 对象自身轴在世界中的方向 / 三项夹角 / 坐标基底是否随时间变,
并直接给建议。真实项目实测示例(`相机基点`):

```
父空间基底（= K location 所在的坐标系）:
  f= 151  Z→世=(-0.8234,-0.5310,-0.1999)
  f= 480  Z→世=(-0.8474,+0.4929,-0.1973)
--- 判据（K location[2] 实际会往哪走）---
K location[2] 方向 vs 对象自身Z :   0.0000 度   ← 一致，就是「沿自身轴」
K location[2] 方向 vs 世界Z    : 101.5303 度   ← 不是世界轴
对象自身Z轴 vs 世界Z           : 101.5303 度   （"轴向与世界轴不一致"的偏角）
父空间基底朝向随时间变化(采样内最大) : 149.1429 度   （随时间变 → 世界轴方案必须 bake 或约束）
```

**两条读法**:

* "K location[2] vs 自身Z = 0.0000 度" ⇒ 现状已经满足"沿自身轴",**直接 K 就行,不用改结构**。
  (该对象自身旋转为 0 ⇒ 自身轴与父空间轴重合,所以天然成立。)
* "父空间基底朝向随时间变化 ≠ 0" ⇒ 世界轴方案一律要 bake 或约束,**不能用 direct**。

## 7. 验收:怎么量才不出错

用配套的 `verify_axis_motion.py`(必须**另开一次请求**跑,避开同 exec 缓存),它静音 `location` 曲线
先采一遍基准轨迹,再采实际轨迹,输出三项:

| 指标 | 通过阈值(坐标量级 ~25) | 正常实测 |
|---|---|---|
| ① 位置 vs 理想轨迹 | ≤ 1e-4 单位 | ~1e-5(float32 精度) |
| ② 沿轴投影 vs 期望距离 | ≤ 1e-4 单位 | ~1e-5 |
| ③ **垂轴分量** | ≤ 1e-4 单位 | ~1e-5(相对 < 0.001%) |

### ⚠️ 不要用"逐帧步进方向 vs 轴方向"来验收

目标轴随时间旋转时(例如"沿自身轴"而自身轴在公转),**位移向量本身就在转**,
再加上基准轨迹也在动 —— 这个指标**必然误报**。实测: 实际偏差只有 8.1e-06 单位的情况下,
该指标报出 **112° / 163.86°** 的假失败。

正确量是 **③ 垂轴分量**(位移向量分解成 沿轴分量 + 垂轴分量,垂轴必须 ≈ 0),
或等价的"位置 vs 理想轨迹"。

## 9. 坑(逐条)

1. **`location` 不听对象自身旋转**:想沿自身轴 ⇒ 让承载位移的那层自身旋转为 0,或按公式换算。
2. **`delta_location` 不是"局部位移"**:与 `location` 同一坐标系(实测偏 90°)。
3. **`delta_rotation` 不改变 `location` 的方向**(实测偏 90°)。
4. **坐标基底是动画时不能只 K 两端**:直线插值会走偏(实测 7.07 单位) ⇒ bake 或约束。
5. **`Copy Rotation` 没有 `LOCAL_WITH_PARENT`**:只有 `WORLD`/`CUSTOM`/`LOCAL`;
   抵消父级旋转要用 `owner_space='LOCAL'` + `target_space='WORLD'`(`WORLD`/`CUSTOM` 实测无效)。
6. **`Copy Rotation` 逐分量取反 ≠ 矩阵求逆**:单轴成立,复合旋转不成立(实测偏 3.83 单位)。
7. **存 `matrix_world` 必须 `.copy()`**:`evaluated_get(dg).matrix_world` 是活引用,
   不拷贝存进列表,循环结束后**全部变成最后一帧的值**(实测三帧采样全打印末帧值,
   导致诊断输出"自身Z vs 世界Z = 0.0000°"的假结论)。`to_3x3()`/`to_translation()` 天然安全。
8. **验收别用"逐帧步进方向"**(见 §7,实测虚报 112°/163.86°)。
9. **driver 表达式不能直接写自定义属性名**,必须走驱动变量(见 §3 做法 C)。
10. **同一次 exec 内"改完立即验证"读到未刷新值** ⇒ 验证分两次请求。
11. **世界轴方案在"父级也在动"时,"世界轴位移"的语义是"在原有运动之上叠加世界方向偏移"**,
    不是"世界坐标绝对直线";要绝对直线(对象在世界里走直线)是另一个需求,
    需要把基准轨迹也一起解出来 —— 本包按"叠加"语义实现,验证脚本也按此判读。

## 10. 真实用法示例

`旋转对象`(绕 Z 匀速转) → `转移对象`(相机原动态) → `相机基点`(全零,位移层) → `摄像机x02`

* 让相机**沿自身 Z(视线轴)推拉** ⇒ `SPACE="SELF"`, `AXIS=(0,0,1)`, 直接 K `相机基点.location[2]`。
  诊断显示该对象"K location[2] vs 自身Z = 0.0000 度",天然成立,不用改结构。
* 让相机**沿世界上下方向升降** ⇒ `SPACE="WORLD"`, `AXIS=(0,0,1)`;
  父空间基底随时间变(诊断报 149°),脚本自动 bake。
* 以后若给 `相机基点` 加了自己的朝向旋转 ⇒ 那时"沿自身轴"需要**再加一层**
  (`相机基点` 承载朝向、新层承载位移),否则 `location` 会回到父空间轴。
