# 分体翻页牌驱动翻页系统(Split-flap)

> 适用: Blender 5.2 LTS(机制对所有版本通用)
> 依据: 本次实战(报刊亭翻页牌 `翻页字牌.blend`,**35 张卡 / 两张牌子 / 上下两排**)+
> 官方手册 Drivers / Frame Change Handlers 章节(2026-10-03 核对)

## 场景

一个翻页牌模型,每张卡是独立的长方体网格(8cm 宽 × 12cm 高 × 1cm 厚),**轴心在卡的左下角**,
原本全部挂在牌子 Empty 下面,没有任何动画。需求:

1. **整块牌波浪式翻页**(不是一两张在动),要有"啪嗒啪嗒"的密度感
2. 翻完**必须回到初始朝向**——停在半途/翻过去就看不到卡面上的字了
3. 最好能实时拖时间轴看效果,参数好调

**目标**: 每张卡绕自己的**中缝水平轴**旋转整数圈,各卡之间用相位错开形成斜向波浪。

## 原理: 三件事决定成败

### 1. 轴心不在中缝 → 新建 Empty 当中缝轴

卡片轴心在左下角,直接转就是绕角上转(像门甩出去),不是翻页。正确做法是给每张卡新建一个
根级 Empty 放在**卡的几何中心**(即"中缝"位置),把卡挂到它下面,再转这个 Empty。

```
card.matrix_world = pivot.matrix_world @ card.matrix_parent_inverse @ card.matrix_basis
```

保持卡片世界位置不变,**只补偿一次**:

```python
pivot.location = center                       # 根级对象: 世界变换 == T(center)
card.parent = pivot
card.matrix_parent_inverse = T(center).inverted()   # ① 唯一的补偿
card.matrix_basis = mw                              # ② 原世界矩阵,原样保留
```

> ⚠️ **别补偿两次**。若 ① 和 ② 都乘 `T⁻¹`,净效果变成 `T(-center) @ orig`,
> 卡片会被平移到世界原点附近(实测踩过:bbox 从 `-57.9783` 变成 `±0.005`)。

### 2. 转整数圈才会回到初始朝向

| 总转角 | 结束姿态 | 字看得见吗 |
|---|---|---|
| 180°(半圈) | 翻过去,背面朝外 | ✗ 看不到 |
| 360° × N(整圈) | **与初始完全一致** | ✓ |

所以角度从 **0 → 1080°(3 圈)**,静止时停在 1080° ≡ 0°,卡面朝外、文字可见。
写成 `360 * flip_turns`,想转几圈改一个数就行。

### 3. 波浪靠相位,不靠手 K 帧

```
delay = ((列号 + 行号) % 8) × 2 帧
```

同一对角线的卡同时翻,形成斜向波浪级联。列/行由卡片**世界坐标**的 Y/Z 排序得出
(不依赖命名,导入模型也适用)。改 `% 8` 或步长就换一种波浪形态。

## 做法

1. 跑 `scripts/flip-card/attach_flip_axes.py`(经 9877 桥发送):自动识别卡片 → 批量建轴 →
   挂接 → 写相位 → 装驱动 → 注册帧处理器。**内置改前快照 / 改后核验**,位置有偏移会直接报 FAIL
2. 拖时间轴看效果;改参数跑 `retune_flip.py`(圈数 / 翻页时长 / 周期 / 波浪步长)
3. **保存前**跑 `reset_flip_rest.py` 停到静止帧并归零(见坑 3)
4. 不想要了跑 `detach_flip_axes.py`,卡片回到原始层级与世界位置

### 参数一览(本次实测值)

| 参数 | 值 | 说明 |
|---|---|---|
| `flip_turns` | 3 | 总转角 = 360×3 = 1080°,结束回到初始 |
| `flip_dur` | 16 帧 | 单次翻页时长(24fps 下 0.67s) |
| `flip_period` | 60 帧 | 每张卡每 2.5 秒翻一次 |
| `flip_delay` | 0~14 | 斜向相位,`((列+行)%8)×2` |
| `flip_axis` | 1 | 本地 Y(根级无旋转 ⇒ 等于世界 Y,沿牌宽) |
| 卡片数 | 35 | 同时约 9~10 张在翻 |

### 缓动: 用 smoothstep,别用二次

```
v = total * (3u² - 2u³),  u = t / dur
```

二次曲线(越转越快)会在到位那一刻**急停**,很假;smoothstep 是慢起 → 加速 → 减速停住,接近真实机械惯性。

## 坑(实测踩过,按严重度排序)

### ★ 1. 非受信任打开的 .blend 里,SCRIPTED 驱动**静默不求值**

这是本次最大的坑,排查掉了两个小时。表现:驱动挂好了、表达式没错,但推帧时
**角度纹丝不动、bbox 不变、也不报错**。

- 根因:`bpy.context.preferences.filepaths.use_scripts_auto_execute = False`
  (属性名不是 `use_auto_scripts`)
- **运行时把这个偏好临时开成 True 也救不活** —— 受信任标记是在**文件加载那一刻**确定的
  (已实证)
- 两条出路:
  - **本次会话实时看效果** → 用 `bpy.app.handlers.frame_change_post` 处理器按公式写
    `rotation_euler`(运行时注册,不受文件信任限制)
  - **长期** → 以受信任方式重开文件(`Reload Trusted`),让真正的驱动接管
- 判活方法: 驱动只写 **evaluated** 数据,必须读
  `obj.evaluated_get(bpy.context.evaluated_depsgraph_get()).matrix_world`,
  直接读 `obj.matrix_world` 永远是 0

### ★ 2. 驱动表达式必须返回**弧度** —— 写成度数会让卡片全歪

`rotation_euler` 的单位是弧度。表达式里写 `1080.0`,Blender 当成 **1080 弧度**存进去
(= 61879°),于是每张卡都歪成随机角度。实测 35 个轴全部残留 `61879.44°`,卡片 bbox
从 `0.01/0.08/0.12` 变成 `0.0856/0.08/0.0977`。

正确写法(驱动命名空间里有 `radians`,实测可用):

```
(radians(1080.0) * (3*(((fc - dl) % 60) / 16) ** 2 - 2*(((fc - dl) % 60) / 16) ** 3))
if (((fc - dl) % 60) < 16) else radians(1080.0)
```

> 拼字符串时用 `%` 格式化要写 `%%`,用 `.format()` 写 `%` —— 混用会把 `%%` 原样留在
> 表达式里变成语法错误(实测踩过,且因为驱动被信任机制挡着,错误不会暴露)。

### ★ 3. 处理器不随文件保存 —— 存盘会冻结在"当时那一帧"

`bpy.app.handlers` 是**运行时**注册,不会写进 .blend。保存时各轴的 `rotation_euler`
是多少,文件里就是多少;重开后没有处理器、驱动又被信任机制挡着 ⇒ **卡片僵在半翻姿态**。

对策(任选):
- 保存前先停到**静止帧**(所有卡都翻完的帧,如 `frame 40`:`(40 - 0..14) % 60` 均 ≥ 16)
- 或跑 `reset_flip_rest.py` 把角度全部归零再存
- 或**烘焙成关键帧**(重开不依赖信任,最省心)

### 4. keep-transform 只能补偿一次(见"原理"第 1 节)

### 5. 新建 / 刚换父级的对象,别回读 `matrix_world`

新建对象后立刻读 `matrix_world` 可能拿到 **basis 或过期值**(本次实测:根级轴 location 已设为
`(-57.97, -16.17, 2.22)`,读回来却是 `(-0.005, 0.445, 0.445)`)。
对策:根级轴的世界变换用 `Matrix.Translation(center)` **解析构造**,不回读;
只有场景加载后**从未动过**的对象读 `matrix_world` 才可信。

### 6. 驱动变量命名避开内置名 `frame`

官方手册明确警告"覆盖驱动命名空间的内置条目可能导致未定义行为"。变量名用 `fc` / `dl` 之类:

```python
var.name = "fc"; var.type = 'SINGLE_PROP'
var.targets[0].id_type = 'SCENE'; var.targets[0].id = scene
var.targets[0].data_path = "frame_current"
```

### 7. 删驱动用 `fc.data_path`,不是 `fc.driver.data_path`

`anim_data.driver_remove(fc.data_path, fc.array_index)` —— `data_path` 在 **FCurve** 上,
`.driver` 上没有这个属性(报 `AttributeError`)。

### ★ 9. 挂总控时:**先 `parent`,再设补偿**,顺序反了整组飞

把轴群收进一个总控 Empty 时,写成了

```python
p.matrix_parent_inverse = T.inverted()   # ✗ 先设补偿
p.parent = master                        # ✗ 后赋 parent → 补偿被重置成单位矩阵
```

结果整组多叠了一个 `+总控位置` 的位移,实测 35 张卡全部平移 `(-59.44, -15.90, +2.08)`。
**正确顺序**:

```python
p.parent = master                        # ① 先挂
p.matrix_parent_inverse = T.inverted()   # ② 再补偿(此时才不会被重置)
```

### 8. 相位取模会"隔 N 列同步"

`% 8` 意味着第 0 列和第 8 列同时翻(波浪呈周期性条带)。这是想要的效果;
若想让整块板单一扫过,去掉取模改成 `(列 + 行) * 步长`(注意总延迟要小于 `flip_period`)。

## 整体搬运: 收进一个总控 Empty(`group_under_master.py`)

35 个轴散在场景根下不好管理,也不方便复用到别的工程。收口做法:

1. 新建总控 Empty(放在**轴群几何中心**,`rotation` 保持 0 —— 否则轴的本地 Y 不再等于世界 Y,翻页轴会歪)
2. 全部轴挂到它下面(**先 parent 后设补偿**,见坑 9)
3. 把 `总控 + 轴 + 卡片` 一并收进**单一集合**

收益:
- **移动/旋转总控 = 整组翻页效果整体搬运**(实测移动 `(+3,-1,+2)`,35 张卡同量跟随、还原后逐张一致)
- 其他工程 `File > Append` 该集合即可复用(注意:处理器不随文件走,见坑 3)

核验判据: 静止帧下 35 张卡全部竖直 + **每张卡的中心严格等于其轴的世界位置**(链完整性最强判据)。

## 脚本清单(`scripts/flip-card/`)

| 脚本 | 作用 |
|---|---|
| `attach_flip_axes.py` | **主脚本**:识别卡片 → 批量建轴 → 挂接 → 写相位 → 装驱动 → 注册处理器;改前快照 + 改后核验 |
| `retune_flip.py` | 改圈数 / 翻页时长 / 周期 / 波浪步长,驱动与处理器同步 |
| `reset_flip_rest.py` | 角度归零 + 跳到静止帧(存盘前必跑) |
| `detach_flip_axes.py` | **撤销**:卡片脱离轴、回到世界原位,删除 `FLIP_pivots` 集合 |
| `probe_flip.py` | 诊断:残留角度、卡片姿态(bbox 尺寸)、处理器/驱动状态 |
| `group_under_master.py` | 把所有轴收进**总控 Empty** + 单一集合,便于整体移动/复制到其他工程;内置零位移核验与整体跟随实测 |
