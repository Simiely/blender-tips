# 空间雷达扫描材质（Y 轴投射 · 极坐标角度扫掠 + 拖尾）

> 适用于：把一份 **Canvas/HTML 雷达扫描动画**（扫描头绕圈转 + 拖尾扇面 + 同心圆网格 + 中心亮点）
> 复刻成 Blender 的**空间材质**（**不用 UV**），贴到一个网格体上，
> 且**沿某个世界轴投射**（图案沿该轴无变化 —— 平移物体，正交侧视下画面逐像素不变）。
> 与 [径向距离场脉冲](../skills/blender-radial-pulse-material/) 同族：
> 都只用"两个世界分量"构成的平面坐标，这条路的独有部分是
> **角度场（atan2）而非距离场**、**多扫描头的相位解算**、以及**方向进哪一项**这个承重的数学选择。

---

## 1. 场景

一块**法线朝 −Y** 的平面（实测世界中心 `(0.03, 0.14, −1.66)`、面内半宽 X=Z≈1.77），
要出现和参考动画一样的效果：

- **扫描头**绕中心匀速转（`110°/s`），可**正/反向**
- **5 条**同时存在、每条带 **129° 拖尾**（越靠尾部越暗），扇面互相重叠成漩涡
- 同心圆**网格**（4 环）+ **中心亮点**，发光限制在内切圆内（四角纯黑）
- 沿**世界 Y 轴投射**：图案与 Y 无关

> **为什么强调"不是 UV"**：UV 贴图会把图案**跟着网格走**（平面拉伸、复制、旋转都会变形）；
> 空间材质用 `纹理坐标.Object` 锚到一个空物体，图案由**空间位置**决定 ⇒
> 平面如何变形、被平移到哪里都不影响"看起来在哪里"。

---

## 2. 做法

### 2.1 锚点：控制空物体 = 坐标系原点 + 参数载体

```python
ctl = bpy.data.objects.get("雷达控制") or 新建 EMPTY
ctl.location = 平面世界中心      # ★ 锚点放在目标中心 ⇒ Object 坐标 = 相对中心的坐标
ctl.rotation_euler = (0, 0, 0); ctl.scale = (1, 1, 1)   # 必须清零（见 §3 坑 1）
tex.object = ctl                # 纹理坐标(Object) 指向它
```

同一个空物体同时是**参数载体**：12 个中文键自定义属性（带 `min`/`max` 才是滑块）
⇒ 一处改、材质节点上的 13 条 `SINGLE_PROP` 驱动一起变。

### 2.2 节点管线（极坐标角度场 → 多扫描条相位 → 掩码合成 → 输出）

```
纹理坐标(Object=雷达控制) → 分离XYZ
u  = ( atan2(世界Z, 世界X) + π ) / 2π      ← ★ 只吃 X/Z，Y 悬空 ⇒ 沿 Y 投射
时刻 = frame / fps × 扫描速度 / 360        ← Value 节点输出 + 驱动
有向条数 = 扫描条数 × 扫描方向              ← 两个输入都驱动
D  = FLOORED_MODULO( 时刻×条数 − u×有向条数, 1.0 )   ← ★ 方向只进角项（§2.4）
拖尾项 = MapRange(D, 0 .. 条数×拖尾/360 → 1..0) ^ 拖尾曲率
头部线 = MapRange( min(D, 1−D), 0 .. 头部线宽 → 1..0 )
中心点 = MapRange( length((X,0,Z)), 0 .. 中心点半径 → 1..0 )
网格   = MapRange( frac(r ÷ (亮面半径/环数)), 0 .. 0.05 → 1..0 ) × 网格亮度
掩码 = min(拖尾+头部线+中心点+网格, 1) × 亮面裁切(r − 亮面半径, 0..淡出宽度 → 1..0)
掩码 × 发光强度 → Emission Strength ; RGB(白) → Emission Color ; Base Color=黑
```

**「Y 投射」的全部实现就是：`分离XYZ` 的 `Y` 输出悬空不接。**
只连 `X` 与 `Z` ⇒ 图案只依赖世界 X/Z ⇒ 沿 Y 无变化。

**半径要用 `CombineXYZ` 把 Y 填 0** 再 `VectorMath(LENGTH)` ⇒ `r = √(X²+Z²)`；
直接对 Object 坐标取长度会带上 Y 分量（平面在 Y 上有跨度时半径就错了）。

### 2.3 ★★ 方向必须只进「角项」，不能进「时间项」

需求是"方向旋钮拨一下，扫描头朝相反方向走"。**首轮实现按直觉写成**

```
错法： D = frac( 方向 × 条数 × (时刻 − u) )
```

结果：**方向拨到 −1 时扫描头仍朝同一方向走，只有拖尾换了边**（被核验抓到的真实 bug）。

**为什么错**：`frac(−x)` 与 `frac(x)` 的值域只差一个补数 ——
把 `t → 1−t` 一换可验证两者**头位置集合完全相同**。方向只作用于"尾部在哪边"，
**没有参与决定头往哪走**。

**正解**

```
正解： D = frac( 条数×时刻 − 方向×条数×u )
      ∂D/∂u = −方向×条数  ⇒  D=0 的头位置 u = 方向×时刻
      ⇒ 方向 = ±1 真正决定 u 的推进方向
```

推导：把头位置定义为 `D = 0` 的解。

```
条数×时刻 − 方向×条数×u ≡ 0  (mod 1)
⇒ u = 方向×时刻  (mod 1/条数)
      方向=+1 ⇒ u 递增（从法线正面看逆时针）
      方向=−1 ⇒ u 递减（顺时针）
```

**落地三条硬约束**

1. **时间项 = `时刻 × 扫描条数`（不含方向）**；**角项 = `u × (方向 × 扫描条数)`**。
2. `有向条数` 节点两个输入都挂驱动：`inputs[0] ← 扫描条数`、`inputs[1] ← 扫描方向`。
3. **「有向条数 → 时间项」这条线不能连** —— 连线会**盖过** `时间项.inputs[1]` 上的驱动值，
   时间项会变成 `时刻×方向×条数`，方向又只进时间项 ⇒ 退回症状。

> 与 [圆柱面螺旋斜纹](../skills/blender-cylinder-spiral-material/) 的"方向以实测标定、
> 纸面推导曾推反"是同一类教训：**方向/符号类参数必须用渲染实证，不能只看表达式连对**。

### 2.4 `FLOORED_MODULO` 而非 `MODULO`

`D = frac(x)` 用 `Math` 的 **`FLOORED_MODULO`（取模 1.0）** 实现。

普通 `MODULO` 对负值**裁剪**（`x<0` 返回负值）⇒ 扫描头跨过 `u=0`（0°）那一帧，
拖尾的角度区间出现负值 ⇒ **拖尾断头/整块闪没**。参考 HTML 里是手写环绕
`(x % 1 + 1) % 1`，与 `FLOORED_MODULO` 等价。

### 2.5 波形放 Math 域，别让 ColorRamp 兼职

拖尾 / 头部线 / 网格环带的亮度掩码全部是 `MapRange(LINEAR, clamp)`（+ `POWER` 调曲率），
**不经过 ColorRamp**。让 ColorRamp 兼职做波形会：参数耦合、色标被驱动锁死、
拖尾长度被结构卡死（此结论来自姊妹 skill `blender-cylinder-spiral-material` 的实测）。
本例只有一个颜色（白），**节点树里一个 ColorRamp 都没有**。

`拖尾曲率` 的指数直接对着参考 HTML 的 `pow(fade, 1.8)` —— 两者逐点等价。

### 2.6 正交的正交：亮面裁切 vs 拖尾长度

| 用户说的 | 该动哪个 |
|---|---|
| 拖尾太长/太短 | `拖尾长度`（度） |
| 发光范围收紧 / 四角要黑 | `亮面半径` + `淡出宽度` |

混成一个旋钮必然返工（同 [径向内收多脉冲](../skills/blender-inward-pulse-material/) 的裁切 vs 占空比）。

### 2.7 参数表（12 个滑块，键在「雷达控制」空物体上）

| 参数 | 默认 | 范围 | 作用 |
|---|---|---|---|
| 扫描速度 | 110 | 0–720 | 扫描头角速度（度/秒）；驱动 = `frame/fps × 速度/360` |
| 扫描条数 | 5 | 1–24 | 同时存在的扫描条数（扇面间距 = `2π/条数`） |

## 3. 坑（全部实测）

| # | 坑 | 现象 | 正解 |
|---|---|---|---|
| 1 | **方向进错项** | 方向拨 −1，头仍朝同一方向走（拖尾换边而已） | 方向只进角项：`D = frac(条数×时刻 − 方向×条数×u)`（§2.3） |
| 2 | **连线盖过驱动** | 「有向条数 → 时间项」一连，上面第 1 条又会复发 | 该线不连；时间项 `inputs[1]` 只挂驱动 |
| 3 | **普通 `MODULO` 负值裁剪** | 头跨 0° 时拖尾断头/闪没 | 用 `FLOORED_MODULO`（§2.4） |
| 4 | **`ARCTAN2` 的 y/x 接反** | 图案左右镜像 | `in0 ← Z`（y）、`in1 ← X`（x） |
| 5 | **半径带上 Y 分量** | 平面在 Y 上有跨度时半径算错、环/中心点变形 | `CombineXYZ` 填 `(X, 0, Z)` 再 `LENGTH` |
| 6 | **Object 坐标只跟随平移、不跟随旋转** | 转空物体纹理不跟着转 | 需要旋转图案就在节点内偏移（ADD + 驱动），别转空物体 |
| 7 | **5.2 没有 `ShaderNodeSceneTime`** | 找不到时间节点，整条链卡住 | `bpy.types` 全量探查确认（5.2 无任何 `ShaderNode*Time*`）⇒ 用 `ShaderNodeValue` 输出 + 驱动 |
| 8 | **`driver_add(path, 0)` 报错** | `index 0 was given while property ... is not an array` | 标量属性**不传 index** |
| 9 | **`MapRange` 同名插槽撞名** | 按名字取到 VECTOR 的那一套 | 用索引：VALUE = `0..5`（Value/From Min/From Max/To Min/To Max/Steps） |
| 10 | **改自定义属性后画面不刷新（脚本侧）** | 脚本里 `ctl[k]=v` 后节点值纹丝不动 | `ctl.update_tag()` + `bpy.context.view_layer.update()`；GUI 拖滑块自动打 tag |
| 11 | **核验只断言结构** | **方向 bug 完全隐形**（本路首轮就是这样放过了一整轮） | 必须渲染 + 像素级实测（§4） |
| 12 | **测量时发光强度太大** | 全画面过曝到 1.0，亮度剖面被压平 ⇒ `argmax` 随机 | 测量前把强度降到 `CHECK_GAIN=1.0` |
| 13 | **`fcurve.evaluate(frame)` 读驱动真值** | 打印出的是**帧号**（1.0 / 31.0）而非驱动值 | 渲染后读**被驱动插槽的 `default_value`** |
| 14 | **核验没还原就结束** | 用户场景被改（引擎/相机/隐藏） | `try/finally` 快照还原 |
| 15 | **桥 exec 里 `__file__` 不存在** | 附件路径报 `NameError` | 脚本内路径写绝对常量（`verify` 顶部 `OUT_DIR`） |
| 16 | **送桥脚本带 BOM** | `SyntaxError: invalid non-printable character U+FEFF` | PowerShell 用 `UTF8Encoding($false)` 写出，别用 `Out-File -Encoding UTF8` |

## 4. 核验：可证伪的读数

**只有结构断言不够** —— 本路首轮唯一的功能 bug（方向进错项，§2.3）在结构断言下完全隐形。
核验必须**把材质渲染出来、量像素**：

1. **沿法线正交正视**：临时相机 `center + normal*30`、`type='ORTHO'`、
   `ortho_scale = 最大边span × 0.98`、`to_track_quat('-Z','Y')`；
   `film_transparent=True`、`view_transform='Standard'`（别用 AgX，会把对比压平）、
   `dither_intensity=0`、其余对象 `hide_render=True`。
2. **采样一圈亮度**：按 `u = i/N` 反演 `X = r·cos(2πu−π)`、`Z = r·sin(2πu−π)`
   （与 `u=(atan2(Z,X)+π)/2π` 严格互逆）⇒ 得 `(u, lum)` 剖面。
3. **测转速**：`count=1` 时剖面只有一个亮峰，取 `argmax(u)`；帧 1→31 的角度差应等于
   `30/fps × 速度`。
4. **测反向**：`方向=−1` 重跑，应得相反符号。
5. **数条数**：`count=5` 数剖面亮峰个数。
6. **证 Y 投射**：平面**沿世界 Y 平移 2m**，两张渲染 PNG 的 **md5 应相同**。
7. **读驱动真值**：渲染后读被驱动插槽 `default_value`（**别用 `fcurve.evaluate`**）。
8. **收尾还原**：快照 / `finally` 还原引擎、相机、分辨率、`film_transparent`、
   `view_transform`、`dither`、帧号、各对象 `hide_render`、被改参数；临时相机 `remove`。

### 实测结果（Blender 5.2.2 LTS / Windows，2026-10-14）

| 判据 | 期望 | 实测 |
|---|---|---|
| 驱动真值（帧 1 / 31） | `0.01019 / 0.31574` | **逐位一致** |
| 单条扫描转角 | +110° | **+109°**（误差 1°） |
| 反向（方向=−1） | ≈ −110° | **−110°** |
| 5 条 | 5 个亮峰 | **5** |
| Y 投射（沿 Y 平移 2m） | 画面不变 | md5 `5a72afe178` **逐像素一致** |
| 收尾 | 无残留 | 引擎/相机/渲染/参数已复原，无异常隐藏 |

构建产物：材质 `平面_雷达扫描`、**节点 33 / 连线 39 / 驱动 13**，
挂到网格「平面」槽 0（旧材质 `Material #26` 保留便于回退）。
