# 参数化摆动驱动系统(单物体 · 参数挂在对象自身)

> 给对象挂「来回摆动」的驱动:**最小角度 / 最大角度 / 持续时间 / 相位偏移** 四个滑块直接长在
> **对象自己身上**,每个对象各一套、互不干扰,改滑块实时生效,无关键帧、无烘焙。
> 公式与 [主题 46 射灯阵列径向摆动绽放系统](射灯阵列径向摆动绽放系统.md) **同源(代数等价)**,
> 但**参数归属 / 错位机制 / 几何前置**三处不同 —— 见 **§4「两版怎么选」**。
> 可复用脚本包见 [`scripts/swing-driver/`](../scripts/swing-driver/)(build / verify)。

---

## 1. 场景

`钟表` 集合里有 5 个空物体父级(`钟表01`~`钟表05`),每个挂着一批网格(`钟表01` 挂 8 个)。要求:

- 每个空物体**绕自身 Y 轴来回摆** —— 网格跟着父级走,不用逐个 K 帧;
- **幅度和节奏要各自可调**(每个钟表可以摆不同角度、不同快慢);
- 改参数**实时看到**效果,不要每次重打关键帧;
- 不烘焙进时间轴(烘了就不好再调)。

> 先做了**关键帧版**([主题 40 Skill `blender-loop-keyframe-anim`](../skills/blender-loop-keyframe-anim/))能跑通,
> 但「改一个角度就要重写曲线」。本系统把它换成**驱动**,把「幅度 / 周期 / 相位」提炼成 4 个滑块。

---

## 2. 原理

### 2.1 公式(与主题 46 同源)

主题 46 第 57 行的写法:

```
α(t) = amin + (amax − amin)·(0.5 − 0.5·cos θ)
```

把它展开:

```
= amin + (amax − amin)/2 − (amax − amin)/2·cos θ
= (amin + amax)/2 − (amax − amin)/2·cos θ
```

**两式代数恒等**,都满足「θ=0 落在 amin、θ=π 落在 amax」。

本系统用**后者**:参数直接就是「中心 ± 半幅」的形式,改 min/max 时不必再乘 0.5 系数,
写进驱动表达式更短、可读性更好。

θ 由「当前帧 − 起始帧 − 相位偏移」除以周期给出:

```
θ = 2π·(frame − 1 − phs) / dur
```

### 2.2 驱动表达式(实测可用)

```python
radians((amin + amax)/2.0
        - (amax - amin)/2.0*cos(2.0*pi*(frame - 1.0 - phs)/dur))
```

4 个 `SINGLE_PROP` 变量 `amin / amax / dur / phs` **全部指向对象自身**的自定义属性。

> ★ **不引自定义 Python 函数**:表达式只用内置 `frame` + 自定义属性值,
> 所以**不存在**「命名空间函数不随 `.blend` 保存 ⇒ 重开文件驱动变红」的问题。
> 对比 [主题 20](驱动式Z轴匀速旋转系统.md) 的 `spin_speed()` 那种命名空间函数版,
> 就必须往文件里塞 Register 文本块来持久化。

### 2.3 为什么不用关键帧

关键帧版([主题 40](../skills/blender-loop-keyframe-anim/))也能做同样的摆动,而且**不依赖 Python
执行权限、复制/追加到别的工程也照播**。区别在**可调性**:关键帧改一个角度要重写整条曲线,
驱动版拖滑块就完事。选哪版见 §4。

## 3. 做法

### 3.1 建参数(带 `min`/`max` 才是滑块)

```python
for key, (dv, lo, hi, desc) in DEFAULTS.items():
    if key not in obj:
        obj[key] = float(dv)
    obj.id_properties_ui(key).update(min=lo, max=hi, soft_min=lo, soft_max=hi,
                                     description=desc, default=float(dv))
```

**属性键名就是显示名** —— Blender 没有独立 label,想要中文标签键就得是中文键。

| 属性 | 默认 | 范围 | 含义 |
|---|---|---|---|
| `最小角度` | -5.0 | -180 ~ 180 | 摆到下死点的角度(度) |
| `最大角度` | 5.0 | -180 ~ 180 | 摆到上死点的角度(度) |
| `持续时间` | 100.0 | 1 ~ 2000 | 一个完整来回 = 一个周期(帧) |
| `相位偏移` | 0.0 | -2000 ~ 2000 | 整体前后挪帧;0 = 帧 1 到达最小角 |

想错开多个对象又不想用 #46 的拍频,`相位偏移` 就够:第 i 个设 `i × step`。

### 3.2 挂驱动

```python
obj.rotation_mode = 'XYZ'
obj.rotation_euler[AXIS] = 0.0          # 基准角先复位,见坑 #6
fc = obj.driver_add('rotation_euler', AXIS)
d = fc.driver
d.type = 'SCRIPTED'
for name, key in [('amin', '最小角度'), ('amax', '最大角度'),
                  ('dur', '持续时间'), ('phs', '相位偏移')]:
    v = d.variables.new()
    v.name = name
    v.type = 'SINGLE_PROP'
    t = v.targets[0]
    t.id_type = 'OBJECT'                 # 指向对象自身 ⇒ 用默认 OBJECT,不需要 SCENE
    t.id = obj
    t.data_path = '["%s"]' % key
d.expression = EXPR
```

### 3.3 核验(**必须另起一次请求**)

驱动**只写 evaluated 数据**,直读原始 datablock 拿到的是未驱动值:

```python
scn.frame_set(fr)
dg = bpy.context.evaluated_depsgraph_get(); dg.update()
obj.evaluated_get(dg).rotation_euler[AXIS]     # ← 这个才是驱动值
```

## 4. 两版怎么选(本文重点)

| 维度 | [主题 46](射灯阵列径向摆动绽放系统.md) · 阵列绽放版 | 本篇 · 单物体自包含版 |
|---|---|---|
| **参数挂哪** | **Scene** 上的 `bloom_*`(全局一套) | **对象自身**的自定义属性(每个对象一套) |
| **调参粒度** | 一处改 → 所有目标一起变 | 每个对象**分别调** |
| **错位机制** | `spread`(速度差)+ `sync`(同步帧)= **拍频** | `相位偏移`(固定错开) |
| **节奏效果** | 时而错开、时而**整齐划一** | 只错开,**不会自己凑齐** |
| **几何前置** | 必须**插一层「铰链」空物体**(要让灯锁在各自竖直径向平面内;XYZ 欧拉下「X 轴水平 ⇒ Z 轴必竖直」,不能一步到位) | 直接驱动对象自身某一轴,**不需要铰链层** |
| **驱动通道** | 铰链的 `rotation_euler[0]`,另配静态 `rz` 对齐角 | 对象自己的 `rotation_euler[1]` |
| **参数随对象走** | ✗(参数在 Scene 上,复制对象带不走) | ✓(复制 / 追加对象,**参数一起带走**) |
| **驱动变量指向** | `id_type='SCENE'`(★ 必须先设,否则 `TypeError`) | `id_type='OBJECT'`(默认,无需额外处理) |
| **适合什么** | 一圈 / 一排**同族**物体做「花开花合」式**群体节奏** | **少量物体各自独立**摆动,幅度节奏互不相同 |

**一句话判据**:

- 想让 N 个物体「**时而错开、时而整齐**」并共用一套节奏 → **主题 46**
- 想让 N 个物体「**各摆各的**」,幅度 / 快慢单独调,且**参数跟着对象走** → **本篇**
- 只想「烘进时间轴、别人打开就能播、不依赖 Python 执行权限」→ **主题 40 关键帧版**

> 三者**共用同一条曲线**(正弦缓动),差别全在「参数挂哪、怎么错位、要不要铰链层」。

## 5. 坑(实测)

1. **驱动只写 evaluated 数据** —— 核验必须 `obj.evaluated_get(depsgraph)`,直读原始 datablock 拿到的是旧值/0。同一次 exec 内「改完立即读」也会滞后,跨请求才正常(实测)。
2. **驱动表达式必须返回弧度** —— `rotation_euler` 单位是弧度,写度数会放大 57.3 倍。
3. **驱动变量名避开内置 `frame`** —— 表达式里要用内置 `frame`,就别再声明一个同名变量。
4. **自定义属性带 `min`/`max` 才是滑块** —— 只写值会显示成无范围的数值框。
5. **替关键帧时:摘 action、别删数据块** —— `ad.action = None` 之前先 `act.name += '_旧关键帧版'` 且
   `act.use_fake_user = True`,留成孤儿随时可挂回去(主题 38 / 40 的存档纪律)。删了就真没了。
6. **挂驱动前把基准角复位为 0** —— 否则角度从被污染的基准累加([主题 20](驱动式Z轴匀速旋转系统.md) 踩过)。
7. **同一次 exec 内改属性后立即读会滞后** —— 跨请求即正常。实测:改成 `最大角度=12 / 持续时间=50 /
   相位偏移=25` 后,帧 1 → **12.0000**、帧 26 → **-5.0000**、帧 51 → **12.0000**,与手算完全一致。
8. **`radians()` 在 5.2 驱动表达式里实测可用** —— 主题 46 文档主张用 `pi/180`,两者都行;
   本篇实测 `radians()` 驱动 `is_valid=True`、数值精确到 1e-6。
9. **桥只改内存** —— 满意了 Ctrl+S,不满意 `File > Revert`。

## 6. 实测数据(钟表01,Blender 5.2.2 LTS)

默认参数(-5 / 5 / 100 / 0),全部走 depsgraph 求值:

| 帧 | 1 | 26 | 51 | 76 | 101 | 151 | 201 |
|---|---|---|---|---|---|---|---|
| 角度 | **-5.0000** | -0.0000 | **+5.0000** | 0.0000 | **-5.0000** | +5.0000 | -5.0000 |

- **周期精确性**:`evaluate(f)` 与 `evaluate(f+100)` 最大差 **0.00000000** 度
- **子对象跟随**:8 个网格世界坐标随父级变化(帧 1 与帧 51 不同)
- **参数实时生效**:改成 12 / 50 / 25 后帧 1 → **12.0000**(见坑 #7),收尾已还原默认
- **驱动结构**:`rotation_euler[1]` / `SCRIPTED` / `is_valid=True` / 4 个 `SINGLE_PROP` 指向对象自身

> **顺带修正一个关键帧版的坑**:关键帧 + `CYCLES` 修饰器时,重复周期 = **键跨度**,
> 即 `100 − 1 = 99` 帧(帧 100 与帧 1 同姿态 ⇒ 循环接缝重复一帧)。
> 驱动版按 `2π·(frame − 1)/dur` 计算,**周期就是 `dur` 帧**,不存在这个问题。
