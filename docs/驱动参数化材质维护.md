# 驱动参数化材质维护:引用体检 · 改写收敛 · 改名换轴

> 适用:已经建好的「**空物体自定义属性 + SINGLE_PROP 驱动器**」参数化材质系统(见主题 25/28/36/37 与
> `skills/blender-procedural-emission-material`、`skills/blender-radial-pulse-material`),
> 现在要做的是**运维改造**而不是新建 —— 把关键帧动画收敛成常量、给参数改名/换轴、确认"这个参数到底谁在读"。
>
> 来源:2026-09-15~16 水晶长廊工程(`260915xAx03.blend`)。控制物体 `竖向灯001_噪波控制`
> / `纵向灯001_噪波控制`(EMPTY)持自定义属性,驱动器分散在**材质节点树**与**7 盏面光灯各自的
> 灯光节点树**(`AreaLight → Shader Nodetree`)里。

## 0. 一句话结论

**改参数前先做引用体检,改完后必须做失效体检。** 这两件事都要求在**全方位**扫描动画数据,
最常漏的一层是 `物体数据 → node_tree`(灯光/网格自带节点树,驱动挂在里面)。

## 1. 谁在读这个参数:引用体检

### 1.1 必须扫到的层(一条都不能少)

```python
# 每个 object:
o.animation_data                       # 对象级(位置/旋转/自定义属性)
o.data.animation_data                  # 数据块级(Light/Mesh/Camera 的直接通道)
o.data.node_tree.animation_data        # ★ 最常漏:灯光/网格/世界自带节点树,驱动都在这里
o.modifiers[i].node_group.animation_data
# 全局:
bpy.data.materials(+ .node_tree) / bpy.data.node_groups
bpy.data.scenes / bpy.data.worlds(+ .node_tree)
```

经验法则:`hasattr(x, "node_tree")` 为真的 data-block 都要往下再扫一层。

### 1.2 漏扫的双向代价(两条都真实发生过)

| 方向 | 症状 | 实测案例 |
|---|---|---|
| **误判** | 参数明明接了线,却报告"全库零引用 ⇒ 假控件" | `面光统一强度` 的消费者在 7 盏灯节点树的 `发光强度.001`(`expr = st * k`),漏扫后得出完全相反的结论 |
| **事故** | 改名/删键后,漏扫层里的驱动**静默失效** | `Z向速度` → `X向速度` 改名时,7 盏灯节点树各有 1 条驱动指向旧键 ⇒ **`is_valid=False`**、面光灯噪波滚动整片停摆,UI 上完全看不出异常 |

两个方向互补:**判断"有没有人读"和"改名会不会改坏"用的是同一份扫描结果**,所以扫描必须一次做全。

### 1.3 体检脚本

`scripts/driver-param-maintenance/param_ref_scan.py`,两种模式:

- `MODE='refs'`:列出**谁在读**指定 ID 的指定属性(层 / 所有者 / 驱动路径 / 表达式 / 变量表)
- `MODE='health'`:列出全库**失效驱动**(`driver.is_valid == False`)与**悬空引用**
  (变量的 `data_path` 形如 `["X"]` 但该 ID 上已无 `X` 键)⇒ **验收判据是 0 条**

## 2. 关键帧 → 常量(收敛)

场景:当初给某个参数打了关键帧(如"噪波种子每 30 帧 +1"的 CONSTANT 阶梯、"发光强度 300→1000→300"的
BEZIER 闪光),现在要**冻结成一个常数**。

### 2.1 固定顺序

1. **读**:打印该曲线全部 `(帧, 值)` + `interpolation` + `extrapolation` + **`fc.evaluate(当前帧)`** + 属性静态值。
   ⚠️ 这一步的产物就是**回滚依据**,先落盘/贴给用户再动手。
2. **定常量**:两种口径,想清楚再用 ——
   - **当前帧所见值**(`fc.evaluate(f_current)`)= 画面不跳变,适合"我只是不想要动画了";
   - **用户指定值**(如"改成 200")= 用户要的是某个具体亮度/速度。
3. **删**:**只删目标 `data_path`+`array_index` 的那条 fcurve**,同一 action 里的其它曲线原样保留。
4. **写回**:IDProperty 直接 `ctrl["名"] = 常量`;节点插槽写 `socket.default_value`。
5. **刷新**:`ctrl.update_tag()` + `bpy.context.view_layer.update()`。
6. **验证**:必须**新的请求**里做(同一次 exec 内改完立即读会拿到未刷新缓存)。

### 2.2 实践要点

- 自定义属性关键帧走 **分层 Action** 路径:`action.layers[].strips[].channelbags[].fcurves`
  (`Action` 上没有 `.fcurves`),遍历全部 channelbag 才能覆盖所有 slot。
- 删 fcurve 用 `cb.fcurves.remove(fc)`,**不要**先 `list()` 之外的原地遍历(边遍历边删会漏)。
- 删完打印"动作剩余 fcurves"作为证据 —— 例如收敛完三个参数后应看到 `[]` 或只剩未处理的那条。
- 若参数被驱动器读取(如 `expr='sd * 10.0'`),删关键帧不影响驱动,驱动会自动读到新的常量值。

## 3. 参数改名 + 驱动换轴

需求形态:「`Z向速度` 改成 `X向速度`」= 属性改名 + 驱动器从向量插槽的**一个分量搬到另一个分量**。

### 3.1 固定顺序(顺序错了会留下悬空驱动)

```
① 引用体检 → 列出全部消费者(跨 data-block!)          ← 少一步就出 1.2 的事故
② 新属性 = 旧值,并把旧属性的 UI 元数据全量复制过去
③ 驱动换轴:driver_remove(path, 旧分量) → driver_add(path, 新分量)
   重建变量(id_type 先于 id) → ★ 显式覆盖 d.expression(否则被自动填成当时的数值=常量驱动)
④ 旧分量归零(清掉驱动残留值)
⑤ ★ 所有驱动都重建完之后,才删旧属性键
⑥ 刷新 + 失效体检(is_valid 0 条 / 悬空 0 条)+ 动态验证
```

### 3.2 UI 元数据全量复制

```python
d = ob.id_properties_ui("旧名").as_dict()        # 不能下标,必须 as_dict()
ob["新名"] = d["default"]
ob.id_properties_ui("新名").update(
    subtype=d.get("subtype", 'NONE'),
    description=d.get("description", ""),        # ★ 描述里的轴向文案要同步改(世界 Z → 世界 X)
    default=d.get("default", 0.0),
    min=d.get("min"), max=d.get("max"),
    soft_min=d.get("soft_min"), soft_max=d.get("soft_max"),
    step=d.get("step", 1.0), precision=d.get("precision", 4))
```

⚠️ `update()` **不接受 `name` 参数** —— 自定义属性的显示名就是键名本身,想换中文标签只能换键名,
逻辑读键的地方(驱动器变量的 `targets[0].data_path`)也必须同步改。

### 3.3 跨节点树同步(本例的关键)

同一个速度参数往往被**多处同构接入**(主材质 + 若干面光灯节点树)。
`Z向速度 → X向速度` 时,主材质搬到 X 分量后,**灯节点树的同名驱动也必须搬到同一分量**,
否则两边的噪波图案滚动方向不一致(本次实测:主材质 idx=2 与 7 盏灯 idx=2 原本一致,
改名后只搬了主材质 ⇒ 灯的那 7 条直接失效)。**判据:改完后主材质与全部灯在同帧读数逐位相等。**

## 4. 三个「index」别混

| 概念 | 长什么样 | 说明 |
|---|---|---|
| **驱动 FCurve 的分量索引** | `drivers.find(path, index=2)` / `driver_remove(path, 2)` / `driver_add(path, 2)` | 向量插槽的 X/Y/Z;`find()` 的 index **必须关键字传参**(位置传参报 `TypeError`) |
| **DriverTarget 的数组分量** | **5.2 已无 `.array_index`** | 写进 `data_path='location[0]'`(见 AGENTS.md 既有坑) |
| **ActionSlot 的标识** | `.identifier` / `.name_display` | **没有 `.name`,也没有 `.display_name`** |

## 5. 验证口径

1. **动态读数**(必须新请求):临时把参数改成一个可辨识的值(如 0.5),`frame_set` 到两三个帧,
   读**下游插槽**的评估值,比对期望(`期望 = 帧号 × 速度`)⇒ 再还原参数与帧号。
   一次能覆盖全部消费者,例如"主材质 + 7 盏灯"共 8 个插槽同帧读数应逐位一致。
2. **失效体检**:全库 `is_valid=False` 计数 = **0**;悬空属性引用计数 = **0**。
3. **关键帧收敛**:打印动作剩余 fcurve 清单(应为空或只剩未处理项)。
4. 收尾:**场景不自动存盘** —— 桥只改内存,必须提醒用户 `Ctrl+S`。

## 6. 踩坑清单

| 坑 | 现象 | 正解 |
|---|---|---|
| 漏扫 `data.node_tree` | 误判假控件 / 改名后驱动静默失效 | 见 §1.1 清单;改完跑失效体检 |
| `driver_add` 自动填常量表达式 | 装完驱动参数纹丝不动 | 必写 `d.expression = '...'` |
| 先删旧属性再重建驱动 | 驱动变红 / 悬空引用 | 顺序反过来:驱动重建完才删旧键 |
| `id_properties_ui(k)` 直接下标 | `object is not subscriptable` | 用 `.as_dict()` |
| `update(name=...)` 改显示名 | 报错 / 无效 | 显示名 = 键名,只能换键 |
| 脚本改 IDProperty 后不刷新 | 驱动读到旧值 | `ctrl.update_tag()` + `view_layer.update()` |
| 同一次 exec 内改完就验证 | 读到未刷新缓存值 | 改与验分两次请求 |
