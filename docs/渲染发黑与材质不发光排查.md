# 渲染发黑与材质不发光排查

> 场景：**"我给对象配了发光材质，渲染出来还是黑的"** —— 这类问题 90% 不在材质节点里。
> 本文给出一条按命中率排序的排查路径，以及一次打全的诊断脚本。
>
> 配套脚本：[`scripts/blackout-diagnose/`](../scripts/blackout-diagnose/) ·
> Skill：[`skills/blender-render-blackout-diagnose/`](../skills/blender-render-blackout-diagnose/)

---

## 一、先分清三种"不亮"

现象不同，病因完全不同。先问清楚（或自己看一眼渲染结果）属于哪一种：

| 现象 | 最可能的原因 | 跳到 |
|---|---|---|
| **纯黑 / 抠掉 / 完全没有该对象** | 材质覆盖、Holdout、视图层排除、输出未连线 | §2 ①②③④ |
| **有形体但发暗、像哑光、灰扑扑** | 色彩变换（AgX/Filmic）压暗、发光强度不足 | §2 ⑤ |
| **忽隐忽现 / 缺块 / 边缘消失** | 透明度与半透明、背面剔除、贴图 alpha | §2 ⑥ |
| **"我改了数值但毫无反应"** | 改的是**未接输出**的节点，或挂在别的对象上 | §2 ④⑦ |

## 二、七条排查路径（按命中率降序）

### ① View Layer 材质覆盖 `material_override` ★最高频

```python
for vl in bpy.context.scene.view_layers:
    print(vl.name, vl.material_override)     # 非 None 就是它
```

- 这是 **View Layer 级属性，不在材质里** —— 在材质节点树里永远查不到，所以极难自查到
- 一个 `material_override` 会把**该视图层下全部对象**的材质统统替换成它，此时你改任何材质都不会生效
- 常见来源：从别的工程 / 教程文件继承、同事调试图省事、Max·C4D 转换流程残留
- **清除**：`vl.material_override = None`（GUI 在 `Properties → View Layer → Material Override`）
- 注意 **Workbench 另有** `scene.display.shading.color_type == 'SINGLE'` + `single_color`，
  效果类似（整场景单色）；排查时这两条都要看

### ② 渲染引擎不读材质节点

- `scene.render.engine == 'BLENDER_WORKBENCH'` → **完全忽略材质节点树**，只看
  `shading.color_type`（`MATERIAL` 用 `diffuse_color`、`SINGLE` 用单色）。
  **发光材质在 Workbench 下永远不会发光**
- 要出材质 / 发光效果，引擎必须是 **`CYCLES`** 或 **`BLENDER_EEVEE_NEXT`**（4.2+ / 5.x 的 EEVEE 名）

### ③ Holdout / 相机可见性 / 视图层排除

对象级"一刀切"，任一条命中都会让对象在渲染里消失或变黑：

| 属性 | 含义 |
|---|---|
| `ob.is_holdout` | **Holdout**：渲染时被抠掉（输出黑/透明），最像"材质没用" |
| `ob.indirect_only` | 只参与间接光，相机直看不到（旧版属性，5.x 可能不存在） |
| `ob.visible_camera` | 相机可见性，`False` = 相机拍不到 |
| `ob.visible_diffuse` / `visible_glossy` / `visible_transmission` / `visible_shadow` | 各光线类型可见性 |
| `ob.is_shadow_catcher` | 阴影捕捉器（本身不显示） |
| `ob.hide_render` | 渲染隐藏 |
| `view_layer.objects.get(name) is None` | 被视图层**排除**（Exclude）——与 `hide_viewport` 不是一回事 |

排查时**逐条打出来**，别只看 `hide_render`。

### ④ Material Output 未连线 / 改错节点 ★最隐蔽

```python
out = next(n for n in nt.nodes if n.type == 'OUTPUT_MATERIAL' and n.is_active_output)
print(out.inputs['Surface'].is_linked)            # False = 整棵树没接输出
for l in nt.links:
    if l.to_node == out:
        print(l.from_node.type, l.from_node.name)  # 真正生效的是这个节点
```

三个高频子情形：

1. **一个材质里有多个 BSDF，只有其中一个接在输出上** —— 用户改了**没接线的那个**。
   实测案例：`Material #18526fds.001` 里 `原理化 BSDF` 的 `Emission Strength = 100`
   （**孤儿节点，未接输出**），而真正接在输出上的是 `原理化 BSDF.001`（`Emission Strength = 10`）。
   用户看到 100 以为够亮，实际生效的是 10
2. **存在多个 `OUTPUT_MATERIAL`**，只有 `is_active_output == True` 那个生效 —— 改了另一个
3. **`mat.node_tree is None`**（`use_nodes=False` 在 5.x 已弃用）—— 节点树被整个旁路，只用 `diffuse_color`

> 诊断脚本会专门输出「**发光值 > 0 但未接到输出**的节点清单」—— 这类节点是"假发光"，
> 几乎必然对应一个迷惑中的用户。

### ⑤ 色彩变换（View Transform）把发光压暗

- Blender 4.x/5.x 默认 **AgX**，对高亮有强烈滚降 + 高亮去饱和。
  **曾经在 Filmic/Standard 下 `Emission Strength = 5` 就很亮，AgX 下 10 也像哑光**
- 排查：`scene.view_settings.view_transform` / `look` / `exposure` / `gamma`
- 对策（按推荐度）：
  1. **提高发光强度**（AgX 下常见量级要到 50~500+，视场景）
  2. 临时切 `Standard` 验证是否只是色调映射问题 —— **这是验证手段，不是最终交付**
  3. 用 `look`（如 `AgX - Punchy`）提升对比
- ⚠️ AgX 只会让发光"不够亮"，**不会让材质变纯黑**。纯黑要往 ①②③④ 找

### ⑥ 透明度 / 半透明 / 背面剔除

- `mat.blend_method`（EEVEE）= `BLEND` / `HASHED` / `DITHERED`，且 Principled 的 `Alpha`
  接了贴图 alpha → 透明区域看着像"黑"或"没渲染出来"
- `mat.use_backface_culling = True` → 法线反的面直接消失
- 贴图 alpha 全 0、或 Base Color 接了空图像 → 黑
- 顺带：**`mat.diffuse_color`（视口颜色）与节点树结果无关**，不要拿它当判断依据

### ⑦ 材质数据块被共享 / 对象挂的不是你以为的材质

- 材质可能**多对象共享**（`mat.users` 很大）。实测案例 `Material #18526fds.001` 有
  **62 个使用者** —— 改它会**同时改掉 62 个对象**，容易被当成"改了没反应"（其实改了别处也在变）
- 用户可能在**别的对象**上配的发光材质，当前对象挂的是另一个 ——
  先 `print` 出 `ob.material_slots[i].material`，别凭记忆
- `.001` 后缀的材质是**复制残留**，容易与无后缀原版混淆

## 三、诊断脚本

[`scripts/blackout-diagnose/diagnose_blackout.py`](../scripts/blackout-diagnose/diagnose_blackout.py)
通过 9877 桥发送：

```
python bl.py diagnose_blackout.py
```

顶部 `TARGET` 填对象名可做对象级体检，留空则只做全场景扫描。输出分区：

| 区 | 内容 |
|---|---|
| A | 引擎 / `view_transform` / `look` / `exposure` / `film_transparent`（含自动告警） |
| B | **所有 view layer 的 `material_override`** + Workbench `color_type` / `single_color` |
| C | 全场景材质健康度：输出未连线数、**"假发光"节点清单**、多 BSDF 只连一个的材质、`Transparent BSDF` 直连输出、`use_nodes` 状态、多 `OUTPUT_MATERIAL` |
| D | 对象级（填了 `TARGET`）：类型 / 父子 / 可见性全套开关 / **Holdout** / 光线可见性 / slots / 材质树连线 |
| E | **结论区**：按扫描结果直接给出"头号嫌疑 + 建议动作" |

性能：遍历 236 个材质实测 **0.05 s**。（注意：切勿在脚本里遍历 Action 的 fcurve，
那才是慢的来源，见 [技巧速查 §1](技巧速查.md#1-远程控制运行中的-blender)）

## 四、真实案例复盘（2026-09-13）

**现象**：给对象 `图形1371.001` 配了发光材质，渲染还是黑的。

**排查过程**：

1. 先查全局（A/B 区）—— 发现 `material_override` 曾非空，用户自己已清除。
   **这就是本次的根因**：覆盖期间全场景材质被替换，配什么发光都不会生效
2. 引擎已从 `BLENDER_WORKBENCH` 切到 `CYCLES`（这也是必经之路 —— Workbench 下材质根本不生效）
3. 顺带扫全场景材质，**又挖出一个隐患**：该对象挂的 `Material #18526fds.001` 有
   **两个 Principled BSDF**，`原理化 BSDF`（`Emission Strength=100`）**未接输出**，
   真正生效的 `原理化 BSDF.001` 只有 **10**
4. 另记：`view_transform = AgX` 仍在生效，AgX 下 10 的发光强度偏弱

**结论**：本例是"两层原因叠加"—— ①材质覆盖让一切都不生效（已解决）；
②即使覆盖解除，生效的发光强度也只有用户以为的 1/10（因为改在了孤儿节点上）。

**教训**：这类问题必须**一次打全七条路径**。只盯着用户提到的那一条，会漏掉第二层原因。

## 五、坑清单（可直接抄进 AGENTS.md）

- **材质覆盖是 View Layer 级属性**，不在材质里 ⇒ 用户永远想不到；`material_override` 非 None 时，
  全场景材质失效，排查材质节点毫无意义
- **Workbench 引擎不读材质节点树** ⇒ "配了发光不亮"先看引擎
- **一个材质可含多个 BSDF，只有接到输出的那个生效** ⇒ 必须显式打印"输出节点连的是谁"，
  并列出"发光值>0 但未接输出"的孤儿节点
- **`is_holdout` / `visible_camera` / 视图层 Exclude** 都会让对象渲染消失，症状极像"材质没用"
- **AgX 会压暗高亮** ⇒ 只解释"不够亮"，不解释"纯黑"
- **`mat.diffuse_color` 与节点树无关**，不能当判断依据
- **材质可能被几十个对象共享**（实测 62 users）⇒ 改前先报 `users` 数
- **写给桥的脚本文件不能带 BOM** ⇒ Windows PowerShell 5.1 的 `Set-Content -Encoding UTF8`
  **会加 BOM**，桥端直接 `SyntaxError: invalid non-printable character U+FEFF`。
  用 Python `open(...,encoding='utf-8')` 写，或确保编辑器不写 BOM
