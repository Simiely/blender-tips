# 射灯阵列径向摆动绽放系统(Blender 5.2)

> 一圈射灯各自**锁在自己的竖直径向平面里**来回摆动,8 盏速度略有差异 ——
> 起初依次展开,跑一段时间后因速度差凑到一处**同时展开**,之后又错开。
> 视觉上就是花开与花闭合。全靠 driver 驱动,改一个数字调整体节奏,不烘焙关键帧。
> 可复用脚本包见 `scripts/spot-bloom-swing/`(probe / build / verify / undo)。

## 场景

装置/舞美里有一圈射灯(实测 8 盏,绕中轴呈八方位排列、半径约 2.5m),想让它们:

- 每盏灯**只在自己的竖直平面内点头**,不许歪到别的方向去;
- 全部**朝内收拢**是"花闭合",**向外张开**是"花开",之间来回往复;
- 8 盏**速度不一样**:一开始依次展开,跑一段后"变成一同展开",再因为速度差错位;
- 整体节奏能**拖滑块实时调**,不要每盏单独 K 帧。

## 原理

### 一、几何:三个量定死一盏灯的摆动

| 量 | 定义 |
|---|---|
| **起始线(0°)** | 灯 → 中轴线对象 的连线。若中轴对象与灯等高就是**水平朝内**;若中轴被抬高(实测高 0.855),就是**朝内上方倾斜**(实测 18.8°) |
| **旋转平面** | 灯的位置与**竖直中轴线**确定的平面 —— 8 盏就是 8 个绕轴辐射的平面,像切蛋糕 |
| **旋转轴** | 该平面内**水平且垂直于半径**的**切向轴** `t̂ = ẑ × r̂`。绕它转,灯只在本平面内点头 |

摆幅定义在起始线之上:`0° = 起始线本身`,向外转到 `amax`(实测 125°)。
中途会经过**竖直朝上**(当 `α = 90° − 起始线仰角` 时)。

### 二、层级:为什么非要插一层"铰链"

```
射灯(定位空对象, 位置不动)
  └─ 射灯_铰链   rotation_euler = (α_driver, 0, rz)
       └─ 射灯_光   rotation_euler = (π/2 + elev, 0, 0)
```

`rz` 是绕 Z 的静态对齐角(`atan2(t̂.y, t̂.x)`),`elev` 是起始线仰角。

**灯的局部旋转为什么是 `π/2 + elev`**(推导,别凭感觉写):

1. Blender `'XYZ'` 欧拉的实际矩阵是 `R = Rz(rz)·Ry(ry)·Rx(α)`,`ry=0` 时 `R = Rz(rz)·Rx(α)`
2. 此时**第一列(X 轴)恒为水平** `(cos rz, sin rz, 0)` ⇒ 取 `rz = atan2(t̂.y, t̂.x)` 就得到 `X = t̂`
3. 灯的照射方向是它的局部 `−Z`,要求 `α=0` 时指向起始线,即 `Rz(rz)·v = 起始方向`
   ⇒ `v = Rz(−rz)·起始方向`;起始线水平时 `v = (0,1,0)`,倾斜 `elev` 时 `v = (0, cos elev, sin elev)`
4. 绕 X 转 `θ` 后 `Rx(θ)·(0,0,−1) = (0, sin θ, −cos θ)`,令其等于 `v`
   ⇒ `θ = 90° + elev`

⚠️ **XYZ 顺序下"X 轴水平"必然导致"Z 轴竖直"**,所以不可能同时取 `X = t̂` 且 `Z = r̂`。
想当然按 `基 = [t̂, ẑ, r̂]` 去构造矩阵,赋给 `rotation_euler` 会**静默歪掉**。这就是要插铰链的原因。

### 三、节奏:拍频公式(核心)

```
f_i     = 1 + spread·i/7                       # 灯 i 的速度系数(按方位递增)
θ_i(t)  = 2π · ( t·f_i − sync·(f_i − 1) ) / period
α_i(t)  = amin + (amax − amin) · (0.5 − 0.5·cos θ_i(t))     # 正弦缓动
```

**为什么会在 `sync` 帧精确同步**:代入 `t = sync`,

```
sync·f_i − sync·(f_i − 1) = sync          # f_i 被抵消, 与 i 无关
⇒ θ_i(sync) = 2π·sync/period, 对所有 i 相同 ⇒ 8 盏展开角完全相同
```

**同步瞬间的展开程度由 `sync / period` 的小数部分决定**:

| sync/period | 同步时展开角 |
|---|---|
| 2.0(`sync=480`) | 0° —— 整体闭合 |
| 2.25(`sync=540`) | 62.5° —— 半开 |
| 2.5(`sync=600`,默认) | 125° —— 整体全开 |

**两次同步之间隔多久**:`对齐周期 = 7 × period / spread`。
默认 `240 / 0.10` ⇒ **16800 帧**,所以 3000 帧的场景里**只会精确同步一次**。
想更频繁地"凑到一起",就加大 `spread`。

## 做法(可复用脚本)

### 1. 先探查,别猜

```bash
python send.py -p 9888 probe_bloom.py
```

打印:8 个定位空对象的水平距轴 / 高差 / **起始线仰角** / 方位角 / 缩放 / 现有层级与驱动数。
**非单位缩放会告警**(挂父子会传递缩放,把灯拉变形)。

### 2. 构建

```bash
python send.py -p 9888 build_bloom_swing.py
```

改脚本顶部配置区:`COLLECTION` / `CENTER_OBJ` / `SPOT_PREFIX` / `LAMP_PREFIX` / `HINGE_PREFIX`
以及 `PERIOD` / `SYNC` / `SPREAD` / `MIN_DEG` / `MAX_DEG`。

driver 表达式(已是实测可用形式,用 `pi/180` 而非 `radians()`):

```python
"amin*pi/180 + (amax-amin)*pi/180"
"*(0.5 - 0.5*cos(2*pi*(fr*(1+spread*%d/7) - sync*spread*%d/7)/period))"
```

6 个 SINGLE_PROP 变量全部指向 Scene:`frame_current`
与 `["bloom_period"]` / `["bloom_sync_frame"]` / `["bloom_spread"]` / `["bloom_min_deg"]` / `["bloom_max_deg"]`。

### 3. 独立核验(**必须另一次请求**)

```bash
python send.py -p 9888 verify_bloom.py
```

### 4. 实时调参

Scene → 属性面板 → 自定义属性,拖 `bloom_*` 五个滑块即可。

### 5. 撤销

```bash
python send.py -p 9888 undo_bloom.py
```

## ⚠️ 坑(代码里看不出,全是实战踩的)

1. **★ 批量脚本中途抛异常会留下半改造状态**:实测 8 盏的循环跑到第 1 盏就炸,
   结果**只有那一盏**被改成铰链架构(水平朝外 180°),其余 7 盏仍是朝上 90° ——
   用户预览直接看到"有一盏不对"。而且 driver 已经 `new` 出来但**变量没挂上**,
   表达式引用未定义变量。**对策**:先把 API 用最小 demo 验证过再写批量脚本;
   跑完必须看 `verify_bloom.py` 的 `VERDICT`。

2. **★ 5.2 的 `DriverTarget.id` 只接受 Object,塞 Scene 直接 TypeError**:
   `TypeError: DriverTarget.id expected a Object type, not Scene`。
   必须先 `tg.id_type = 'SCENE'` 再 `tg.id = scene`。枚举里有 `'SCENE'`,也有 `'ACTION'` / `'WORLD'` 等。

3. **★ 桥是 `exec` 整段代码,任何一行抛异常会让前面所有 print 全部丢失**
   (stdout 被 redirect,只有整体成功才回包)。所以**写批量脚本前先探 API**,
   别指望靠报错信息定位。这次连踩 4 个 5.2 属性变更才学乖。

4. **★ 5.2 删改的属性(实测)**:

   | 4.x 写法 | 5.2 实测 |
   |---|---|
   | `ActionSlot.name` | **不存在** → 用 `name_display` / `identifier` |
   | `UnitSettings.length_system` | **不存在** → 用 `system` / `length_unit` / `scale_length` |
   | `Light.power` | **不存在** → 用 `energy`(新建 Spot 默认只有 **10 W**,基本看不见) |
   | `Light.show_cone` 默认 True | **默认是 `False`** —— 想让聚光灯在视口显示照射锥必须显式打开 |
   | `DriverTarget.id_type` 可选 | **必须显式指定**,否则 `id` 只接受 Object |

5. **定位空对象常常没有旋转**:实测 8 个 `射灯*` 全是 `rotation=(0,0,0)` ——
   **朝向信息根本不存在**。而 Blender 聚光灯默认朝 `−Z`(向下),所以**方向必须问用户**,
   不能默认"朝下"。

6. **起始线是不是水平的,取决于中轴线对象有没有被移动**:本例原始中轴与灯等高(0.405),
   起始线水平;后来用户把中轴抬到 1.2606,起始线就变成朝内上方倾斜 18.8°。
   **"灯与中轴线的连线"有两种理解** —— 指向轴上的**垂足**(水平) vs 指向**中轴对象那个点**(倾斜)。
   按用户原话「射灯和绽放中轴线**对象**的连线」取后者。

7. **静态方案:移动中轴线不会自动重算**。起始线的 `rz` 与 `elev` 是构建时算出来
   **写死在变换里**的,driver 只负责摆幅、不含几何。改完中轴位置需重跑构建脚本。
   (若要实时跟随,得改用 `Damped Track` 指向中轴 + 子级叠加摆动,每盏多 2 个对象)

8. **"整体闭合"的瞬间默认不存在**:默认 `sync/period = 2.5` ⇒ 唯一那次同步发生在**完全展开**。
   要"整体闭合"那一下,把 `bloom_sync_frame` 设成 `period` 的整数倍(如 480)。

9. **同一次 exec 内改完立即验证会读到未刷新缓存值**:构建与核验必须分两次请求。

10. **`射灯*` 前缀匹配要写严格正则**:`射灯_光` / `射灯_铰链` 都以 `射灯` 开头,
    用 `startswith("射灯")` 会把灯和铰链一起吞进去。用 `^射灯(\.\d{3})?$`。

11. **桥只改内存**:满意了 Ctrl+S。

## 验证要点

| 判据 | 实测值 |
|---|---|
| 灯的**世界位置误差** | **0**(灯没被铰链带走) |
| **切向偏离** `dir·t̂` | **0.000000**(8 盏全部锁死在各自径向平面) |
| frame 0 展开角 | -0.0 / 1.6 / 6.2 / 13.6 / 23.5 / 35.4 / 48.6 / **62.5**(依次错开) |
| **frame 600(sync)角差** | **0.000000**,8 盏全部 125.0° |
| frame 601 | 124.98°,开始错开 |
| frame 0 灯 0 的**光线到中轴距离** | **0.0000**(闭合时精确命中花心) |
| 参数改动 | 拖 `bloom_*` 滑块实时生效,不用重跑 |
