# 合成器后期辉光(Glare)

给**已经渲染出来的画面**加一层眩光:灯带/霓虹/LED 的高光向外溢出成柔和光晕。
做法是**合成器节点组** —— `渲染层 → 眩光(Glare) → 合成输出`,
挂在 `scene.compositing_node_group` 上;**不动几何、不动材质、不重渲**。

6 个中文滑块长在一个**空对象**上(材质/场景可整体搬运),`类型`/`质量`/`染色`/`阈值过渡柔度`
留在节点上**不设驱动**给用户手调(与"色标归用户自己调"同一约定)。

- 脚本包:[`../scripts/post-glare-glow/`](../scripts/post-glare-glow/)
- AI 作业规范:[`../skills/blender-post-glare-glow/`](../skills/blender-post-glare-glow/)

> ⚠️ **本主题存在的第一个理由**:仓库里**旧配方在 5.x 已经失效**。旧接法把终结节点写成
> `CompositorNodeConvertToDisplay`,在 5.x 下整条合成被**静默旁路** —— 不报错、画面完全不变。
> 详见 §2.3 与 §3.1。受影响的既有文档:`粒子系统礼花喷射方案.md` §3.8 与
> `scripts/firework-confetti/build_firework.py`(**尚未修,见 §6**)。

## 1. 场景

一句话:**"我新开了工程,帮我增加后期辉光效果。"**

拆开是四件事:

1. 效果作用于**整幅渲染画面**,而不是某一个材质 ⇒ 走**合成器**,不是着色器。
2. 参数要能**实时调**(开关 / 强度 / 阈值 / 尺寸 / 饱和度 / 最大亮度)。
3. 参数**不能锁死在节点里** —— 用户是 Blender 重度使用者,类型和质量这类
   "看效果才知道哪个好"的档位要留给自己手调。
4. 工程里对象上万(实测 **10,630**),不可能靠改几何/材质来做画面级效果。

## 2. 做法

### 2.1 锚点:空对象「辉光控制」= 参数载体

6 个自定义属性挂在一个 EMPTY 上,驱动器从它读值:

| 旋钮 | 默认 | 硬量程 | 软量程 | 说明 |
|---|---|---|---|---|
| `辉光开关` | 1.0 | 0–1 | 0–1 | 1=开 / 0=关(强度乘 0,实测与不加合成器逐位相同) |
| `辉光强度` | 1.0 | 0–4 | 0–2 | 眩光强度(会乘辉光开关) |
| `辉光阈值` | 1.0 | 0–50 | 0–20 | 进入辉光的亮度阈值(线性,越高越挑剔) |
| `辉光尺寸` | 0.5 | 0–1 | 0–1 | 扩散尺寸(0–1 比例,5.x 是 `Factor`) |
| `辉光饱和度` | 1.0 | 0–4 | 0–2 | 饱和度(1 = 原色,>1 更艳) |
| `辉光最大亮度` | 10.0 | 0–500 | 0–100 | 单像素最大贡献(压过曝) |

★ **交付时必须把该对象设为 `view_layer.objects.active`** ——
Blender 的**物体属性面板只显示活动对象**,不选中它,这 6 个滑块根本不在面板里。
(踩过:用户"找不到参数";也踩过用户切到别的对象后"参数不见了"。)

### 2.2 节点管线

```
渲染层(RLayers) ──Image──> 眩光(Glare) ──Image──> 合成输出(NodeGroupOutput)
```

节点 **3** 个 / 连线 **2** 条。`眩光` 的 `Image` 输出是"原图 + 眩光"已经合成好的结果;
另有 `Glare`(只有眩光)与 `Highlights`(只有高光)两个输出可选用。

### 2.3 ★★★ 5.x 合成器迁移:终结节点必须是 `NodeGroupOutput`,而且要先声明组输出插座

这是本主题**最关键的一步**,也是整套效果能不能生效的唯一开关:

```python
ng = sc.compositing_node_group          # CompositorNodeTree
# ★ 必须先声明组输出插座,再接线
for it in ng.interface.items_tree:
    if it.item_type == 'SOCKET' and getattr(it, 'in_out', None) == 'OUTPUT':
        break
else:
    ng.interface.new_socket(name="Image", in_out='OUTPUT', socket_type='NodeSocketColor')
```

**漏掉 `new_socket` 这一步,整条合成被静默旁路** —— 后果见 §3.1。

另外三条 5.x 事实:

* **`scene.node_tree` 在 5.0 已移除**;`scene.use_nodes` 恒为 `True` 且设了没用 ⇒
  不要再写 `scene.use_nodes = True`。
* **`scene.compositing_node_group` 才是那棵树**(`CompositorNodeTree`)。
* **`render.use_compositing` 是总闸**:关掉后连极端眩光也是 0 差异。

> **5.0 起的合成器路线图**:5.0 给链着的节点树上了 CPU 实时合成器(RTR),5.1 起有后端相关限制,
> 旧 CPU 合成器在 5.2 被移除。所以"5.x 该怎么接"跟 2.x/3.x 的教程**不能混用**。

### 2.4 驱动器映射(6 旋钮 → 5 驱动)

| 驱动 `data_path` | 表达式 | 变量 |
|---|---|---|
| `nodes["眩光"].inputs["Threshold"].default_value` | `th` | `th ← 辉光阈值` |
| `nodes["眩光"].inputs["Size"].default_value` | `sz` | `sz ← 辉光尺寸` |
| `nodes["眩光"].inputs["Saturation"].default_value` | `sa` | `sa ← 辉光饱和度` |
| `nodes["眩光"].inputs["Maximum"].default_value` | `mx` | `mx ← 辉光最大亮度` |
| `nodes["眩光"].inputs["Strength"].default_value` | `(sw * st)` | `sw ← 辉光开关`,`st ← 辉光强度` |

* **`辉光开关` 不单独占一个插座**:它乘进 `Strength`(两个变量一条驱动)⇒
  `开关=0` 时 `Strength=0`,而 `Strength=0` 实测与"完全不加合成器"等价 ⇒ **真旁路**。
* 驱动类型全部 `SCRIPTED`,变量全部 `SINGLE_PROP` 指向空对象 `辉光控制`
  ⇒ **不引命名空间函数**,重开文件驱动不会变红。
* `SINGLE_PROP` 变量必须**先 `tgt.id_type='OBJECT'` 再 `tgt.id`**。

### 2.5 参数表

见 §2.1 的表。★ **兼容性口径**:驱动器只提供本主题 6 个键;**工程里别的同名键不会被碰**。

### 2.6 留给用户手调的插座(本包不设驱动)

`眩光` 节点上**可以直接改**的:类型(6 选 1)、质量(Low/Medium/High)、
染色、阈值过渡柔度;以及只在对应类型下起作用的
`条纹数` / `条纹角度` / `迭代` / `淡化` / `颜色调制` / `对角线` / `抖动` / `内核` 等。

这与"ColorRamp 上零驱动、颜色留给手调"是同一条约定:
**结构归脚本,审美归用户。**

### 2.7 可发现性:紫色插座 + 指路提示

被驱动的 5 个插座在 UI 上是**紫色、拖不动**的。这不是坏了,是"改道":
Blender 每次依赖图求值都会把它重算回驱动结果,手输的值立刻被覆盖。
(用户原话:"合成器「眩光」节点上,框是紫色拖不动"。)

所以本包顺手做了三件**非破坏**的指路工作:

1. **节点标题**:`glare.label = "参数在空对象「辉光控制」上"`
   (★ 只改 `label`,**不动 `node.name`** ⇒ 驱动地址 `nodes["眩光"]` 不受影响)。
2. **被驱动插座的悬停提示**:`被驱动 →「辉光控制」的辉光强度`。
3. **可直接改的插座提示**:`可直接改:类型 6 选 1` / `可直接改:Low/Med/High` / …

## 3. 坑(全部实测)

### 3.1 ★★★ 静默旁路:唯一的信号是"所有出图字节数完全相同"

第一次构建后,5 张不同参数的出图**字节数全部是 220,159**。这才把问题揪出来:

* **不报错**;
* **画面完全不变**(与不加合成器逐像素相同);
* **连 PNG 文件字节数都一模一样**。

根因:终结节点不是 `NodeGroupOutput`,或者组没有声明 OUTPUT 插座(§2.3)。
丢掉"没接上"这个错误信号的代价,就是必须靠**字节数/像素**去发现它。

### 3.2 ★★ 比 md5、比文件大小都不足以判"两张图一样"

PNG 里含时间戳类块 ⇒ **md5 不同、但字节数可以完全相同**。
最早用 md5 判"变体有没有生效",结果 5 个变体全部报"生效"而每个文件都是 78,341 字节 ——
**md5 不同只是因为时间戳**。判"一样"必须**比像素**。
(反之判"不一样"也一样:差异可能只是量化噪声,见 §4.2。)

### 3.3 ★★ 不要把 `CompositorNodeConvertToDisplay` 当终结节点

它会把色彩管理**再套一遍**:实测旁路档 `max=0.4039`、`90944/129600` 个分量被改动。
正解是 `眩光 → 合成输出` 直连,此时"强度 = 0"与"不加合成器"**逐位相同**
(早期 180×180 隔离实验实测 `max=0.00000000` / `0/129600`)。

### 3.4 ★★ 驱动挂在**合成器节点树**上时:脚本读插座必须手工 tag,渲染却会自己求值

* **脚本路径**:改完自定义属性后,**只 `evaluated_depsgraph_get().update()` 读到的是陈旧值**。
  实测:属性 1.0 → 3.5,插座**停在 1.0**;手工 `ng.update_tag()` 之后才变 3.5。
  ⇒ 正确姿势:`ctrl.update_tag()` + `ng.update_tag()` + `sc.update_tag()` + 依赖图更新。
* **渲染路径**:全程**不 tag**,只改 `辉光开关` 1→0,两次渲染相差
  `120817/230400` 个分量(`max=0.89019614`)⇒ **F12 / 视口渲染时驱动会自己求值**。

⇒ 推论:**"脚本读到陈旧值" ≠ "用户在界面上改参数没用"**。
一度想把用户的"拖不动"归因到没 tag,是**误判** —— 那条只影响脚本自己读数。

### 3.5 ★★ 驱动维护:索引用 `data_path`,变量在 `targets[0]` 上

* **`AnimData.drivers.new()` 是追加到末尾**,`remove()` 会让后续元素前移
  ⇒「第 i 条驱动」这个索引**永远不稳定**,一律**按 `data_path` 匹配**。
* **`DriverVariable` 没有 `.data_path` / `.id`** —— 它们在 **`v.targets[0]`** 上。
  读错会永远判"规格不符"、**每跑必重建**(数值仍对,但幂等报告失效)。
* 改驱动器的**变量**必须**原子重建**整条驱动;只把字段"改对"救不回 `is_valid=False` 的僵死状态。
* 删驱动前先把要用的字段"冻结"成局部变量,否则 `ReferenceError: StructRNA ... has been removed`。

### 3.6 ★ MENU 插座的取值是**标题式字符串**,且没有 `enum_items`

`Type`:`'Fog Glow'` / `'Bloom'` / `'Streaks'` / `'Ghosts'` / `'Simple Star'` / `'Kernel'`;
`Quality`:`'Low'` / `'Medium'` / `'High'`;`Kernel Data Type`:`'Float'` / `'Color'` 等。

写成全大写标识符(`'FOG_GLOW'`、`'KERNEL'`)会 `TypeError`。
而且 `NodeSocketMenu` **没有 `.enum_items`** ⇒ **枚举只能试写**,别指望列出候选。

### 3.7 ★ subtype 决定量程:`FloatFactor` ⇒ 0–1

| 插座 | 类型 | 量程 |
|---|---|---|
| `Strength` / `Saturation` / `Size` / `Smoothness` / `Fade` / `Color Modulation` / `Jitter` | `NodeSocketFloatFactor` | **0–1** |
| `Threshold` / `Maximum` | `NodeSocketFloat` | 不受 0–1 限制 |
| `Streaks` / `Iterations` | `NodeSocketInt` | 整数 |

**旧配方的 `Size = 12` 是 2.x–3.x 的整数 API,在 5.x 已失效**(会被夹到 1.0)。

### 3.8 ★★ 大尺寸眩光 + 低采样 = 噪点放大器

同一组 `尺寸 = 1.0`:**12 samples 不降噪 ⇒ 整幅炸成雪花点;24 samples + 降噪 ⇒ 干净的柔光雾**。

Fog Glow 会把任何超过阈值的像素**摊开成一大团**,低采样的噪点被当成高光一起放大。
⇒ **先把渲染弄干净,再调大尺寸。** 这不是数据错了,是采样不够。

### 3.9 ★ 自定义属性要像"滑块",必须写硬 `min` / `max`

只写 `soft_min`/`soft_max` 时,Blender 里控件仍是**普通数值框**(硬边界 ±3.4e38),
看起来不像滑块。正确写法:

```python
ctrl.id_properties_ui(p).update(min=hmn, max=hmx, soft_min=smn, soft_max=smx,
                                step=0.01, precision=3)
```

`step` 默认 **1.0**(拖一格跳 1),细调要 0.01。
★ 判"属性是否被锁"**别看** `ID.is_property_readonly` / `is_property_hidden` / `is_property_set`
—— 本项目版本上调用签名对不上,**一律 `TypeError`**;直接看 `id.animation_data` 里有没有指向它的驱动。

### 3.10 ★ 紫色插座 = 被驱动;`description` 有 63 字节上限,`label` 只读

* `NodeSocket.description` 的硬上限实测 **63 字节**(中文 3 字节/字 ≈ 21 字),
  **超了静默截断、不报错** ⇒ 写提示前先量长度并断言写回一致。
* **`NodeSocket.label` 是只读的** —— `bpy_struct: attribute "label" from "NodeSocketFloat" is read-only`。
* 只有 **`Node.label`** 能改,而且改 label **不影响 `node.name`** ⇒ 驱动地址安全。

### 3.11 ★ 视口里看不见辉光:要另设 `shading.use_compositor`

`space.shading.use_compositor` 枚举是 `['DISABLED','CAMERA','ALWAYS']`,**默认 `DISABLED`**
⇒ 视口里看不到辉光(而且 `shading.type` 还得是 `RENDERED`)。
脚本里遍历 `VIEW_3D` 区域把它设成 `'ALWAYS'` 即可(本包的 `build_glow.py` 已内置)。

### 3.12 ★ 脚本层"报告串位":别复用循环残留变量

在一处分支里写成了 `describe(d)`,而 `d` 是**上一个 `for` 循环的残留变量**,
于是"旧规格"打印出来的是**隔壁那条驱动** —— 看着像 6 个旋钮整体串了一位,
**实际数据一直是对的,只有报告错了**。
⇒ **报告异常时先确认自己在读对象本身,不是在读残留引用。**

### 3.13 桥的既有约束(与其它主题共通)

* 桥 `exec` 环境里**没有 `__file__`** ⇒ 脚本内路径必须写绝对常量。
* 送桥脚本**不能带 BOM**(PowerShell 5.1 的 `Out-File -Encoding UTF8` 会写 BOM
  ⇒ 桥端 `SyntaxError: U+FEFF`)。
* **异常会让前面所有 `print` 全丢**(只剩 ERR 的 traceback)⇒ 诊断脚本要防御性写法。
* **硬超时 120 s**。本包的 `verify_glow_render.py` 出 7 张 400×225 图,
  实测渲染段 7–9 s/张,**接近上限** ⇒ 要更保险就把 `VW/VH/SAMPLES` 调小。

## 4. 核验:可证伪的读数

### 4.1 `verify_glow_render.py` —— 三层共 8 项

| # | 断言 | 为什么是判据(它能怎么失败) |
|---|---|---|
| [0] | 同设置渲两次逐位相同 | 不成立则后面所有像素比对都不作数(自证工具可靠) |
| [1] | `开关=0` ≡ 完全不加合成器 | 接错终结节点 / 管线多套一层色彩管理 ⇒ 立刻掉下来 |
| [2] | 增益 >0.02 的像素 > 500 个;最大变暗 > −0.02 | 效果没生效 ⇒ 第一条掉;**把高光搬走** ⇒ 第二条掉 |
| [3] | 暗部增益占比 >10%;暗部最大单点 >0.02;高光也被加强 | **光晕的物理签名** —— "整体提亮"会让第一条掉;"只把高光搬走"会让第三条掉 |
| [4] | 尺寸↑ ⇒ 暗部增益↑;**阈值↑ ⇒ 总增益↓**;**强度↓ ⇒ 总增益↓** | 阈值/强度接反 ⇒ 立刻掉下来 |

★ 关键在于 **[1] / [4] 规定了"能让它失败的方向"** —— 不是"看起来在发光"这种恒真读数。

### 4.2 ★★ 判据陷阱:本类工程的 Cycles **不是逐位确定的**

`[0]` 默认要求**严格逐位相同**。但在对象数以万计、含大量高光的 CAD 场景里实测:

```
A1 vs A2 (同设置两次): max=0.00392157  差异分量=1/360000
差异诊断:
  最大差异在 分量 k=174860(像素 43715,通道 0,y=109 x=115): A1=0.54509807 A2=0.54901963
  差值的 8bit 台阶数 = 1.000000
  两侧中点 = 0.54705885  (= 139.5000/255)
```

* 差值**恰好 1 个 8bit 量化步**(`1/255`),差异分量**只有 1 个**;
* 两侧中点**正好是 `x.5/255`** ⇒ **真实浮点值压在量化台阶的中点上**,末位抖动就翻到邻档;
* 再跑一次,**抖动的像素换成了另一个**(上一次是 `y=212 x=255` 通道 2,中点 `126.5/255`)
  ⇒ 是**多个像素同时踩在台阶上**,跟"哪个先翻"有关,不是某个固定像素坏了。

⇒ **不是辉光坏了,是判据比介质更严。** 本包的处理是**把两个判据分层**:

* `[0]` **工具自检**保持严格(`DET_MAX_DIFF = 0.0`),失败时**自动打印差异诊断**
  (差异像素坐标 / 8bit 台阶数 / 两侧中点)⇒ 一眼分辨"量化台阶"还是"真不确定"。
* `[1]` **物理结论**给 1 个量化步容差(`EQ_MAX_DIFF = 1/255`、`EQ_MAX_CNT = 8`)——
  因为 1 个 LSB 仍是**同一张图**;而"管线真的不等价"会让**成千上万**个分量一起变,
  这点容差抓不住它才有问题。

★ 想要更硬的证据:**把渲染格式改成 32 位浮点 EXR 再比**(绕开 8bit 量化)。
**先怀疑度量,再怀疑被测对象。**

### 实测结果(Blender 5.2.2 LTS / Windows,2026-10-16)

工程 `261015合并_扇形装置_连廊.blend`,CYCLES,10,630 个对象,AgX。

| 项 | 读数 |
|---|---|
| 探针 | 眩光节点 **22 输入 / 3 输出**;5 条驱动全部 `is_valid=True`;`Type='Fog Glow'`、`Quality='High'` |
| 构建(复跑) | `跳过重接(幂等)` / `驱动总数 = 5(5 条未改动)` / `6 个旋钮全部 min/max/step 就位` / `插座提示 9 条` |
| 维护(复跑) | `CHANGED=0`、行为验收 `FAIL=0` |
| 结构 | 3 节点 / 2 连线;终结 `NodeGroupOutput`;`interface 输出插座 = [('Image','OUTPUT')]` |
| [0] 自证 | `1 个分量 × 1 个 8bit 台阶`,中点 `139.5000/255`(**见 §4.2**) |

### 撤回

* **只关效果、不删结构**:`辉光开关 = 0`(实测与"完全不加合成器"等价);
  或 `render.use_compositing = False`(总闸,极端眩光也 0 差异)。
* **整条摘掉**:`scene.compositing_node_group = None`
  (节点组本身留着,`use_fake_user` 已置,不会因无用户被存盘清掉)。
  视口要一并看不见,把 `shading.use_compositor` 设回 `'DISABLED'`。
