# 参数化弹出门与角色控制系统（单控制器驱动多子树、门旋转 + 角色位移）

> 来源：9877 桥工程实战（Blender 5.3，`261123.blend`）
> 适用：Blender 5.x，已建好的门/角色层级，不重建几何
> 关键词：EMPTY 控制器、自定义属性、SINGLE_PROP 驱动、rotation_euler、弧度、Slotted Action、多子树同步

## 零、一句话

把「门打开 + 角色弹出」做成同一个控制器：

```text
3点钟_弹出控制["弹出进度"] 0–10
  ├─ 3点钟方向 右门 Z 旋转
  ├─ 3点钟方向 左门 Z 旋转
  ├─ 3点钟方向 角色 Y 位移
  ├─ 10点钟方向 右门 Z 旋转
  ├─ 10点钟方向 左门 Z 旋转
  └─ 10点钟方向 角色 Y 位移
```

参数关键帧后来被用户调整为 `(30,0) → (75,10)`，两组动画在同一参数上同步。

脚本包：`../scripts/parameter-popup-door/`
Agent Skill：`../skills/blender-parameter-popup-door/SKILL.md`

## 一、场景

在装置场景中，两组方向各有三个子对象：

- 右侧门
- 左侧门
- 角色伸出

需求：

- 用一个空对象的中文参数 `弹出进度` 控制弹出
- 参数范围 `0–10`，打关键帧
- 门做 Z 轴旋转，角色做 Y 轴位移
- 3点钟方向与 10点钟方向复用同一个控制器，保持同步
- 不改动几何，只加驱动

## 二、总体架构

核心思想：**先抓当前位姿作为一端，再用上一次记录/用户确认的数据作为另一端，线性插值写进驱动表达式。**

```text
控制器自定义属性 p (0–10)
  └─ SINGLE_PROP 驱动变量 p
       ├─ 右门 rotation_euler.z = r0 + (r1-r0)*p/10
       ├─ 左门 rotation_euler.z = l0 + (l1-l0)*p/10
       └─ 角色 location.y    = y0 + (y1-y0)*p/10
```

## 三、对象与数据块清单

| 对象 | 型别 | 关键配置 | 作用 |
|---|---|---|---|
| `3点钟_弹出控制` | EMPTY | `弹出进度` 0–10，BEZIER 关键帧 | 总控制器 |
| `3点钟方向/右侧门` | EMPTY | Z 旋转驱动 | 右门 |
| `3点钟方向/左侧门` | EMPTY | Z 旋转驱动 | 左门 |
| `3点钟方向/角色伸出` | EMPTY | Y 位移驱动 | 角色 |
| `10点钟方向` 下三子对象 | EMPTY | 复用同一控制器 | 第二组门/角色 |

依赖：三条驱动 × 两组 = 6 条 SINGLE_PROP 驱动，全部指向 `3点钟_弹出控制["弹出进度"]`。

## 四、参数与端点

### 4.1 控制器

| 参数 | 范围 | 关键帧 | 作用 |
|---|---:|---|---|
| `弹出进度` | 0–10 | `(30,0) → (75,10)` | 两组弹出总控 |

### 4.2 3点钟方向端点

| 对象 | 通道 | p=0 | p=10 |
|---|---|---:|---:|
| 右侧门 | rotZ (rad) | 3.141592741 | 0.968994 |
| 左侧门 | rotZ (rad) | 0.0 | 2.207841 |
| 角色伸出 | locY | -8.837891 | -343.205627 |

角色 X/Z 不变，只改 Y，避免把角色传送走。

### 4.3 10点钟方向端点

| 对象 | 通道 | p=0 | p=10 |
|---|---|---:|---:|
| 右侧门 | rotZ (rad) | 0.0 | -2.775074 |
| 左侧门 | rotZ (rad) | 0.0 | 2.722714 |
| 角色伸出 | locY | 31.439859 | 31.018097 |

10点钟角色 Y 是递减，核验判据不能写成递增。

## 五、做法

### 5.1 先抓基线，不猜状态

执行前必须只读记录两组子树的：

- local location / rotation / scale
- world matrix / world translation / euler
- action 与 children

用户曾明确纠正“门=初始，角色=最终”，所以**当前场景状态不一定是起点**。必须先读，再让用户确认。

脚本：`probe_current_pose.py`、`capture_3oclock.py`、`capture_10oclock.py`

### 5.2 建控制器

```python
ctrl = bpy.data.objects.get("3点钟_弹出控制") or bpy.data.objects.new("3点钟_弹出控制", None)
ctrl["弹出进度"] = 0.0
ui = ctrl.id_properties_ui("弹出进度")
ui.update(min=0.0, max=10.0, default=0.0, description="弹出进度 0–10")
```

关键帧写入 Blender 5.x Slotted Action 时，优先直接写 `action.layers -> strips -> channelbags -> fcurves` 的 `keyframe_points`。

### 5.3 挂驱动

```text
driver = obj.driver_add("rotation_euler", 2).driver
driver.type = "SCRIPTED"
var = driver.variables.new()
var.name = "p"
var.type = "SINGLE_PROP"
target = var.targets[0]
target.id_type = "OBJECT"
target.id = ctrl
target.data_path = '["弹出进度"]'
driver.expression = "r0 + (r1 - r0)*p/10"
```

表达式中的 `r0/r1` 是**弧度常量**，不要套 `radians()`。

### 5.4 第二组复用

10点钟方向直接复用同一个变量路径，不再新建控制器。

### 5.5 核验

另起请求：

- 检查 6 条驱动 `is_valid=True`
- 端点逐帧对账
- 角色 Y 的单调方向按实际数据判定
- 子对象随父级移动
- 控制器关键帧位置与用户最终设置一致

## 六、使用说明（复用步骤）

1. 先跑 `probe_current_pose.py` 与 capture 脚本，写基线 JSON/TXT
2. 让用户确认哪一端是初始、哪一端是最终
3. 跑 `build_3oclock.py`
4. 若出现角度错误，用 `fix_radians_expr.py` 去掉误加的 `radians()`
5. 跑 `verify_3oclock.py`
6. 抓 10点钟当前状态
7. 跑 `build_10oclock.py`
8. 跑 `verify_10oclock.py`
9. 提醒用户 Ctrl+S

## 七、注意事项（坑）

1. **当前状态不一定是起点**：用户描述可能出现前后矛盾，必须以基线 JSON + 用户确认为准。
2. **弧度值不要再套 `radians()`**：基线本来就是弧度；套了会把角度除以约 57.3，驱动不报错但角度全错。只有手头是“度”时才转换。
3. **角色只改 Y**：X/Z 保持基线，否则不是弹出而是传送。
4. **第二组复用同一控制器**：不要复制控制器，否则两组无法同步。
5. **控制空物体无子级**：会被「空物体收敛清理」当作无用 EMPTY 删除，跨主题操作时必须保留。
6. **单调判据按数据方向写**：10点钟角色 Y 是递减，别套递增模板。
7. **驱动读值走 evaluated 数据**：同一次 exec 内改完立即读可能拿到旧值。
8. **Slotted Action 不能直接找 fcurves**：Blender 5.x 要遍历 layers/strips/channelbags。

## 九、Blender 5.x API 坑速查

| 问题 | 说明 |
|---|---|
| `AnimData.action_slots` | 5.3 用 `action_slot`，不是复数 |
| 自定义属性滑块 | 必须写 `min/max`，否则只是普通属性 |
| `SINGLE_PROP` 目标 | 先设 `id_type`，再设 `id` 和 `data_path` |
| 驱动求值 | 读结果用 `evaluated_get(depsgraph)` |
| 弧度常量 | 直接写进表达式，不要 `radians()` |
