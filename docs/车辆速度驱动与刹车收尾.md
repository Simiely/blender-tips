# 车辆速度驱动与刹车收尾

> 给「车在跑」的动画做一套**可调**的运动系统：一条速度曲线决定一切，改曲线不用重对构图。
> 实测环境 Blender 5.2.2 LTS / 9877 桥 / CYCLES。示例数据来自一段 30–150 帧的车行镜头。
>
> 配套：[Skill](../skills/blender-vehicle-speed-brake/) · [脚本包](../scripts/vehicle-speed-brake/) ·
> 传输层见 [Skill: blender-bridge-ops](../skills/blender-bridge-ops/)

---

## 0. 一句话

**速度曲线是唯一数据源 → 积分成位移 → 烘焙成关键帧 → 轮角由位移派生 → 相机补偿把末帧构图钉回原方案。**
调速度只改第一项，其余全部自动跟着走。

## 1. 为什么不能直接给位移打关键帧

因为"速度"和"位移"是两种东西，人调的是前者。
如果直接拖位移曲线，缓动形状和速度曲线**没有对应关系**：你看到的 `AUTO_CLAMPED` 曲线，实际速度是它的导数，两头慢中间快，用户没法表达"前快后慢降到某个值"。

所以：**用户调速度，机器算位移**。

## 2. 结构

```
控制_车速["速度倍率"]   ← 关键帧曲线，唯一"源"
        │ 数值积分（0.25 帧步长，梯形法）
        ▼
绑定_车辆根.location[0]  ← 逐帧烘焙，LINEAR，无驱动
        │ 位移派生（驱动）
        ▼
绑定_轮_*.rotation[1]    ← -(X0 - x) / R
        │
        ▼
控制_相机补偿.location[0] = (D - REF×∫total) × 进度
        │
        ▼
控制_车身.rotation[1] = 点头曲线 × 点头强度     ← 纯观感层
```

顺带的好处：全车只需要「关键帧 + 驱动」，**0 约束 0 修改器**，Bridge 里改起来最省事，也最容易回滚。

## 3. 积分与烘焙

### 3.1 常量

| 常量 | 怎么取 | 本例 |
|---|---|---|
| `X0` / `X1` | 原方案车根首末帧世界 X | 7.297282 / 2.621750 |
| `D` | `abs(X1 - X0)` | 4.675532 m |
| `REF` | `D / 原方案帧数` | 0.077926 m/帧 |
| `R` | **轮心 z − 地面 z** | 0.360 |
| 步长 | 0.25 帧（要能整除区间） | — |

`REF` 是"倍率 1.0 时每帧走多远"，是整个系统的**尺度锚点**。它必须绑在"原方案的时长"上，
不能绑在"这次烘焙的区间长度"上（见 §7 坑 1）。

### 3.2 积分

梯形法，0.25 帧步长，得到累计曲线 `cum(f)`，然后：

```python
dist(f) = REF * cum(f)
root.location[0] = X0 - dist(f)      # 车往 -X 方向跑
```

逐帧 `keyframe_insert` + 全部设为 `LINEAR`。为什么是 LINEAR：位移已经是积分结果，
再叠一层贝塞尔缓动等于二次平滑，速度就和你调的那条曲线对不上了。

### 3.3 区间

**取速度曲线自己的首末关键帧**，不要用 `scene.frame_start/end`。
用户经常把场景拉长去做静帧（本例场景 30–150，动画只到 105），用场景范围会让车在静帧段继续滑。

## 4. 轮角：零滑移的写法

```python
绑定_轮_*.rotation_euler[1] = -(X0 - rx) / R      # rx = 车根 LOC_X, WORLD_SPACE
```

任何速度曲线下都自动零滑移，不需要重新调轮子。

**`R` 必须取"轮心到地面"，不是包围盒半径。** 本例轮胎包围盒直径 0.728（半径 0.364），
但轮心 z=0.360、地面 z=0，轮胎底部沉进地面 4 mm —— 有效滚动半径是 **0.360**。
用 0.364 会让逐帧 `Δx/Δθ` 恒为 0.364，看起来"很一致"，其实每一帧都在打滑。

## 5. 相机补偿：末帧构图守恒

车速变了，车的总位移就变了，末帧构图必然偏。补偿思路：

```
相机要补的量 = 原总位移 - 新总位移 = D - REF × ∫total
施加方式      = 补偿量 × 进度          （进度是 0→1 的 S 曲线，在动画终点饱和为 1）
```

于是**最后一帧的相对构图与原方案逐位一致**（本例偏差 ≤ 3.9e−5 m），中途补偿不满，
所以减速在画面里看得见。

这条性质很值钱：**用户换任何速度档位，都不用重新对构图。** 主动讲给他们听。

## 6. 刹车：怎么造出「顿一下」

### 6.1 软和顿的分界是 jerk，不是位移

- **软**：速度从起刹点开始平滑衰减 ⇒ 减速度从 0 慢慢爬升 ⇒ 看起来像"滑行停稳"。
- **顿**：起刹那一帧，**减速度从 −0.3 直接跳到 −7 m/s²**。

做法是给起刹关键帧一个**斜率拐点**：进柄几乎水平、出柄猛压。

| 关键帧 | 值 | 左手柄 | 右手柄 |
|---|---|---|---|
| 30 | 1.000 | (24, 1.060) | (44, 0.820) |
| **92** | **0.680** | **(80, 0.740) 水平** | **(95.5, 0.260) 猛压** |
| 105 | 0.000 | (100, 0.000) | (110, 0.000) |

实测：逐帧倍率下降量 f92→f93 从 **−0.0048 跳到 −0.1127**（23 倍），
减速度 **−0.3 → −7.4 m/s²**，刹车行程 **32.4 cm**。真车急刹 7–9 m/s²。

### 6.2 行程的硬上限

15 帧 = 0.5 s，**刹车行程上限 ≈ `REF × 0.5s × 起刹倍率`**。
想让车"刹得住、看得见"，起刹帧就必须还带着速度 —— 这和"前快后慢降到很低"是矛盾的：

| 起刹倍率 | 中段 | 刹车行程 | 峰值减速度 |
|---|---|---|---|
| 0.80 | 8.42→6.73 km/h | 39.6 cm | 8.02 m/s² |
| **0.68** | **8.42→5.72** | **32.4** | **7.4** |
| 0.55 | 8.42→4.63 | ≈26 | ≈6.5 |
| 0.10 | 8.42→0.84 | 2.8 | 1.6（软） |

**先问用户要哪个，别替他选。** 本例第一版选了 0.10（保住"前快后慢"），
用户看完说"太软"，才换到 0.68。

### 6.3 单调性校验

改完曲线必须验 `spd(f) >= spd(f+1) - 1e-9`。曲线出现回升 = 车会往前窜一秒再继续减速。

## 7. 车身点头（刹车前倾）

### 7.1 必须拆成两个属性

**Blender 里一个属性不能既有关键帧又被驱动。** 想"乘一个系数"，只能：

```
控制_车身["点头曲线"]   ← 关键帧（形状 + 时机）
控制_车身["点头强度"]   ← 普通属性 + id_properties_ui 滑块（幅度）
        │ 驱动：dive * k
        ▼
绑定_车身.rotation_euler[1]
```

曲线定稿（本例）：

| 帧 | 值 | 说明 |
|---|---|---|
| 88 / 92 | 0 | 刹车前水平 |
| **96** | **−0.0100** | 峰值；× 强度 0.65 = **−0.37°** |
| 101 | +0.0045 | 回弹过冲（约峰值的 45%） |
| 105 / 112 | 0 | 归零 |

**下压宁小勿大。** 首稿给 −0.0314（−1.17°），用户上手改成 −0.0100，说更含蓄更真。
低速刹车（5.7 km/h）本来就不该点头 1° 以上，0.3–0.5° 足够读出重量感。

### 7.2 轴心与「会不会被拉伸」

- **轴心必须在轮轴高度**（本例车身空物体在 `(3.1649, 0, 0.363)`，z 正好等于轮心高度）。
  轴心在地面会变成"整车往前栽"。
- **非等比 scale 下动 rotation 是安全的**，因为子级的 `matrix_parent_inverse` 里有 `S⁻¹`：

  ```
  body.matrix_world · Mp⁻¹ = P·T·R·S · S⁻¹·T⁻¹ = P·T·R·T⁻¹   → 绕轴心的纯旋转
  ```

  但要**实测证伪**：取车身包围盒对角两点，转前转后量距离（本例 4.803540 → 4.803540，差 −8.7e−8）。
- **动 scale 会立刻破坏这个抵消关系**，车身被非等比拉开。rotation 可碰，scale 不行。

### 7.3 穿模必须实测

真正决定穿不穿的是"轮拱相对轮胎压下去多少"，不是角度本身。
量法：轮胎表面顶点（世界坐标、**当前帧**）→ 对每个车身网格 `closest_point_on_mesh` → 取最小距离。

| 强度 | 角度 | 间隙 |
|---|---|---|
| 0 | 0° | 3.95 cm |
| **0.65（定稿）** | **−0.37°** | **3.95 cm** |
| 1.00 | −0.57° | 3.95 cm |
| 2.00 | −1.15° | 3.39 cm |
| 3.00 | −1.72° | 1.78 cm |

外推：**间隙在 −2.35° 附近归零**，这就是该车型的物理上限。

**强度是相对系数**：基准曲线从 −0.0314 改成 −0.0100 之后，同一个强度对应的物理角度全变了。
首稿 max=1.15 是按旧基准卡的，换基准后 1.15 只到 −0.66°，用户想回到 −1.17° 得设 2.05 却被挡住。
**改基准必须重量间隙、重设 max。** 本例最终 max=3.0 / soft_max=1.5。

## 7.5 六个坑（按踩到顺序）

1. **烘焙归一化不能依赖区间长度**。`D / (F1 - F0) * cum` 在区间从 60 帧变 75 帧时，
   会把已有段整体压到 80%，静默改掉用户认可的部分。用常量 `REF = D / 原方案帧数`。
2. **自定义属性的 min/max 会真的钳制取值**，不只是限制滑块。
   `max=0.00` 之后写 `+0.0045` 读出来是 0，而 `fcurve.evaluate()` 明明是对的 ——
   症状是"某个动作整体消失但曲线看着正常"。
3. **一个属性不能既有关键帧又被驱动**（§7.1）。
4. **世界坐标采样点不能跨帧复用**。车在移动，拿 f105 采的轮胎点量 f96 的间隙，
   结果全是 0.0x mm 的假穿模，而且"不同幅度结果一模一样"就是它的指纹。
5. **非等比 scale 下要保距校验**（§7.2）。
6. **改完属性要 `update_tag()` + `view_layer.update()`**。桥内 Python 改自定义属性不触发依赖图刷新，
   驱动会读到旧值（老坑的新一次复现）。

## 8. 核验清单

1. 末帧构图三维相对位置 vs 基线，偏差 ≤ 1e−4 m
2. 零滑移：逐帧 `Δx/Δθ` 偏离 `R` 超 1e−4 的帧数为 0
   （末几帧位移只剩 1e−5 m 时会有浮点噪声，看该帧绝对位移即可排除）
3. 速度单调不增
4. 终点之后车 X / 相机 X / `进度` / 车身角全部冻结
5. 驱动 `is_valid` 全 True，变量 `data_path` 指向存在的键
6. `min(车体所有网格包围盒 z) > 0`（点头峰值那一帧最容易穿地）
7. 自定义属性读值 == `fcurve.evaluate(f)`（不等 ⇒ 坑 2 或没刷新）
