# 动画转移到父级空对象(动态转移)

> 来源: `E:\desktop\260910\游里屋顶街区模型\260910xBx01.blend` 实战(11,891 对象,相机 x02 由父级空对象带动公转)
> 适用: Blender 5.2 LTS
> 脚本包: [`scripts/anim-transfer-to-empty/`](../scripts/anim-transfer-to-empty/)

## 场景

某个对象(这里是**相机**)自己带着关键帧动画。每次调整它的运动都要给**它本体**K 动画,
本体上就堆了一串"大数字"位姿(loc 25.28 / rot 101.53°…),既难改也容易改坏。

**目标**: 把动态整份搬到新建的空对象上,让本体退化为"纯被驱动"节点。
要求 —— 搬完之后本体的**世界运动逐帧完全不变**,并且下次要加动态时一眼就知道该 K 哪个对象。

## 原理

世界变换恒等式:

```
matrix_world = parent.matrix_world @ matrix_parent_inverse @ matrix_basis
```

原世界运动 `M(t) = P(t) @ mpi_old @ B(t)`。分四步构造:

| 步 | 动作 | 效果 |
|---|---|---|
| 1 | 建空对象 **D**,与目标**同父级 + 同 `matrix_parent_inverse` + 同 basis** | `D.world(t) ≡ M(t)`(全部帧) |
| 2 | 把目标的 action **复制**给 D(独立副本 + 绑 slot) | D 完整复刻原世界运动,且可独立编辑 |
| 3 | 目标改挂到 D 下,摘掉自身动画,冻结成静态 basis | 目标不再自己动,改由 D 带动 |
| 4 | (推荐)在 D 与目标之间插一个**无动画基点空对象 B**,三者全用单位 MPI + 单位 basis | 本体本地变换彻底归零 |

**数学保证**(第 4 步插入基点后):

```
M'(t) = B.world(t) @ I @ I = D.world(t) @ I @ I = D.world(t) = M(t)     ← 恒等
```

乘单位矩阵是**精确**的(没有大数相消),所以这是最干净的形式。
若不插基点(`ZERO_TARGET=False`),目标直接挂 D 下,则需:

```
MPI = B(F)⁻¹ ,  basis = B(F)  =>  M'(t) = M(t) @ B(F)⁻¹ @ B(F) = M(t)   ← 恒等
```

> ⚠️ **通用解是 `B(F)⁻¹`(局部 basis 的逆),不是 `M(F)⁻¹`(世界矩阵的逆)。**
> 只有"参考帧 F 处局部 == 世界"(即 `mpi_old @ P(F) == I`,例如 F 帧父级 Z 旋转恰好为 0)时两者才相等。
> 自测实测: 构造一个参考帧处 `M(F)` 与 `B(F)` 相差 **6.35 单位**的场景,用 `B(F)⁻¹` 结果 **0 偏差**;
> 若误用 `M(F)⁻¹`,对象会被挪偏 6.35 单位。

## 最终层级

```
原父级
└── <目标>_动态     ← 承载原动画(独立 action 副本)
    └── <目标>_基点  ← 无动画空对象,单位 MPI + 单位 basis(纯静态底座)
        └── <目标>   ← 本地变换彻底归零(action=None,loc=0,rot=0,scale=1)
```

**为什么"基点"这一层值得加**: 本体本地全零后,打开 N 面板一眼可见"动态全在上游";
下次要加动态自然去 K **基点/动态空对象**,不会再误 K 本体。
且"乘单位矩阵"比 `B(F)⁻¹ @ B(F)` 少一次大数相消,精度反而更好。

## 做法

### 0. 先录基线(必做)

`verify_transfer.py` → `MODE='record'` → 得到 `//_anim_transfer_baseline.json`
(逐帧世界矩阵,相对 `//` = 工程文件目录)。

> 不录基线就无法证明"运动没变"。这是本方案唯一的验收依据,不能省。

### 1. 执行转移

`transfer_anim.py` 顶部改 `TARGET` / `FRAME`,跑一次。脚本内置:

- **前置自检**: 目标无 action → 报错退出;已存在同名 `_动态`/`_基点` → 报错退出(幂等保护);
  有约束/驱动 → 打印警告(本脚本只搬 action)
- **对齐断言**: D 与目标在参考帧世界位姿不一致就中止(说明父级/MPI/basis 没对齐)
- **后置粗检**: 打印层级、MPI、本体本地变换、`animation_data`、参考帧世界位姿差异

### 2. 存盘 + 逐帧验证

`Ctrl+S` 存盘(桥只改内存),再把 `verify_transfer.py` 的 `MODE` 改成 `'check'` 跑一次。

## 验证

转移前后逐帧对比世界矩阵(实测,参考场景坐标量级 ~25 单位):

| 阶段 | 旋转块元素最大差 | 平移分量最大差 | 角度偏差 |
|---|---|---|---|
| 插基点前的中间态(`B(F)⁻¹` 路径) | 1.192e-07 | 7.629e-06 | 1.741e-05 度 |
| **最终(插基点,单位阵相乘)** | **0.000e+00** | **0.000e+00** | 6.157e-06 度 |

→ 插基点这一步**把误差清零了**: 前者的舍入来自 `B(F)⁻¹` 与 `B(F)`(各含 ~25 量级分量)相消。

判读阈值:

| 指标 | 通过阈值 | 正常实测 |
|---|---|---|
| 位置分量最大偏差 | ≤ 1e-5 单位 | ~1e-6 量级 |
| 旋转块元素最大偏差 | ≤ 1e-6 | ≤ 1.19e-07(= float32 eps) |
| 角度最大偏差 | ≤ 1e-4 度 | ~1e-5 度 |

## 坑(逐条实测)

### 1. `obj.parent` 赋值会重置 `matrix_parent_inverse`(最容易翻车)

必须**先设 `parent`、再设 `matrix_parent_inverse`**。写反了会被静默清掉,
症状是对象飞到别处、且 MPI 平移回读为 `(0,0,0)`。
隔离实验(`blender --background --factory-startup`,逐项单测):

| 操作 | MPI 是否被重置 |
|---|---|
| 设 MPI → 再赋 `obj.parent` | **是,变 (0,0,0)** |
| 赋 `obj.parent` → 再设 MPI | 否 ✅ |
| 赋 `parent_type` | 否 |
| `animation_data_clear()` | 否 |
| 写 `location` / `rotation_euler` / `scale` | 否 |
| `scene.frame_set()` | 否 |

### 2. 新建/改动对象后必须 `view_layer.update()` 再读 `matrix_world`

否则读到单位矩阵 → `matrix_parent_inverse` 设成 identity → 子对象世界坐标 = 父位置 + 自身位置(翻倍偏移)。

### 3. 复制 action 只搬"被关键帧覆盖的通道"

没被覆盖的通道(如 `location[0]/[1]`、`rotation_euler[1]/[2]`)取的是**目标对象自己的静态 basis**。
所以"建 D → 同级 → 复制动画"这三步必须保证 D 的**静态 basis / 父级 / `matrix_parent_inverse`**
三者都与目标一致,否则复制过去是对不上的。脚本已自动快照并回填(含 `delta_*`)。

### 4. 5.2 Slotted Action: 复制后必须显式绑 slot

```python
new_act = src_act.copy()
new_act.name = '...'
ad = obj.animation_data_create()
ad.action = new_act
ad.action_slot = new_act.slots[0]      # 关键: 不绑 slot,曲线挂着但不生效
```

### 5. `animation_data_clear()` 不进 undo 栈

清之前先做备份: 旧 action 加 `use_fake_user = True` 保留成孤儿数据块,
随时可把 `ad.action` 指回去还原。**不要删 action 数据块**(删了就真没了)。

### 6. 验收指标别用 `2*acos(dot)`(会虚报 100 倍)

`dot ≈ 1` 时 acos 病态放大 —— 实测把 **3.8e-06** 的矩阵差虚报成 **0.0396°**,
差点误判成"有真实漂移"。改用:

- 旋转矩阵**元素最大差**(最直观),或
- 良态式 `2*asin(sqrt(x²+y²+z²))`,注意 `mathutils.Quaternion` **没有 `.vector` 属性**(用 `.x/.y/.z`)

### 7. 同一次 exec 内"改完立即验证"读到未刷新值

`matrix_world` 在 `view_layer.update()` 后通常可读,但涉及 action 求值的验证一律**另开一次请求**,
或以重开文件后的结果为准。验证器设计成 `record` / `check` 两次请求就是这个原因。

### 8. 参考帧怎么选

建议取**父级 Z 旋转为 0 的那一帧**(局部 == 世界),快照最干净、最无歧义。
`ZERO_TARGET=True` 下 `FRAME` 只影响快照取值,数学上任意帧都成立;
`ZERO_TARGET=False` 下参考帧决定 `B(F)`,必须与录基线时一致。
