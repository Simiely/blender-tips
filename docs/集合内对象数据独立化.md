# 集合内对象数据独立化 · Blender 5.2

> 把集合内「共享数据块」的对象转成**每个对象持有独立数据**,解决链接复制
> (linked duplicate)导致的"复制出去改一个、全跟着变"问题。
> 可复用脚本见 `scripts/make-independent/make_independent.py`。

## 场景

- 从 3ds Max / FBX / OBJ 等外部导入的场景,对象常以 **linked duplicate** 方式存在:
  多个对象共用一个网格数据块(如 `Mesh.537` 同时被 `组7912_GeomAdjust` 和 `组7913_GeomAdjust` 引用)。
- 症状:把对象复制/导出到别的工程后,它们仍然**共享数据块** —— 编辑其中一个的网格,
  所有副本一起变;单独导出某个对象,数据块还被多个对象引用,行为诡异。
- 排查方法(桥内探查):

  ```python
  import bpy
  col = bpy.data.collections['补充']
  meshes = [o for o in col.objects if o.type == 'MESH']
  print(len(meshes), len(set(id(o.data) for o in meshes)))
  # 43 个网格对象, 只有 21 个唯一数据块 → 有共享
  ```

## 原理

Blender 中「对象」和「数据块」是分开的:多个对象可以引用同一个网格数据块(实例化/链接复制)。
要"独立",就是把对象引用的数据块 `copy()` 出一份**独占副本**,再重新挂回对象:

```python
if o.data.users > 1:          # 被多个对象共享才需要处理
    o.data = o.data.copy()    # 复制数据块 → 该对象独享
```

- `users > 1` 判断是关键:本来就独占的数据块跳过,保证**幂等**可重跑;
- 只复制数据块,不改对象名 / 变换 / 层级 → **非破坏**;
- 材质默认保持共享(同一材质多处用是正常的);要连材质也独立,开 `MAKE_MATERIAL_UNIQUE`。

## 做法

1. 打开 `scripts/make-independent/make_independent.py`,改顶部 `COLLECTION` 为你的集合名。
2. 桥内执行 `python send.py make_independent.py`,或 Scripting 工作区 **Run Script**。
3. 看输出,独立化数量符合预期后 **Ctrl+S** 保存。

## ⚠️ 坑(实战踩的)

- **桥接 exec 时 `__name__` 是 `builtins` 不是 `__main__`**:
  脚本如果写 `if __name__ == '__main__': main()` 会**静默不执行**(桥端只回 `OK` 无输出)。
  所以本脚本直接调用 `main()`,**不用 `__main__` 守卫**。在 Scripting 工作区直接 Run Script 也一样。
- **判断共享用 `users > 1`,别只看数据块名**:`Mesh.537` / `Mesh.539` 这种带序号的名字
  不代表独立,可能同时被多个对象引用;`users` 才是引用计数。
- **只处理目标集合**:遍历 `col.objects`,集合外的对象即使共享同一数据块也不受影响,
  避免误伤其它用途的实例化对象。
- **运行后必须 Ctrl+S**:数据块复制发生在内存,不保存工程不落盘。

## 调试建议

- 想验证结果:重跑一次脚本,输出应显示 `独立化 0 个`(已全部独立);
- 只想处理选中的几个对象 → 把 `col.objects` 换成 `bpy.context.selected_objects`;
- 大规模场景(上万对象)建议按集合分批跑,避免一次卡死。
