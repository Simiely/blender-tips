# 面光渐变发光面：用 Parametric 画光带

> 来源：`261111xJ88G_animation_Extx01_03.blend` 实战（Blender 5.2.2 LTS / Windows / RTX 4070 SUPER，2026-11-12）
> 场景：一台车模的棚拍布光，24 盏面光里有十几盏靠"发光面渐变"控制光斑形状；
> 调参时出现"改什么都没反应"，排查后发现是取错了数据块。

---

## 0. 一句话结论

**面光要做出「面上有明暗分布」，坐标只能用 `几何.Parametric`（它对面积光输出平面映射 UV），
并且必须把 `自发光` 接到 `灯光输出.Surface`；开节点后亮度看 `自发光.Strength`，不看 `light.energy`。**

## 1. 节点链

```
几何数据.Parametric → 分离XYZ.X/Y → 渐变(ColorRamp) → 自发光.Color → 灯光输出.Surface
                                    ↑
                          自发光.Strength 决定亮度
```

- `分离XYZ.X` = 沿灯面宽（U）；`.Y` = 沿灯面高（V）。竖条用 X，横条用 Y。
- 色标位置 = 灯面上的百分比位置。**单条亮带**配方：`0.0 → 0` / `0.3 → 0.08` / `1.0 → 0`（B_SPLINE）。
- 亮度换算：`Strength ≈ P / (π·A)`（A = 灯面积 m²）。1×1 m 灯 50 W → 公式 15.9，实测约 13
  （色标非全白，偏低约 20%）。

## 2. 坑

### ★★★ 取灯必须走 `obj.data`，不能用 `bpy.data.lights[名]`

本工程的数据块名与对象名**错位**：

```
对象 面光.002      → 数据块 面光.004
对象 面光.003      → 数据块 面光.006
对象 灯光_左侧面光  → 数据块 面光.002   ← 按名字取会拿到这一盏
```

`bpy.data.lights["面光.002"]` 拿到的是**另一个对象的灯**（且它带灯链接、只照一个空集合），
于是"改什么都没反应"。正确入口：

```python
ob = bpy.data.objects["面光.002"]
L = ob.data                       # 真正的数据块
print(L.users)                    # >1 说明被多盏灯共用，改一处影响全部
```

### ★★★ 漏接 `灯光输出.Surface`，灯静默全黑

重建节点树时若把输出节点一起删掉、或没连上，灯完全不发光，但属性面板一切正常。
排查第一步就数连线。

### ★★ 输出节点插槽按名字可能取不到

`out.inputs['Surface']` 会抛 `KeyError`；按类型取更稳：

```python
surf = [s for s in out.inputs if s.type == 'SHADER'][0]
```

### ★★ 开节点后 `energy` 失效

改 `light.energy` 没有任何效果 —— 亮度在 `自发光.Strength` 上。

## 3. 验证（可证伪）

**不能看全幅平均亮度。** 把渐变从「左黑→右白」翻转成「左白→右黑」，
**总光通量不变，全幅均值必然一模一样**，会被误判成"渐变没生效"。

正确判据（二选一）：

1. **分半比较**：算画面左半/右半均值，翻转色标后两者应**互换**；
2. **单灯隔离**：其它灯全关，只留这盏，翻转色标看图案是否翻面。

## 4. 实测数据

| 项 | 数值 |
|---|---|
| 翻转型渐变 A/B 全幅均值差 | **0.000000**（完全相等，判据无效） |
| 同上，左右半比较 | A：0.016 / 0.071，B：0.024 / 0.063（方向相反） |
| 1×1 m 面光 50 W 等效 Strength | 公式 15.9 / 实测 ≈13 |
| 因取错数据块而白跑的 A/B | 11 次全部无变化 |
