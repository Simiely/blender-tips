## 1. 远程控制运行中的 Blender

**场景**:想让我(或脚本)直接操作你正打开的 Blender 实例。

**原理**:Blender 里跑一个 socket 监听脚本(桥),外部通过 `127.0.0.1:9877` 发 Python 代码,桥调度到**主线程**执行并回传结果。

**关键文件**:
- **本仓库可复用包**:`scripts/blender-remote-control/`(桥 + 发送器 + 示例 + README,跨机器直接用)
  - `blender_bridge.py` — 桥脚本(在 Blender Scripting 工作区运行)
  - `send.py <code.py>` — 客户端:发送文件内容到 9877 并回显
  - `example_probe.py` — 通用示例:探查场景相机及关键帧(兼容 4.x/5.x)
  - `README.md` — 完整说明:原理 / 环境核对 / 使用步骤 / 踩坑 / 常见问题
- 本项目实战脚本副本:`D:\workbuddy\2026-08-16-20-56-59\blender_control\`

**使用步骤**:
1. Blender → Scripting 工作区 → 文本编辑器 **Open** 打开 `blender_bridge.py` → **Run Script**(Alt+P)
2. 看到 `[Bridge v2] BRIDGE READY` 即成功
3. 外部:`python send.py setup_drivers.py` 即可远程执行

**⚠️ 坑**:
- `bpy.context` **只能在主线程访问** —— 后台线程直接 exec 会报 `'Context' object has no attribute 'active_object'`。桥必须用 `bpy.app.timers` 调度到主线程(每 0.05s 检查队列)。
- 重启 Blender 后要重新运行一次桥脚本(可注册为启动脚本自动加载)。
- 端口 9877(v2);旧版 9876 是线程版,已废弃但无害。

## 2. 自定义属性 + 驱动控制对象显隐

**场景**:用一个空物体的 0/1 开关(`vis`),批量控制 N 个子对象的**视口显示 + 渲染显示**,并支持打关键帧做显隐动画。

**设置驱动**(Python,经桥远程执行):

```python
import bpy
ctrl = bpy.data.objects['空物体']
children = [c for c in bpy.data.objects if c.parent == ctrl]

for child in children:
    for prop in ('hide_viewport', 'hide_render'):
        fcurve = child.driver_add(prop)
        drv = fcurve.driver
        drv.type = 'SCRIPTED'
        drv.expression = '1 - var'          # vis=1 显示,vis=0 隐藏(反了改 'var')
        for v in list(drv.variables):
            drv.variables.remove(v)
        var = drv.variables.new()
        var.name = 'var'
        var.type = 'SINGLE_PROP'
        var.targets[0].id = ctrl
        var.targets[0].data_path = '["vis"][0]'
```

**⚠️ 坑**:
- 直接改 `obj['vis'] = [0]` 后**驱动不重算**,必须 `ctrl.update_tag()` + `bpy.context.view_layer.update()` 才生效。**用户打关键帧走动画通道,自动刷新,无此问题**。
- `driver.evaluate()` 返回缓存值,验证要看属性本身(`c.hide_viewport`)。

## 3. 给自定义属性打关键帧

**场景**:给 `vis` 这类自定义属性做显隐动画。

**操作**(不用碰驱动编辑器):

**⚠️ 坑**:按 I 时鼠标必须悬停在属性数值上,否则插入的是别的属性。

## 4. Blender 5.2 Slotted Action API

**场景**:Blender 5.x 中读写对象的动画曲线/关键帧。

**关键变化**:新版动画用 **slotted action**,`action.fcurves` **不存在**了;ActionSlot 也没有 fcurves,`slot.handle` 是 int 句柄。

**正确用法**:

```python
action = obj.animation_data.action
fcu = action.fcurve_ensure_for_datablock(obj, 'location', index=0)  # index 必须关键字传参!
kfs = sorted(fcu.keyframe_points, key=lambda k: k.co[0])
for k in kfs:
    print(k.co[0], k.interpolation)
```

**⚠️ 坑**:
- `fcurve_ensure_for_datablock(datablock, path, index=i)` — **index 必须是关键字参数**,否则报错。
- 标准通道:location / rotation_euler / scale(各 3 条曲线)。
- 修改后无需额外刷新,依赖图自动更新。

## 5. 关键帧插值机制

**核心规则(官方手册确认)**:
> 关键帧的**插值模式 = 从该帧到下一个关键帧**之间的过渡方式。

- 段 N 的形状由**段首帧**的 `interpolation` 决定(LINEAR/BEZIER/CONSTANT…)
- **最后一个关键帧的插值不影响任何可见段**(只作用于其后的外插 Constant/Linear)

**推论**:
- 想"结尾段是直线" → 把**倒数第二个关键帧**设为 LINEAR
- 想"开头段是直线" → 把**第一个关键帧**设为 LINEAR
- 想整段平滑 → 段首帧 BEZIER(handle 保持 AUTO)

## 6. C4D 式"中间平滑+两头线性"的正确做法

**场景**:3 个关键帧,想要"中间平滑过渡、两头直线"(C4D 习惯;改 interpolation=LINEAR 会产生折角,不满足)。

**正确做法(手动,权威)**:
1. **中间关键帧**保持平滑不动(BEZIER / AUTO handle)
2. **两头关键帧**的 handle 类型改为 **FREE(自由)**
3. **手动把手柄方向拉到与线段方向平行对齐** → 段变直线

**效果**:起点直线出发 → 中间平滑过渡 → 终点直线到达,无折角。

**教训记录**:
- ❌ 改 interpolation=LINEAR → 段直线但关键帧处折角(尖角)
- ❌ VECTOR handle 自动拉直 → 用户不采用(缺少可控性)
- ✅ Free handle 手动对齐 = C4D 切线控制思维

**远程自动对齐思路**(可脚本化):帧首尾 handle 设为 FREE,并把 handle 坐标放在相邻关键帧连线上(方向平行),中间帧 handle 保持 AUTO。

## 7. 合成器与渲染输出(Blender 5.2 重点变化)

**场景**:渲染 720 帧输出 PNG 序列到指定文件夹。

### 5.2 的关键变化(与 4.x 不同)

| 项 | 4.x | 5.2 |
|---|---|---|
| 合成器节点树 | `scene.node_tree` | `scene.compositing_node_group` |
| 合成输出节点 | `CompositorNodeComposite` | **已移除**(渲染结果不再自动显示在查看器) |
| File Output 路径属性 | `base_path` / `file_slots` | `directory` / `file_output_items` |
| 输出文件名 | — | `{Directory}/{File Name}{Socket Name}{frame}.{ext}` |

### 输出 PNG 序列的正确配置(File Output 节点)

1. 合成器:Render Layers.Image → File Output.Image
2. File Output 节点属性(N 侧栏 → Node → Properties):
   - **Media Type = Image**(不是 Multi-Layer EXR,否则输出 .exr)
   - **Directory** = `//output/260817x01/`(相对 .blend;`//` 开头)
   - **File Name** = `frame_####`(`####` 自动变帧号)
   - 勾选 **Auto Extension**;格式 **PNG**
   - 槽(Images/Layers)勾选 **Override Node Format** 选 PNG(否则用节点级 EXR)
   - **Output Paths 面板**会显示最终路径,用于验证
3. 渲染:**Ctrl+F12(Render Animation)** 才输出全部帧;F12(Render Image)只写当前帧文件

### 渲染后查看器不自动显示结果(5.2 特有)

- 原因:5.2 移除 Composite 节点 → 合成器开启时渲染结果**不自动送进图像查看器**(显示透明/空白,要手动切)
- 方式 A(保留合成器):加 **Viewer 节点**(Output → Viewer)连到 Render Layers,查看器右上角切 **Viewer Node**
- 方式 B(回到默认):**移除合成器节点组**(见下"关键机制")→ 渲染结果像普通渲染一样自动显示;输出走渲染属性(路径 + PNG)

### 关键机制:合成器节点组 = 输出的开关(5.2,必读)

- **`use_nodes` 在 5.x 恒为 True,无法用 Python 关闭**(废弃属性,6.0 移除;`scene.use_nodes = False` 无效)
- **没有合成器节点组**(`compositing_node_group` 为空)→ 渲染结果按渲染属性路径**正常输出**(新工程默认,实测)
- **有节点组但节点树被清空** → "幽灵状态":合成器激活但无输出节点 → 渲染结果**不保存**(表现为"无法渲染")
- **移除空节点组 = 恢复默认输出**:
  - GUI:Outliner → 顶部过滤器切 **Blender File** 模式 → 展开 **Node Groups** → 选中"合成器节点" → `X` 删除
  - 脚本:`scene.compositing_node_group = None` + `bpy.data.node_groups.remove(grp)`(数据块操作,低风险)

### 双份输出(File Output + 渲染属性同时生效)

- File Output 节点与渲染属性路径同目录时,会**各输出一份**:File Output 文件名含槽名(如 `frame_0001Image.png`),渲染属性为 `frame_0001.png`
- **位深不同导致大小差异**:File Output 可 16-bit(文件约 2.7 倍大),渲染属性默认 8-bit
- 只保留一条:删 File Output 节点(保渲染属性)或清空渲染属性路径(保 File Output)

### RGBA PNG 打开显示透明

- 原因:PNG 带 alpha 通道且 alpha=0(透明背景),查看器/看图软件按 RGBA 显示 → 棋盘格
- 查看:图像编辑器显示切 RGB,或换看图软件
- 不需要透明背景:输出颜色模式改 **RGB**(不要 RGBA);或渲染属性 Film 关 Transparent

## 8. Cycles 渲染提速技巧(按性价比排序)

**场景**:720 帧 Cycles 大场景(13535 对象)渲染太慢,想提速。

### 🥇 首选:确认用 GPU 渲染(最大瓶颈)

- 渲染属性 → 设备(Device)→ **GPU Compute**(NVIDIA 选 **OptiX**,RTX 系最优)
- CPU → GPU 通常**快 5~10 倍**(4070 Ti Super:15s/帧 → 2~3s/帧)

### 🥈 开降噪 + 降采样(画质几乎不变)

- 渲染属性 → **降噪(Denoising)** 勾选,设备选 OptiX
- 采样 64 → **32**(或 16):64 采样 + 降噪 ≈ 200+ 采样无降噪的画质
- 收益:快 2~4 倍

### 🥉 其他技巧

| 技巧 | 操作 | 收益 |
|---|---|---|
| 降分辨率 | 分辨率缩放 100%→50% | 快 ~4 倍 |
| 减光程反弹 | 光程 → 最大反弹 4→2 | 快 20-40% |
| 关体积/景深/运动模糊 | 按需关闭 | 视场景 |
| 隐藏无关对象 | Outliner 点相机图标 | 视场景 |
| 终极方案 | 引擎切 EEVEE | 快 20 倍+(质量不同) |

### 断点续渲(改设置不重头)

1. Esc 停止渲染 → 2. 改设备/采样/降噪 → 3. 帧范围改为 `当前帧+1 - 720` → 4. Ctrl+F12
- 改设置对后续帧立即生效,已出帧不浪费

### 查看每帧渲染用时(详细)

**方式 1:系统控制台(实时看)**
- 中文菜单:**窗口 → 切换系统控制台**(弹出黑色控制台窗口)
- Ctrl+F12 渲动画时,逐帧打印:
  ```
  31:14.422  render | Saved: '...frame_0015.png'
  31:30.219  render | Saved: '...frame_0016.png'
  ```
  - `31:14.422` = **累计时间**(渲染开始到此刻,分:秒.毫秒),不是单帧用时
  - `Saved:` = 该帧已保存(路径乱码是控制台中文编码显示问题,实际文件名正常)
  - **单帧用时 = 相邻两行累计时间相减**(如 31:30.2 − 31:14.4 = 15.8 秒)
- 渲染结束会打印 **Total render time**(整批总用时)

**方式 2:命令行渲染落盘(可统计)**
- `blender -b 工程.blend --render-anim > render_log.txt 2>&1`
- 渲染完从日志提取每帧 `Time:`,可做平均/最慢帧统计

**注意**:F12(单帧)只有 1 条信息;逐帧滚动必须 Ctrl+F12(动画渲染)

## 9. 渲染白膜(材质覆盖,非破坏性)

**场景**:大场景(CAD 导入 5 万对象)想快速出白模图(clay render)检查模型轮廓与光照,不想改任何原材质。

**原理**:View Layer 的 **Material Override** —— 渲染时把所有对象材质临时替换成指定材质,原材质不动;出图后设回 `None` 即恢复。

**做法**(Python,经桥远程执行,Base Color=**60% 灰白**防过亮):

```python
import bpy

# 1) 白膜材质(灰白 diffuse,无金属无反射)
mat = bpy.data.materials.get("Clay_White") or bpy.data.materials.new("Clay_White")
mat.use_nodes = True
nt = mat.node_tree
for n in list(nt.nodes):
    if n.type != 'OUTPUT_MATERIAL':
        nt.nodes.remove(n)
bsdf = nt.nodes.new("ShaderNodeBsdfPrincipled")
bsdf.inputs["Base Color"].default_value = (0.6, 0.6, 0.6, 1.0)
bsdf.inputs["Roughness"].default_value = 1.0
bsdf.inputs["Metallic"].default_value = 0.0
out = next(n for n in nt.nodes if n.type == 'OUTPUT_MATERIAL')
nt.links.new(bsdf.outputs["BSDF"], out.inputs["Surface"])

# 2) 设置视图层材质覆盖
bpy.context.scene.view_layers[0].material_override = mat

# 3) 渲染(先设好 render.filepath,write_still 落盘)
bpy.ops.render.render(write_still=True)

# 4) 恢复原材质渲染:vl.material_override = None
```

**⚠️ 坑**:
- **无灯光对象的场景(CAD 导入常见,实测 0 灯光)**:渲染全靠世界光。确认 World 节点树有 **Sky Texture 并连接到 Background**——节点树里有 TEX_SKY 但未连线 = 孤立节点,世界只按默认灰照亮,白膜效果平淡。脚本自动补连:
  ```python
  w = bpy.context.scene.world
  sky = next(n for n in w.node_tree.nodes if n.type == 'TEX_SKY')
  bg  = next(n for n in w.node_tree.nodes if n.type == 'BACKGROUND')
  if not bg.inputs[0].is_linked:
      w.node_tree.links.new(sky.outputs[0], bg.inputs[0])
  ```
- 材质覆盖是**视图层级设置**,Eevee / Cycles 都生效;只在 F12 渲染体现,视口渲染预览不显示。
- 非破坏性:原材质不被修改,渲染完 `material_override = None` 即可恢复。

## 10. 时间轴整体前移

**场景**:最靠前的内容(如第一个相机动画)前面空了大量帧,想把**整个时间轴**(所有关键帧 + 标记 + 渲染范围)整体前移。

**做法**(远程脚本,经桥执行,先备份帧号 JSON):

```python
delta = 最早关键帧 - 目标帧          # 如 75 - 1 = 74
for o in D.objects:
    if not (o.animation_data and o.animation_data.action): continue
    act = o.animation_data.action
    for layer in act.layers:
        for strip in layer.strips:
            for cb in strip.channelbags:
                for fc in cb.fcurves:
                    for kp in fc.keyframe_points:
                        new = kp.co[0] - delta
                        if new < 1: continue      # 负帧保护:整体跳过(co+handle 都不动)
                        kp.co[0] = new
                        kp.handle_left[0] -= delta
                        kp.handle_right[0] -= delta
for m in C.scene.timeline_markers:
    m.frame = max(1, m.frame - delta)
C.scene.frame_end = max(1, C.scene.frame_end - delta)
```

**⚠️ 坑**:
- **负帧保护**:平移后 < 1 的关键帧必须**整体跳过**(连 handle 一起),否则产生负帧关键帧;单帧常量曲线(如 loc/rot/scale 只有 1 帧)跳过无影响
- 标记也要一起平移(`m.frame -= delta`),否则标记与动画内容错位
- frame_end 同步减 delta;frame_start 通常不变(目标帧=1)
- **同一次 exec 内改完立即验证会读到未刷新缓存值**(数值错误但数据实际正确)→ 必须用**新请求**重新读取验证

## 11. 关键帧小数帧的检测与修复

**场景**:时间轴/曲线编辑器里有关键帧显示在**整数刻度之间**("不在数字轴上",如 287.5)。

**原因**:
- 在 Graph Editor / Dope Sheet 里**拖动关键帧时未开启帧吸附(Snap → Frame)**,鼠标落在半帧位置放手 → 产生 .5 帧
- **探查脚本用 `int(round(kp.co[0]))` 统计会掩盖小数帧**:banker's rounding 把 361.5 显示成 362 → 误判"数据没变"

**检测**(必须输出精确值):

```python
for kp in fc.keyframe_points:
    f = kp.co[0]
    if abs(f - round(f)) > 1e-6:
        print(f"小数帧: {fc.data_path} @ {f}")
```

**修复**(吸附到整数帧,handle 同步保持形状):

```python
for kp in fc.keyframe_points:
    f = kp.co[0]
    if abs(f - round(f)) > 1e-6:
        d = round(f) - f
        kp.co[0] = round(f)
        kp.handle_left[0] += d      # FREE 手柄需手动;AUTO_CLAMP 自动重算
        kp.handle_right[0] += d
```

**⚠️ 坑**:
- **吸附目标要校验段间距**:如 914.5 吸到 914(保持 914→916 间距),不要机械四舍五入成 915;`.5` 用 Python `round()` 取偶数恰好正确(287.5→288、467.5→468、914.5→914、107.5→108)
- 小数帧不影响动画播放,只影响显示精度与后续对齐操作;不介意可以不管

## 12. 首尾帧交换与反转关键帧的真相

**场景**:把一段相机动画的首尾对调(镜头方向反转)。

**远程做法**(帧位置不变,首尾值互换):

```python
pts = fc.keyframe_points
if len(pts) >= 2:
    first, last = pts[0], pts[-1]
    first.co[1], last.co[1] = last.co[1], first.co[1]   # 交换值
    al = first.handle_left.copy(); ar = first.handle_right.copy()   # handle 必须 copy
    first.handle_left, first.handle_right = last.handle_left.copy(), last.handle_right.copy()
    last.handle_left, last.handle_right = al, ar
```

**GUI 做法(关键)**:**Blender 没有"反转关键帧"菜单项!** 正确操作是:
- 菜单 **关键帧 → 镜像**(快捷键 `Ctrl-M`)→ **沿时间轴关于当前帧**(先把播放头拖到动画中间帧)或 **沿时间轴关于时间 0**
- 官方文档:https://docs.blender.org/manual/en/latest/editors/graph_editor/fcurves/editing.html(Mirror 部分)

**⚠️ 坑**:
- "Reverse Keyframes" 是**错误记忆**(来自其他软件/旧版),Blender 官方文档与 API(bpy.ops.graph / bpy.ops.action)均无此操作,反转统一走 Mirror
- 多帧动画用"沿时间轴关于当前帧"镜像 = **整体反转**顺序(不只首尾);只想换首尾用远程脚本或手动拖

## 14. 大场景去重优化:重复网格合并为实例

**场景**:3ds Max 等导出的点位模型场景,数万对象,大量**同名网格**(如 `G-物体.001` ~ `.5251`)是同一几何复制出来的 → 文件大、加载慢、内存高。

**原理**:让重复几何的对象**共享同一个 mesh 数据块**(Blender 的实例化)。对象数量不变,数据块数量大减 → 内存/加载/依赖图全面优化。

**检测**(只读,经桥执行):
1. 类型分布:`Counter(o.type)` 看 MESH/EMPTY 占比,找大头
2. 同基础名分组:`re.sub(r'\.\d+$', '', m.name)` 统计变体数(有几百上千变体的就是重复候选)
3. **几何指纹**必须包含:**顶点坐标(取整) + 面顶点索引 + 材质名 + UV 层名** —— 全部一致才合并
4. **抽检验证**:取同簇 2~3 个数据块比对顶点坐标+面拓扑(指纹相同 ≠ 几何相同,必须真比对)

**合并**(经桥执行,先备份 .blend):

```python
groups = defaultdict(list)
for m in D.meshes:
    base = re.sub(r'\.\d+$', '', m.name)
    key = (base, vf(m), pf(m), mat_key(m), uv_key(m))   # 完整指纹
    groups[key].append(m)

remap = {}; to_delete = []
for key, ms in groups.items():
    if len(ms) > 1:
        base_mesh = ms[0]
        for m in ms[1:]:
            remap[m] = base_mesh
            to_delete.append(m)

for o in D.objects:                     # 1. 先重定向对象引用
    if o.type == 'MESH' and o.data in remap:
        o.data = remap[o.data]
for m in to_delete:                     # 2. 再删冗余数据块(users==0 才删)
    if m.users == 0:
        D.meshes.remove(m)
```

**效果(实测)**:63,233 对象场景,mesh 数据块 **9,079 → 3,803(-58%)**,对象数不变,材质 100% 保留,共享数据块覆盖 54,165 对象。

**⚠️ 坑**:
- **指纹必须含材质和 UV**:几何相同但材质/UV 不同,合并会改变外观
- **大场景全量指纹计算在桥内 >120s**:send.py 会报超时,**但桥实际会执行完**——重跑一次看结果(冗余 0 = 已完成),不要重复执行
- 合并后同组对象**共享数据,编辑一个全部同步**(对重复复制体是预期行为;要独立编辑的对象别合并)
- 这是**内存/加载优化,不是视口流畅度优化**——视口卡顿的主因是对象数量级(本场景 5.7 万 MESH 对象),对象数不变则视口操作改善有限
- 桥只改内存,记得 Ctrl+S(建议另存)

## 15. 挂载(parent)与轴心(origin)操作的位置保持

**场景**:把一批对象挂到空对象下打组、把空对象/原点对齐到子物体包围盒中心、或做"轴心居中"类操作,要求**子物体世界位置不变**。

**核心坑(Blender 5.x 实测)**:
- `child.parent = empty` 后 **matrix_parent_inverse 不自动设置(保持单位矩阵)** → 子对象世界位置 = 空对象位置 + 局部坐标
- 空对象在原点、物体在 (743,380) 时,挂载后世界位置变成 **743+743=1486(翻倍)**;后续撤销/再移动还会叠加偏移
- 症状表现:移动空对象 → 子对象跟着走(翻倍);局部坐标被反复重写(743 大数 ↔ 小数)

**正确做法(打组保持位置)**:

```python
# 1. 空对象先定位到目标位置(包围盒中心等)
e.location = center
bpy.context.view_layer.update()      # 刷新,否则 parent 用旧矩阵
# 2. 挂载
child.parent = e
# 3. 手动设置父逆矩阵 → 世界位置立即恢复,局部坐标=相对父级小数
child.matrix_parent_inverse = e.matrix_world.inverted()
```

**轴心/原点操作注意**:
- 移动空对象后子对象**跟随**(标准父级语义);要"只移空对象、子物体不动"必须同步更新所有子对象 mpi
- empty-align-center 类"轴心居中/贴底"操作同理:依赖 mpi 保持子物体,务必走"解除 parent → 改位置 → 重挂 + 手动 mpi"流程,不要直接改位置
- **验证挂载正确**:子对象 world 位置不变 ✓ + local 变为相对父级小数 ✓ + mpi 非单位矩阵 ✓

## 16. 循环渐变色(ColorRamp 三色自然循环)

**场景**:灯光/材质动画需要**无限循环的渐变波**(白黑白波、三色流光等),要求循环无缝、过渡线性、可滚动。

**原理(4 层逻辑,缺一不可)**:
1. **N 等分对称**:12 等分(13 端点)= 3 色 × 4 格,每种颜色占环的 1/3,对称均分
2. **同色连标 = 平台期**:3 个连续同色色标之间插值仍是同色 → 稳定色区(首尾色拆成 2+2 格,卷环后合并成 4 格)
3. **删过渡中点 = 线性过渡**:删除两平台之间的色标(如 2/12,6/12,10/12),过渡由两侧平台色标线性插值决定
4. **首尾同色 = 无缝循环**:渐变条两端同色,卷成环后 1 接 0 颜色连续,滚动无接缝

**实现(共享材质 + Mapping 偏移驱动,空对象静止)**:
- 节点链:纹理坐标(Object=控制空物体) → Mapping(**Scale Z=-1/周期**, **Location Z 关键帧=滚动**) → Separate XYZ(Z) → Clamp → ColorRamp(平台+过渡布局,LINEAR) → Principled Emission
- 滚动关键帧:Mapping Location Z **0→周期**(线性 + CYCLES 循环),**空对象不移动**
- **最小色标结构(6 个,推荐)**:1/12(A) 3/12(B) 5/12(B) 7/12(C) 9/12(C) 11/12(A) → 每平台只留 2 个端点色标
- **边界 0/1 可删**:ColorRamp 两端自动外推最近色标颜色 → A 平台跨循环边界(11/12→1→0→1/12)依然连续无缝
- 完整段结构:A 平台(外推 0~1/12)→ 过渡(1/12~3/12)→ B 平台(3/12~5/12)→ 过渡(5/12~7/12)→ C 平台(7/12~9/12)→ 过渡(9/12~11/12)→ A 平台(11/12~1 外推)

**⚠️ 坑**:
- **ColorRamp 插值类型 EASE 会"抖"**(过渡不平滑)→ 必须改 `interpolation = 'LINEAR'`(手动拖动色标可能把默认改成 EASE)
- 过渡区中间**别留色标**(会打断线性插值);平台段两端同色色标已足够,中间同色色标冗余可删
- 滚动用 **Mapping Location 偏移**,不要移动空对象(parent 会让子对象世界位置 = 父位置+局部,见 §15)
- 换色逻辑通用:等分数 = 颜色数 × 4;**最少色标数 = 颜色数 × 2**(每平台 2 端点);2 色 = 8 等分/6 色标,4 色 = 16 等分/8 色标

## 17. 圆柱贴图与理发店滚筒(含 Object 坐标/Driver 两大坑)

**场景**:对离散对象组(灯珠阵列)做整体圆柱投影贴图 + 螺旋条纹 + 旋转/上升动画。

**圆柱投影(标准做法,搜索确认)**:
- u = atan2(y, x) 归一化((atan2+π)/2π, 0~1 环绕一圈), v = 高度归一化((z-zmin)/高, 0~1)
- 螺旋条纹: f = u×K + v×N(K=环绕圈数, N=高度条纹数), **FLOORED_MODULO 1**(负数正确循环,避免 MODULO 负值导致底部"裁剪")
- 条纹方向: K:N 比例决定角度(1:4≈14°, 2:2=45°, 3:2≈56°);K=N 时 45°;方向反转用 SUBTRACT(u-v)
- ColorRamp 做条纹/灰度(黑/灰/白 三分法 = 等分+首尾同色循环)

**⚠️ 坑1:Object 坐标只跟随平移,不跟随旋转!**
- Texture Coordinate 的 Object 输出,移动空物体有效,但**旋转/缩放空物体不影响材质坐标**(实测 90° 旋转无变化)
- 要让条纹旋转:不能靠转空物体,必须**材质节点内偏移**(u 加偏移 = 绕柱旋转)
- 官方文档只说"变换物体可让纹理移动",但旋转实际无效(平移才生效)

**⚠️ 坑2:材质节点 driver 路径必须用 inputs[N] 数字索引**
- `driver_add('nodes["节点名"].inputs[1].default_value')` ✓ 成功
- `inputs["Location"]` 这种名称形式报 not found(5.2 bug)
- keyframe 同理: 用 inputs[1] 形式(见 §16)

**驱动式速度控制(用户改数字立即生效)**:
- 控制空物体自定义属性 rot_speed/up_speed + 对象级 driver:`frame * rot_speed / 360`(rotation/location driver 无材质路径问题)
- 或材质节点 driver:`frame * rot_speed / 360` 驱动 UOffset 节点 inputs[1]
