# 星芒散射光效系统（多尖角星芒散布 + 控制器参数化 + 相机/表面法线朝向）

> 来源：星芒工程实战（Blender 5.2 远程桥工程，Eevee / Cycles）
> 适用：Blender 5.2 LTS，Eevee + AgX + Bloom（Cycles 需另挂合成器 Glare）
> 关键词：几何节点、Instance on Points、Object Info、billboard、表面法线、Distribute Points on Faces、EMPTY 控制器、自定义属性驱动、循环关键帧动画

---

## 零、一句话

把一套「**参数化星芒 + 亮片散射**」做成一坨可复用的**数据块集合 + 控制空物体**：
调整 `星芒_控制器` 上的中文滑块即可改形状、大小、数量、贴面距离、动画。

两种朝向模式二选一：

| 模式 | 朝向来源 | 适用 |
|---|---|---|
| **billboard（面向观众）** | `物体信息(空物体)`，空物体挂在相机下 | 远景亮片、要始终正面朝镜头 |
| **表面包裹（贴壳）** | `面散布.Normal`（`Distribute Points on Faces` 输出） | 星芒贴着宿主表面朝外、可正负推离表面 |

> ⚠️ 两种模式的**选点链路不同**：billboard 模式用 `MeshToPoints`（点云），包裹模式**必须**用 `Distribute Points on Faces`（原因见 §5.5）。

---

## 一、场景

在活动场景中需要一组**闪烁的发光星芒亮片**，要求：

- 多个星芒（中央圆盘 + 6 个尖角）成片散布，有视觉厚度/层次
- 每个星芒**始终朝向相机**（billboard），不随视角翻转变扁
- 星芒形状（尖角长度 / 圆盘半径 / 基部半角 / 内凹程度）与**整体大小、脉冲动画**都能统一控制
- 只渲染散布出来的星芒，**源对象本尊不渲染**（源用于生成几何，不留在画面）


## 二、总体架构

核心思想：**「源对象」负责生成星芒几何（被隐藏），「散布节点组」负责把该几何实例化到点云各点并做朝向/缩放/偏移**。源对象缩放被散布实例继承，因此控制器一个参数就能同时控所有星芒的大小。

```
星芒(源, hide_render=True, 单面平面)
  └─ NODES 修改器「星芒_GN」  → 平面被生成成多尖角星芒几何(4 形状参数 socket)
  └─ 6 条驱动                 → Socket_0..3 由形状参数驱动; scale 由 实际大小/1000 驱动

球心_点云 / 2 / 3(宿主 MESH, 提供散布点位)
  └─ NODES 修改器「星芒_散布_GN 系列」 → 每宿主一组: 读「星芒」几何实例化 →
       沿相机朝向对齐 + 场景时间错相缩放 + 位置偏移
  └─ NODES 修改器「小球_分布_GN 系列」(可选, 小球/星芒可并存, 见 §七)

星芒_控制器(EMPTY, 6 中文滑块 + 循环动画)
  ↳ 驱动「星芒」4 形状 socket 与整体 scale
空物体(EMPTY, 挂在相机下 → 朝向参考)
  ↳ 散布节点组经 ObjectInfo(RELATIVE) 读它, 让每个实例对齐到朝向
```

调用链：`星芒_控制器.实际大小/形状参数` → `星芒`(源) 修改器 socket + scale → 散布节点组读源几何 → 点云各点实例化 → 朝向/缩放/偏移 → 渲染。


## 三、对象与数据块清单（都在「星芒_效果」集合）

| 对象 | 型别 | 关键配置 | 作用 |
|---|---|---|---|
| `星芒` | MESH | 单面平面(1 面/4 顶)；**`hide_render=True`**；NODES 修改器 `星芒_GN`；材质槽 `星芒_发光` | 星芒形状**源**，不渲染 |
| `星芒_控制器` | EMPTY | 6 中文属性 + Action `动态缩放_动画` | 统一参数面板 |
| `空物体` | EMPTY | 父级=`连廊相机x04_1-450`（挂在相机下） | billboard 朝向参考 |
| `球心_点云` | MESH | scale=1, loc=0；修改器 `小球_分布_GN` + `星芒_散布_GN_4` | 宿主 1 |
| `球心_点云2` | MESH | 同上；修改器 `小球_分布_GN_2` + `星芒_散布_GN` | 宿主 2 |
| `球心_点云3` | MESH | 同上；修改器 `小球_分布_GN_3` + `星芒_散布_GN_3` | 宿主 3 |
| `连廊相机x04_1-450` | CAMERA | 帧 1–450 机位 | 场景相机 |

依赖的数据块（复制时一起带走）：节点组 `星芒_GN`、`星芒_散布_GN`、`星芒_散布_GN_3`、`星芒_散布_GN_4`、`小球_分布_GN 系列`；材质 `星芒_金色`、`星芒_发光`；Action `动态缩放_动画`。


## 四、控制器参数 → 驱动映射

`星芒_控制器` 的中文自定义属性（键名即显示名，[技能 `材质参数统一控制器` 同款约定](材质参数统一控制器与实时面板.md)）：

| 参数 | 默认(实况) | 作用 | 驱动目标 |
|---|---|---|---|
| `尖角长度` | 96.0 | 星芒尖角长度 | `星芒` 修改器 `星芒_GN` `Socket_0` |
| `圆盘半径` | 12.0 | 中央圆盘半径 | `Socket_1` |
| `基部半角` | 5.0(接口默认13) | 尖角基部半角 | `Socket_2` |
| `内凹程度` | 1.0 | 尖角内凹程度 | `Socket_3` |
| `实际大小` | 5.0 | 星芒整体大小基准 | 源 `星芒` `scale` = `实际大小/1000`（正确式应 `+ 动态缩放/1000`，见 §七坑②） |
| `动态缩放` | -0.45（动画）| 循环脉冲缩放（应叠加到整体大小） | 源 `scale`（当前仅 `实际大小` 生效） |
| ★ `生成数量` | 220 | 星芒颗数（期望值，±3% 随机波动） | `星芒_散布_GN` 内 `生成数量_N` 的 **Value 输出**，表达式 `floor(x + 0.5)` |
| ★ `法线距离` | 0.0 | 沿表面法线**正负推离**表面（米） | `星芒_散布_GN` 内 `法线距离` 的 **Value 输出**，表达式 `x` |

形状 4 参数用 **SCRIPTED 驱动**，表达式 `x`（SINGLE_PROP 变量指向控制器属性值）；整体大小用 `实际大小/1000`（当前）。`动态缩放_动画` 为 30 帧三角波关键帧（`(1,-0.45)→(16,0.1)→(31,-0.45)`）+ **CYCLES 循环修饰器**铺满 1–450 帧，写在控制器 Action 里。

★ 后两个参数（`生成数量` / `法线距离`）是**包裹模式**新增，**都驱动节点组内部的 `Value` 节点，不驱动修改器 socket**（原因与实测见 §5.6）。

读属性/驱动值时**必须走 depsgraph**（`dg.evaluated_get(obj).scale`），直接读内存对象可能拿到缓存值（[技能 `blender-bridge-ops`](../skills/blender-bridge-ops/) 铁律）。


## 五、几何节点结构

### 5.1 `星芒_GN` —— 源对象的形状生成器（41 节点）

挂在 `星芒` 源上的 NODES 修改器。把单面平面重建成星芒：

```
组输入(尖角长度/圆盘半径/基部半角/内凹程度)
  → 二次型贝塞尔×2 + 曲线圆环(Circle)        (6 尖角骨架 + 中央圆盘)
  → 填充曲线/点转曲线/重采样/设置样条线闭合/曲线转点
  → 实例化于点上 × 旋转实例(ROTATE_INSTANCES) (尖角沿圆环阵列)
  → 实现实例(REALIZE) → 合并几何体 → 设置材质(Set Material→星芒_金色)
  → 组输出(Geometry)
```

接口输入：`尖角长度=96`、`圆盘半径=12`、`基部半角=13`、`内凹程度=1.0`、`动态缩放=1.0`（末 socket 当前未连线，用默认 1.0）。**「动态缩放」接口输入与「实际大小」是两套作用点**：`实际大小`走对象 scale（继承给实例），接口里的 `动态缩放` 属星芒_GN 内部预留。

### 5.2 `星芒_散布_GN` 系列 —— 散布器（32 节点 ×3 份，结构相同）

三宿主各一份独立节点组（`星芒_散布_GN`=点云2、`_3`=点云3、`_4`=点云），差异只在**位置偏移**方向。

接口：`Geometry`(出入) + `生成数量`(Int, 默认 50)。

主链：

```
组输入.Geometry(宿主点云)
  → 网格转为点(MeshToPoints)
  → 随机值+编号 → 运算(阈值) → 分离几何体(Selection 筛选)
  → 设置位置.002(SET_POSITION, Offset=合并XYZ.002 位置偏移)
  → 实例化于点上(Instance=变换几何体←物体信息[星芒,RELATIVE],
                   Scale=合并XYZ.001, Rotation=对齐欧拉至矢量[空物体])
  → 实现实例(REALIZE) → 组输出
```

关键接线（探测实况）：

| 输入 | 来源 | 含义 |
|---|---|---|
| IOP.Instance | 变换几何体 ← **物体信息(星芒)** space=**RELATIVE** | 取源星芒几何（带动画/缩放）当实例 |
| IOP.Scale | **合并XYZ.001**（X/Y/Z ← 运算.007） | 场景时间→运算链错相缩放 |
| IOP.Rotation | **对齐欧拉至矢量 ← 物体信息(空物体)** | 每个实例朝向相机下的空物体（billboard） |
| IOP.Selection | 未接线 | 数量筛选在分离几何体处做死 |
| SET_POSITION.002.Offset | **合并XYZ.002** | 施加在实例化**之前**的点上，避免被实例缩放放大 |

三组的位置偏移（合并XYZ.002 常量，X/Y/Z）：

| 节点组 | 宿主 | 偏移 |
|---|---|---|
| `星芒_散布_GN` | 球心_点云2 | (-0.0065, **-0.0076**, 0) |
| `星芒_散布_GN_3` | 球心_点云3 | (-0.0065, 0, **-0.0076**) |
| `星芒_散布_GN_4` | 球心_点云 | (-0.0065, **+0.0076**, 0) |

另有 `合并XYZ`（X/Y/Z=**0.12**）作星芒实例**基准缩放**常量。

### 5.3 缩放动画链（场景时间 → 错相）

实例缩放走 **Scene Time → SINE → MULTIPLY → ADD 运算链 → COMBXYZ.001 → IOP.Scale**，配合随机值给每点不同相位，实现**颗颗错峰脉动**（Geometric Nodes 里做，依赖 SceneTime，独立于对象级 scale 驱动）。源对象级 scale 再由控制器 `实际大小` 统一放大——两层相乘得出最终尺寸。

### 5.4 材质

- `星芒_金色`（散布星芒可见材质）：Emission **Color=(1,1,1,1) 白**，**Strength=5**。改色直接改它。
- `星芒_发光`：源网格材质槽，无发光节点（源已隐藏，不参与画面；历史遗留）。

### 5.5 表面包裹模式：`Distribute Points on Faces`

**为什么不能沿用 `MeshToPoints`**：实测 `网格 转为 点(FACES)` 输出的点云**没有 `normal` 属性**——点云属性表只有 `position` / `.edge_verts` / `.corner_vert` / `.corner_edge`。于是：

- `几何节点输入法线(InputNormal)` 在点域读到 **0**
- `命名属性('normal')` 读到 **0**
- `捕获属性(domain='FACE')` 也传不到点域

**可证伪的判据**：把 `法线距离` 从 0 改到 ±2 m，评估包围盒**逐位不变**（`18.831 × 11.379 × 4.302` 四个档位完全相同）⇒ 法线根本没接上，不是“距离太小看不出来”。

**正解**：`Distribute Points on Faces`（`distribute_method='RANDOM'`）的输出自带 `Points` / `Normal` / `Rotation`，`Normal` 是**节点显式输出**，不是点云属性，因此直接可用。

链路：

```
组输入.Geometry
  → 面散布(Distribute Points on Faces, RANDOM, Seed=3, Density=数量/表面积)
  → 设置位置(Offset = 随机抖动 + Normal×法线距离)
  → 实例化于点上(Instance=物体信息[星芒,RELATIVE],
                  Rotation=对齐欧拉至矢量←面散布.Normal,
                  Scale=场景时间错相链)
  → 实现实例 → 组输出
```

关键接线：

| 输入 | 来源 | 说明 |
|---|---|---|
| `面散布.Mesh` | 组输入.Geometry | 宿主网格 |
| `面散布.Density` | `密度换算` = `生成数量_N / 表面积` | RANDOM 模式**只有 `Density`**；`Density Max` 只在 Poisson 模式存在，按名取会 `KeyError` |
| `对齐欧拉至矢量.Vector` | **`面散布.Normal`** | 实例 +Z 对齐表面**外**法线（星芒平面在 XY，其法线即 +Z） |
| `法线距离_缩放.Vector` | **`面散布.Normal`** | `VectorMath(SCALE)`，Scale = `法线距离` |
| `设置位置.Offset` | `法线距离_相加` = 随机抖动 + 法线×距离 | 仍施加在**实例化之前** |

**法线距离**：正=外推、负=内嵌、0=贴面。实测（宿主 bbox `18.793 × 11.078 × 5.045`，表面积 `190.238`）：

| 距离 | 评估 bbox 尺寸 |
|---|---|
| −0.5 | 18.347 × 10.240 × 4.205 |
| 0 | 18.897 × 10.665 × 4.900 |
| +0.5 | 19.558 × 11.196 × 5.709 |
| +1.0 | 20.319 × 11.787 × 6.517 |

单调扩张 ⇒ 法线朝外、方向正确。

**表面积从哪来**：`sum(pl.area for pl in host.data.polygons)`。前提是宿主 `loc/rot/scale` 已烘焙成单位变换，否则面积与实际几何的米制比例不一致，数量会整体偏。

### 5.6 数量驱动：节点内 `Value`，不驱动修改器 socket

旧结论（§七坑⑤）是“EMPTY 属性驱动几何节点 socket 不稳”，于是把 `生成数量` 留在修改器面板。**更可靠的做法是把数量搬进节点组内部**：

```
ShaderNodeValue「生成数量_N」(默认 220)
  → Math(DIVIDE, B=表面积) → 面散布.Density
```

驱动挂在节点树的 `Value` 输出上（与 4 个形状参数同一套路）：

```python
path = 'nodes["生成数量_N"].outputs[0].default_value'
fc = ng.animation_data_create().drivers.new(path)
d = fc.driver
d.type = 'SCRIPTED'
d.expression = 'floor(x + 0.5)'
v = d.variables.new()
v.name = 'x'
v.type = 'SINGLE_PROP'
t = v.targets[0]
t.id_type = 'OBJECT'
t.id = ctrl
t.data_path = '["生成数量"]'
```

三条纪律：

1. **同时移除 interface 里的 `生成数量` socket**（`ng.interface.remove(item)`）。否则修改器面板上会留一个“能拖、但没人读”的**假控件**——这正是“改了参数没效果”的典型来源。
2. `floor(x + 0.5)` 保证拖出小数时按整数取期望颗数。
3. 改控制器后 `ng.update_tag()` + `ctl.update_tag()` + `view_layer.update()`；颗数走 `host.evaluated_get(dg)` 读，不能直接读原对象。

实测：220 → **224 颗**、500 → **483 颗**，还原 220 → **224 颗**；驱动 `is_valid=True`。

> 数量是**期望值**：`Density × 表面积` 的随机投放有 ±3% 波动（224/220 = +1.8%，483/500 = −3.4%）。要绝对精确得改成按索引等距取样，但会失去随机分布。

### 5.7 复杂宿主：安全生成低模包裹（百万级面片）

适用：宿主是复杂装置（真实案例 `Arc015.001`：523 万顶点 / **1040 万面** / 62680 条边界边），需要 1000 面以内、带内凹的包裹壳。

> ★★★ **红线：不要在桥里对原始大网格做 Remesh / Decimate。**
> 实测 1000 万面 Voxel Remesh 直接超过桥的 **120 s 硬超时**，并把 Blender 主线程拖死 → 进程僵死（`Responding=False`、内存停在 ~350 MB、CPU 不再增长），此后**连 `--factory-startup` 启动都卡在 UI 初始化**，只能重启电脑。
> 桥是主线程 `exec`，重活没有并行余地；这类操作要么先减面，要么走 `blender.exe --background`（见 `skills/blender-headless-batch`）。

安全的四步流程（实测 5.2 万面源、总耗时 **< 3 s**）：

| 步骤 | 做法 | 实测 |
|---|---|---|
| ① 先减面 | 在 GUI 里把宿主手动 Decimate（D 盘工程 523 万顶点 → 3.86 万顶点 / 5.2 万面） | 用户手动完成 |
| ② 复制 + 烘焙变换 | `obj = src.copy()` + `obj.data = src.data.copy()`，再 `data.transform(src.matrix_world)`、`matrix_basis = Identity` | 0.0 s（5.2 万面） |
| ③ Voxel Remesh | `modifiers.new('R','REMESH')`、`mode='VOXEL'`、`voxel_size=0.06` | 12264 面 / 0.4 s |
| ④ 迭代 Decimate | 每轮**先读当前面数**再算 `ratio = 目标 / 当前` | 12264 → 1926 → 994，1.7 s |
| ⑤ 法线外扩 | `recalc_face_normals` → 顶点沿法线 +0.02 m | 994 面 / 1292 顶点 |

关键点：

- **③ 的作用是把多块薄壳变成封闭流形**，否则 ④ 会卡住（见坑⑯）。
- **④ 的 `ratio` 与实际降幅不一致**，必须循环「读面数 → 算 ratio → apply」，不能一次设置到位（实测 `ratio=0.0799` 从 12264 → 1926，`ratio=0.5088` 从 1926 → 994）。
- **⑤ 外扩后要按“最近点法线”核验穿出**，不能只看 bbox（见坑⑱）。实测 994 面壳：穿出 **47.9%**、最近距离中位 **0.0588 m**、最大 **0.707 m** —— 低模壳对复杂装置必然有局部穿插，靠星芒的 `法线距离` 外推 0.05~0.1 m 补偿即可。

### 5.8 在「位置」集合的空对象上布星芒（可手动移动）

需求：集合 `位置` 里有 N 个 EMPTY（实测 19 个 `空物体.006~.024`），**每个位置放 1 颗星芒**，用户移动空对象时星芒跟随。

> ★ **Empty 不能挂修改器**（`empty.modifiers.new(...)` 返回 `None`），所以不能“给空对象加 GN”。
> 正解 = **子对象**：复制源 `星芒`，父级设为对应 Empty。

```python
o = src.copy()                    # 共享源 mesh + GN 修改器
o.parent = empty
o.matrix_parent_inverse = Matrix.Identity(4)
o.location = (0.0, 0.0, 0.0)       # 世界位置 = Empty 位置
o.hide_render = False             # ★ 复制会带上源的 hide_render=True
o.visible_camera = True
```

**闪烁**：复制对象会**继承源的 scale 驱动**，要先 `animation_data_clear()`，再按索引重建 3 条：

```python
expr = 'a * (1 + %.3f * sin(frame * %.1f + %.3f))' % (AMP, SPEED, i * 0.7)
# a = SINGLE_PROP → 控制器["实际大小"]；frame 是 5.2 驱动内建变量
```

实测：基准 0.25、AMP 0.35、SPEED 3.0（周期约 2 s），两颗在帧 1/5/10/15/20 的 scale 分别是 `0.262→0.307→0.164→0.324→0.223` 与 `0.204→0.251→0.193→0.337→0.176`，**相位确实错开**。

**朝向**：对象级可以加 `DAMPED_TRACK`（几何节点实例不行，见坑⑥）：

```python
c = o.constraints.new('DAMPED_TRACK')
c.target = bpy.context.scene.camera
c.track_axis = 'TRACK_Z'          # 星芒平面法线是 +Z
```

三者叠加：**父级负责位置**、**对象级 scale 驱动负责闪烁**、**DAMPED_TRACK 负责朝向**。移动 Empty 时三者全部跟随。

**专用控制器（必须放在用户操作的集合里）**：这批星芒最初复用 `星芒_控制器`（它在 `星芒_效果` 集合），用户反馈“控制器找不到”。正解是给它们建一个**独立控制器 `位置星芒_控制器`**，直接放进 `位置` 集合（位于 19 个空对象中心上方 1.2 m），参数与被驱动对象同屏可见：

| 参数 | 默认 | 作用 |
|---|---|---|
| `基础大小` | 0.25 | 星芒基准尺寸（米） |
| `闪烁幅度` | 0.35 | ±35%，设 0 即完全不闪 |
| `闪烁速度` | 3.0 | 角速度，约 2 s 一个周期 |

驱动表达式改为三变量：

```
base * (1 + amp * sin(frame * spd + 相位))     # 相位 = i × 0.7，每颗错开
```

实测 19 颗 × 3 条 = **57 条驱动全部 `is_valid=True`**；帧 1/10/20 两颗为 `0.262/0.164/0.223` 与 `0.204/0.193/0.176`。参数有效性判据：`闪烁幅度=0` 时帧 1 与帧 10 **恒定 0.250**，改回 0.35 立刻恢复波动。

### 6.3 用脚本审计状态 / 修复 scale 驱动

见可复用脚本包 [scripts/starburst-scatter/](../scripts/starburst-scatter/)（`probe_star.py` / `verify_star.py` / `fix_star_scale.py`）：
- `probe_star.py`：只读 dump 控制器 6 参数、源驱动/scale 表达式、三宿主散布偏移、生成数量。
- `verify_star.py`：独立核验关键不变量（源隐藏渲染、ObjectInfo 空间、偏移、scale 表达式、控制器动画关键帧）。
- `fix_star_scale.py`：把源 scale 3 条驱动表达式重置为 **`实际大小/1000 + 动态缩放/1000`**（幂等，恢复控制器 `动态缩放` 对整体大小的影响）。

> ⚠️ 这三个脚本的断言是 **billboard 模式**的（检查 `对齐欧拉至矢量 ← 空物体`、固定偏移、修改器面板数量）。**包裹模式**结构不同（`← 面散布.Normal`、`生成数量` 驱动在节点内、`法线距离` 在 Offset 里），直接套会误报，需按 §八 的两项包裹模式检查另写断言。


## 七、注意事项（坑）

1. **源隐藏渲染，散布照常**：`星芒.hide_render=True` / `visible_camera=False`，但散布实例走节点组评估，**不受影响**（保留 `hide_viewport=False`，视口可继续看到生成用的源几何）。
2. **scale 驱动表达式的先后版本**：正确完整式是 `实际大小/1000 + 动态缩放/1000`（`动态缩放` 参与整体大小）。**实况已退化为只 `a/1000`**（`b` 变量在但未进表达式）→ 控制器上的 `动态缩放_动画` 目前不影响大小。若要脉冲动画生效，用 `fix_star_scale.py` 恢复，或直接改表达式。核验时读**评估** scale，确认 `实际大小×?`。
3. **Object Info 必须 RELATIVE**：`物体信息(星芒)` 用 RELATIVE 才能继承源对象 scale（`实际大小` 参数由此对每个实例生效）；改成 ORIGINAL 会**忽略源缩放与动画**（源 scale 驱动形同虚设）。
4. **位置偏移要放在实例化之前**：用 `设置位置(SET_POSITION)` 施加在分离后的**点**上、再进 `实例化于点上`；若直接给 IOP 的 Position/Scale 改，偏移会被实例基缩放大、方向错乱。
5. **生成数量别驱动“修改器 socket”，要驱动“节点内 Value”**：用 EMPTY 自定义属性直接驱动几何节点 socket **不可靠**（depsgraph 读缓存值，如 288.0；实测驱动 `is_valid=True` 但评估网格颗数不变）。**正解见 §5.6**：数量放进节点组内部的 `ShaderNodeValue`，驱动挂 `nodes["生成数量_N"].outputs[0].default_value`（与 4 个形状参数同一套路，实测 220→224 / 500→483 立即生效）。搬完**必须移除 interface 里的同名 socket**，否则修改器面板会留一个能拖但没人读的**假控件**。
6. **朝向有两种来源，别混用**：**包裹模式**读 `面散布.Normal`（实例 +Z 对齐表面外法线）；**billboard 模式**读 `物体信息(空物体, RELATIVE)`，`空物体` 必须**挂在相机下**（随机位走），别直接指向相机（相机不在节点树几何内）。两者都必须在**几何节点内**做——对象级 DAMPED_TRACK 等约束**不作用于实例化对象**（[仓库相关原则](驱动式Z轴匀速旋转系统.md)同源）。
7. **多份散布用独立节点组**：三个宿主各一份独立散布组（不是复制修改器引用同名组），各自偏移/数量隔离，改一处不串扰。修改器 input 不可迭代（`mod.properties.inputs` 是 `GeometryNodesInterfaceInputs`，访问用 `.get(名字)` / 属性访问，`enumerate(...)` 会抛异常）。
8. **细节联动**：源 `星芒` 是 1 面平面+GN 修改器生成形状——改源材质/几何请在修改器/材质里改，别在源平面布线；删源会断散布。`星芒_金色` 认定颜色以**接在 Active Output 上的 Emission** 为准。控制器 `动态缩放` 键名即中文 UI（键即显示名）。
9. **写/验分两次请求**：同一次 exec 里改完立即读会拿到刷新前的缓存；改后 `obj.update_tag()` + `view_layer.update()`，另起一次请求核验（桥 120s 超时先用 powershell 不带 BOM 落盘）。
10. **备份先行**：对 `.blend` 的修改（尤其驱动、修改器）先做带时间戳备份；`fix_star_scale.py` 只改驱动表达式、幂等，可安全重跑。
11. **★ `Mesh to Points` 的点云没有 `normal` 属性**：`网格 转为 点(FACES)` 的输出属性只有 `position` / `.edge_verts` / `.corner_vert` / `.corner_edge`。所以 `输入法线`、`命名属性('normal')`、`捕获属性→点域` 三条读法**全部读到 0**。**判据**：法线距离从 0 改到 ±2 m，包围盒**逐位不变**（不是幅度太小）。要沿表面法线做朝向/偏移，**必须**换 `Distribute Points on Faces`（§5.5）。
12. **★ `Distribute Points on Faces` 的 RANDOM 模式没有 `Density Max`**：节点输入在 RANDOM 下是 `Mesh / Selection / Distance Min / Density / Density Factor / Seed`，`Density Max` 只在 **POISSON** 模式出现；按名字取会 `KeyError: 'Density Max' not found`。密度 = `生成数量 / 表面积`。
13. **★ 按名字找节点，不能“找不到就回退到第一个”**：写改造脚本时用 `cands[0] if cands else None` 做兜底，会让第二个 `VectorMath` 复用第一个节点（因为名字还没设上），随后两个运算**指向同一节点、`in1 ← 自己的输出`形成自环**，求值静默出错。**正解**：命名后重新查找，找不到就**新建并命名**，绝不回退到同类节点的第一个。
14. **★ `ng.links.remove(l)` 之后访问 `l.from_node` 会抛 `ReferenceError`**：要先存 `src = l.from_node.name`，再删链接。批量改线时代码里同时有 `print(l.from_node...)` 最容易踩（同一坑一次脚本里踩了两次）。
15. **★★★ 百万级网格的 Remesh / Decimate 绝对不要走桥**：实测 1000 万面 Voxel Remesh 超过 **120 s 硬超时**，Blender 主线程被拖死 → 进程僵死（`Responding=False`、内存停在 ~350 MB、CPU 不再增长），此后**新进程连 `--factory-startup` 都卡在 UI 初始化**，只能重启电脑（未存盘改动全丢）。正确做法：先手动减面到 5 万面级（§5.7 ①），或走 `blender.exe --background`（`skills/blender-headless-batch`）。
16. **★ Decimate 在“多块薄壳/非流形”网格上会卡住**：52007 面减到 15381 后，继续 `ratio=0.068` 只降到 14261，之后**完全不动**（ratio 再设也不降）。正解：先做一次 **Voxel Remesh** 把网格变成**封闭流形**，再 Decimate（实测 12264 → 1926 → 994 顺利）。
17. **★ Decimate 的 `ratio` 不等于实际降幅**：实测 `ratio=0.0799` 只从 12264 → 1926（不是 980），`ratio=0.5088` 从 1926 → 994。必须**循环**「读当前面数 → 算 ratio → apply」，不能一次设到位。
18. **★★ 非凸壳的“是否包住”不能用半空间判据**：`n·p − d ≤ 0`（所有面）只对**凸包**成立；shrinkwrap / remesh 后的内凹壳会误报“全部越界”。正解用 `obj.closest_point_on_mesh(p)` 取最近点法线，`dot(p − loc, normal) > 0` 才算在壳外。实测 994 面壳穿出 47.9%、中位距离 0.0588 m。
19. **★ 复制源星芒会继承 `hide_render=True` 与旧驱动**：`src.copy()` 带过来的是“隐藏 + `实际大小` scale 驱动”，直接用会看不见、且 19 颗同步闪。必须显式 `hide_render=False`、`visible_camera=True`、`animation_data_clear()` 后重建驱动（§5.8）。
20. **★ Empty 不能挂修改器 ⇒ 用子对象承载星芒**：`empty.modifiers.new(...)` 返回 `None`，想“空对象跟着动”只能用 `star.parent = empty` + `matrix_parent_inverse = Identity` + `star.location = (0,0,0)`；位置由父级负责、闪烁由对象 scale 驱动、朝向由 `DAMPED_TRACK` 负责。

## 九、Blender 5.2 API 坑速查

| 问题 | 说明 |
|---|---|
| `mod.properties.inputs` 不可迭代 | 5.2 返回 `GeometryNodesInterfaceInputs`，`enumerate(...)` 抛错；用 `.get(名)` / 属性访问 |
| EMPTY 属性驱动几何 socket 不稳 | 驱动读缓存值（如 288.0）；**改驱动节点组内部的 `ShaderNodeValue` 输出**（§5.6），并把 interface 里的同名 socket 删掉 |
| 几何节点实例不受对象级朝向约束 | 实例朝向必须几何节点内 `ALIGN_EULER_TO_VECTOR` |
| ObjectInfo ORIGINAL 忽略源缩放 | 要继承源 scale/动画用 **RELATIVE** |
| 读被驱动值 | 必须 `evaluated_depsgraph_get()` 后 `evaluated_get`，不能直接读内存属性 |
| **`Mesh to Points` 点云无 `normal`** | 输出属性只有 `position` / `.edge_verts` / `.corner_vert` / `.corner_edge`；`输入法线` / `命名属性('normal')` / `捕获属性` 全读 0 ⇒ 改用 `Distribute Points on Faces` 的 **`Normal` 输出** |
| **`DistributePointsOnFaces` 的密度插座** | RANDOM 模式用 **`Density`**；`Density Max` 只在 POISSON 模式存在（按名取 `KeyError`） |
| **`ng.links.remove()` 后旧引用失效** | 先存 `l.from_node.name`，再删链接；删完别回头读 `l.*` |
| **按名找节点时兜底复用同类节点** | `cands[0]` 兜底会让第二个 `VectorMath` 指向第一个节点、形成自环；找不到就**新建并命名** |
| **`RemeshModifier` 无 `use_remesh_fill_volume`** | 5.2 实测 `AttributeError`；VOXEL 模式只设 `mode`/`voxel_size` 即可 |
| **大网格 Remesh/Decimate 走桥** | 120 s 硬超时 + 主线程僵死 + 后续启动卡死（见坑⑮）；先减面或走 `--background` |
| **非凸壳内外判据** | 半空间 `n·p−d` 只对凸包成立；用 `obj.closest_point_on_mesh(p)` 的最近点法线方向判断 |
