# 径向材质多位置部署与播放时差（复制到新圆心 · 三层共享独立化 · 帧错位）

> 适用于：同一套**径向发光材质**（内收多脉冲 / 四段循环脉冲）要部署到场景里的**多个位置**
> （每处一份独立的材质 + 自己的控制器）；各处的播放要**错开一段时间**（比如相邻错 15 帧）；
> 以及排查/解决"**改一个材质或参数，其它地方跟着一起变**"的共享问题。
> 前置：[径向内收多脉冲材质](径向内收多脉冲材质.md)（材质本体怎么做、环数怎么算准）。

---

## 1. 场景

一组灯效果由「空对象 + 名下若干网格」构成。复制整套到场景其它位置后，希望：

1. 每处的材质**参数与动画完全一致**，只是**圆心**跟到新位置
2. 各处的播放**错开一段时间**（相邻错 15 帧），形成波浪式效果，而不是齐刷刷
3. 改其中一处的材质/参数，**其它处不受影响**

实测规模参考：9 个空对象 / 148 个网格对象 / 15 万顶点（最大单网格 1092 顶点），
一次性独立化毫无压力。

---

## 2. 做法

### 2.1 位置副本：动态定位 + 改指向 + 命名防叠

**定位**：不要按名字找材质 —— 用户会改名/挪动。**从网格的材质槽里读出材质，
再顺着 `纹理坐标.object` 找到它读的控制器**：

```python
pairs = []                                  # [(材质, 控制器)]
for pn in PLANES:                           # 或遍历某空对象名下的网格
    ob = D.objects[pn]
    for i in SLOT_IDX:
        m = ob.material_slots[i].material
        tex = [n for n in m.node_tree.nodes
               if n.type == 'TEX_COORD' and n.object]
        pairs.append((m, tex[0].object))
```

**复制**：`material.copy()` / `object.copy()` 会把节点树、**全部驱动**、
**全部自定义属性**（含用户已调好的值）整套带过来 ⇒ "参数不变"天然满足。
**只有三处要改指向**：

| # | 要改什么 |
|---|---|
| ① | 副本节点树的 `纹理坐标.object` → 新控制器 |
| ② | 副本材质里所有驱动变量的 `target.id` → 新控制器 |
| ③ | 副本控制器**自身那条只读驱动**的变量 → 新控制器 |

新控制器放在**实测的网格并集中心**（三面/多面分别实测再取并集，别沿用旧控制器的坐标）。

**命名防叠**：历史后缀（`_位3`、`_副本`、`_面1`…）要先剥掉再接新后缀，
否则会叠成 `…_位3_面1_位4` 这种垃圾名：

```python
import re
def new_name(name):
    base = re.sub(r"(_位\d+|_副本|_面\d+)+$", "", name)
    return base + NEW_TAG          # NEW_TAG 如 "_位4"，每次挪位置 +1
```

> ⚠️ 命名也可以**自动编号**：扫所有径向材质名里的 `_位N`，取最大 N+1 当本处后缀，
> 省得每次手改。本包的 `copy_to_position.py` 已内置。

### 2.2 ★ 带关键帧的材质：action 必须**重建**，不能 copy

复制一份**带关键帧**的材质（如四段循环脉冲的 `TVAL ≡ 帧号`）时，
`nt.animation_data.action` 会**与原件共用**。两个坑：

- **直接共用**：改一方的关键帧，另一方跟着变
- **`action.copy()` + 按名字重绑 `action_slot`**：fcurve 明明在、`fc.evaluate(f)` 也对，
  但节点**评估值冻结**在复制那一刻的帧值 —— 重绑**不生效**（实测）

**正解**：丢掉带过来的 action，原地重建：

```python
ad = nt.animation_data
if ad and ad.action:
    ad.action = None                       # ① 丢掉复制/共用的 action
tv = nt.nodes["TVAL"]                      # ② 原地 keyframe_insert（会自建 action + slot）
tv.outputs[0].default_value = 1.0
tv.outputs[0].keyframe_insert('default_value', frame=1)
tv.outputs[0].default_value = 250.0
tv.outputs[0].keyframe_insert('default_value', frame=250)
for fc in 所有TVAL的fcurve:                # ③ LINEAR + 外推 LINEAR
    for kp in fc.keyframe_points: kp.interpolation = 'LINEAR'
    fc.extrapolation = 'LINEAR'
```

> 驱动不在 action 里（在 `animation_data.drivers`），所以丢 action **不影响驱动**。
> ⚠️ **本 exec 内刚建完 action 就读关键帧评估值 = 读到缓存**（实测读出的是复制那一刻的帧值）
> —— 验证必须**另起一次请求**（AGENTS「修改与验证分两次请求」对新建 action 同样成立）。

### 2.3 ★★ 快照式独立化（修「改一个、其它跟着变」）

「改一个、其它一起变」有**三种成因**，先判别再动手：

| 层 | 判据 | 症状 | 解法 |
|---|---|---|---|
| ① **网格数据** | `mesh.users > 1`（Alt-D 关联复制／复制时勾了关联数据） | 改一个对象的**材质槽**，其它一起变 | 逐对象 `ob.data = ob.data.copy()` |
| ② **材质** | `material.users > 1` | 在材质编辑器里改**节点/参数**，大家一起来 | 每对象 `material.copy()` |
| ③ **控制器/驱动目标** | 多个材质的 `纹理坐标.object` 是**同一个**空物体 | 拖**控制器参数**，大家一起来 | 每份材质配自己的控制器 |

> 网格独立（①）之后，材质槽就是每对象一份的 ⇒ 可以给不同对象挂不同材质；
> 但**编辑材质本体**仍会影响所有用它的对象（那是②），要彻底独立还得②③一起做。

**★ 独立化必须「先快照、后动手」**：

```python
snap = collections.defaultdict(list)
for ob in targets:
    snap[ob.data.name].append(ob)          # 先按数据块分组

to_copy = []
for dname, lst in snap.items():
    if len(lst) > 1:
        to_copy.extend(lst)                # 被共享组里的每个对象都记下来

for ob in to_copy:                         # 然后才动手
    if ob.data.users > 1:
        ob.data = ob.data.copy()
```

> ⚠️ **不能一边遍历一边判 `users > 1`**：复制一个，那份数据的 users 就掉 1，
> 轮到共用同份数据的**兄弟对象**时 `users == 1` ⇒ 被跳过 ⇒ 漏掉一整批
> （实测 118 个对象只处理了 90 个，漏 28 个）。

**★ 匹配关键词要向用户要全**：本例的空对象叫「发射灯效果」「收缩灯效果」，
还有一组叫「收缩**射**灯效果」—— 只匹配 `发射灯/收缩灯` 就会**整组漏掉**
（"收缩灯"不是"收缩射灯"的连续子串）。

### 2.4 播放时差：时间错位 ≡ 相位偏移（数学上严格等价）

**为什么现在多份材质是同步的**：它们都读同一个 `scene.frame_current`，
且 `循环周期` / `相位偏移` 完全相同 ⇒ 相位一致。

内收材质的相位是：

```
相位 = 帧号 ÷ 循环周期 + 相位偏移
```

给第 k 份设 `相位偏移 = 20k ÷ 循环周期`，它的相位就变成 `(帧号 + 20k) ÷ 循环周期`
—— **严格等价于把它的播放时间推后 20k 帧**（前提：各份的 `循环周期` 相同）。

**各份要设的值**（周期 124、相邻错 15 帧、从第 0 份的当前相位偏移 0.85 起算）：

| 份 | 相位偏移 | TVAL 关键帧（脉冲类） |
|---|---|---|
| 0 | 0.85（不动） | (1, 1) / (250, 250) |
| 1 | 0.97097 | (1, 16) / (250, 265) |
| 2 | 0.09194 | (1, 31) / (250, 280) |
| 3 | 0.21290 | (1, 46) / (250, 295) |
| 4 | 0.33387 | (1, 61) / (250, 310) |

- **内收类**：只改各控制器的 `相位偏移`，**零节点改动**。注意取 `mod 1`（UI 上限是 1.0；
  相位差 1.0 = 一整圈，取模后效果不变）
- **四段循环类**：没有相位参数，但 `TVAL ≡ 帧号` 靠两个关键帧（斜率 1、截距 0）实现
  ⇒ **把两个关键帧的【值】各加偏移**（`值 = 帧 + 偏移`，斜率不变）即可，零结构改动
- **两两实测**：相邻对的相位差换算 = **15.00 帧整**（0.12097 圈 × 124）

> ⚠️ **语义坑**：`相位偏移` 存的是【圈数】不是【帧数】。以后改 `循环周期`，
> 等效的帧错位会跟着变（帧错位 = 相位偏移 × 循环周期）。
> 要"错位多少帧"这个语义固定下来，就加一个 `帧偏移` 参数
> （相位改成 `(帧号 + 帧偏移) ÷ 循环周期`；脉冲类在 TVAL 后面加一个加法节点）
> —— 每份材质 +1 节点 +1 属性 +1 驱动。

### 2.5 材质丢失防护（users=0 ⇒ 存盘被清；未挂载不进依赖图）

- **材质 `users == 0` 且没有 fake user ⇒ 存盘时被 Blender 当孤儿清掉**。
  「这材质怎么没了」十有八九是这个 —— 先看 `users` 和 `use_fake_user`，别急着重建。
- **防再丢**：给要保留的材质 `use_fake_user = True`；要删哪个就明确删。
- ★ **没被任何对象使用的材质（只剩 fake user）不进依赖图** ⇒ 播放不动、
  读关键帧/驱动的**评估值**拿到的是**原始存值** —— 这不是"材质坏了"，
  挂到对象上立刻正常。「材质坏了」和「材质没被使用」要分开判断。

## 3. 坑表（本路实测）

| # | 坑 | 正解 |
|---|---|---|
| 1 | 复制材质后 `纹理坐标.object` 和**所有驱动变量仍指旧控制器** | 三处指向逐一改（§2.1） |
| 2 | 带关键帧的材质复制后 action 与原件**共用**；`copy()+重绑 slot` 让评估值冻结 | `action=None` + 原地 `keyframe_insert` 重建（§2.2） |
| 3 | **同 exec 内刚建完 action 就读关键帧评估值 = 读到缓存** | 验证放**另起一次请求** |
| 4 | 独立化一边复制一边判 `users>1` ⇒ 漏掉一整批 | 先快照后动手（§2.3） |
| 5 | 匹配关键词漏变体（收缩**射**灯）⇒ 整组漏掉 | 关键词向用户要全，或放宽匹配 |
| 6 | 命名叠罗汉（`_位3_面1_位4`） | 新名字前先剥掉历史后缀（§2.1） |
| 7 | 材质 users=0 无 fake ⇒ 存盘被清 | `use_fake_user = True`（§2.5） |
| 8 | 未挂载材质读评估值 = 原始存值，误判"坏了" | 先确认它有没有被对象使用（§2.5） |
| 9 | 控制器自身那条只读驱动也要改指向（`可见脉冲数`/`周期帧数`） | 与②一起处理（§2.1） |
| 10 | `Mesh.materials` 迭代出 **Material 对象**（无 `.material`） | 要 `.material` 用 `object.material_slots`；`clear/append/pop` 在 `Mesh.materials` 上可用（`pop` 要 `index=` 关键字） |
